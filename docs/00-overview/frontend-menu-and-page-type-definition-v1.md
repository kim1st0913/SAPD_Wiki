# SAPD Wiki Frontend Menu and Page Type Definition V1

本文档用于固化 SAPD Wiki 最新全站菜单结构、页面类型定义和 Stitch 设计输入边界。

版本：V1
日期：2026-05-15
适用阶段：前端重构 / Stitch 设计交接前置

## 1. 定义目标

- 为后续 Stitch 设计和 Codex 前端实现提供统一输入。
- 固化全站一级菜单、二级菜单、路由建议和页面类型。
- 明确每类页面的设计重点和不适合的设计方式。
- 避免后续把工作台页、目录页、文档页、标准页和预留页混成一种 UI。

## 2. 本文件定义范围

- 全站一级菜单和二级菜单。
- 页面类型枚举和每类页面的适用场景。
- 每个菜单项的页面目标、设计重点、不适合的设计方式和优先级。
- Stitch 设计顺序建议。
- 与导航 Manifest 的字段口径。

## 3. 本文件不定义范围

- 不定义后端 API 字段细节。
- 不修改 ETL、数据库、数据模型或导出 JSON。
- 不定义具体视觉稿像素、颜色、字体和组件代码。
- 不决定 React / Vue / 原生 JS 等前端技术栈迁移。
- 不将预留页面伪装成已完成业务功能。
- 不改变现有 Frontend Baseline 1.0 的三页关系投影边界。

## 4. 页面类型总表

| 页面类型 | 适用对象 | 核心特点 | 优先级 |
|---|---|---|---|
| `application-shell` | 全局导航、应用壳、顶栏、侧栏、搜索入口 | 提供全站框架和页面容器 | P0 |
| `document-hub` | 安全指南首页、方法论文档集合页 | 文档集合入口和阅读导航 | P2 |
| `document-page` | 单篇指南 / 方法论页面 | 章节目录、正文、引用和相关指南 | P2 |
| `capability-mapping-workbench` | 安全能力映射 | 安全能力为主语的核心关系工作台 | P1 |
| `environment-mapping-workbench` | 信息化环境安全能力映射 | 信息化对象为主语的对象映射工作台 | P1 |
| `domain-module` | 开发安全、数据安全、SAPD 成熟度评估 | 专题模块入口或独立业务模块入口 | P2 / P3 |
| `knowledge-directory` | 安全知识各类目录 | 表格浏览、检索、标签、详情抽屉 | P2 / P3 |
| `knowledge-reference-page` | 单个知识对象详情页 | 对象详情、定义、关联和来源证据 | P2 |
| `standard-framework-directory` | 安全标准 / 框架首页 | 标准目录、版本、覆盖范围和映射状态 | P2 |
| `standard-framework-page` | 单个标准 / 框架页面 | 条款、控制项、映射和版本说明 | P2 |
| `placeholder-page` | 其他指南、其他目录、预留页面 | 建设状态、后续规划、返回入口 | P3 |

优先级定义：

| 优先级 | 含义 |
|---|---|
| `P0` | 前端基础框架，包括全局导航、应用壳、主布局、搜索入口 |
| `P1` | 核心业务工作台，包括安全能力映射、信息化环境安全能力映射 |
| `P2` | 重要知识、标准目录和独立业务模块，包括安全指南、安全知识、安全标准 / 框架、SAPD 成熟度评估 |
| `P3` | 专题扩展与预留模块，包括开发安全、数据安全、Hype Cycle、其他指南、其他标准等 |

## 5. 页面类型定义

### 5.1 `application-shell`

适用：

- 全局导航
- 应用壳
- 顶栏
- 侧栏
- 全局搜索
- 页面容器

核心区域：

- 顶部栏
- 左侧一级导航
- 二级菜单展开区
- 主内容区
- 当前页面标题区
- 面包屑
- 搜索入口

不适合：

- 不做营销官网首页。
- 不做大面积 Hero 区。
- 不做过度科技炫技风。

### 5.2 `document-hub`

适用：

- 安全指南首页。
- 方法论文档集合页。

核心区域：

- 指南目录
- 方法分类
- 最近更新
- 推荐阅读
- 文档说明

不适合：

- 不做复杂关系图。
- 不做能力映射工作台。
- 不做过多卡片堆叠。

### 5.3 `document-page`

适用：

- 安全技术架构设计方法。
- 数据安全设计方法。
- 安全管控模式设计方法。
- 成熟度模型使用指南。

核心区域：

- 左侧章节目录
- 中间正文区
- 右侧页内目录
- 来源引用
- 相关指南

不适合：

- 不把正文压缩成过多折叠面板。
- 不做卡片海报页。
- 不做复杂知识图谱。
- 不承载客户评估任务、评分结果或评估报告操作；这些属于 `工作台 > SAPD 成熟度评估`。

### 5.4 `capability-mapping-workbench`

适用：

- 安全能力映射。

核心区域：

- 能力目录
- 当前能力详情
- 关注点切换
- 技术视角映射
- 管理视角映射
- 标准 / 框架映射
- 关联模块清单
- 来源证据

设计重点：

- 这是核心工作台，不是普通目录页。
- 主体区域必须留给当前能力工作区。
- 左侧目录应可搜索、可滚动、可折叠。
- 关联模块应以清单方式呈现，不应设计成复杂网络图。
- 来源证据默认折叠。
- 技术视角和管理视角应能清晰切换。

不适合：

- 不做大面积 Hero 区。
- 不做营销官网风。
- 不做复杂网络关系图。
- 不让关联模块清单挤压主体内容。
- 不把所有关系堆在一个卡片内。

### 5.5 `environment-mapping-workbench`

适用：

- 信息化环境安全能力映射。

核心区域：

- 信息化对象目录
- 对象详情
- 安全作用域分布
- 安全技术服务清单
- 安全技术模块 / 技术措施映射
- 能力关联
- 来源证据

设计重点：

- 这是对象映射型工作台。
- 核心主语是“信息化对象”，不是“安全能力”。
- 应突出对象、作用域、服务、模块、措施之间的层级关系。
- 适合使用分栏、表格、标签、详情抽屉。

不适合：

- 不应直接套用安全能力映射页面。
- 不应把信息化对象弱化为普通筛选条件。
- 不做复杂关系网络图。
- 不做只展示卡片的浅层目录页。

### 5.6 `domain-module`

适用：

- 开发安全。
- 数据安全。
- SAPD 成熟度评估。

核心区域：

- 专题说明
- 建设状态
- 后续规划
- 相关知识入口
- 相关标准入口
- 业务模块型页面可包含任务入口、填报工作区、结果摘要和导出入口

不适合：

- 当前阶段不做深度业务重构。
- 不强行接入尚未准备好的数据。
- 不伪造不存在的功能。
- 不把评估填报、评分结果和客户运行数据混入安全能力映射、环境映射或 LC-AP 关系投影。
- 不把成熟度模型说明、等级解释和模板填写说明放入评估工作台主流程；说明类内容归入 `安全指南`。
- 不在成熟度评估模块内维护独立安全能力主数据；能力数据引用 `知识库字典 > 安全能力清单` 权威数据。

### 5.7 `knowledge-directory`

适用：

- 安全能力作用域目录。
- 安全技术模块/措施清单。
- 安全管理工作/流程清单。
- 安全职能清单。
- Hype Cycle。
- 其他知识目录。

核心区域：

- 目录检索
- 表格浏览
- 标签筛选
- 详情抽屉
- 来源证据
- 对象间关联

不适合：

- 不做成长文档页面。
- 不大面积卡片平铺。
- 不让每类知识对象都使用完全不同的页面结构。
- 不默认展示复杂关系图。

### 5.8 `knowledge-reference-page`

适用：

- 单个知识对象详情页。
- 单个作用域详情。
- 单个技术模块详情。
- 单个流程详情。
- 单个岗位 / 职能参考详情。

核心区域：

- 对象基本信息
- 定义说明
- 关联能力
- 关联技术措施
- 关联管理工作
- 来源证据

### 5.9 `standard-framework-directory`

适用：

- 安全标准 / 框架首页。

核心区域：

- 标准 / 框架目录
- 标准分类
- 版本信息
- 覆盖范围
- 映射状态

不适合：

- 不做 PDF 文件列表。
- 不只做静态链接集合。
- 不忽略标准版本信息。

### 5.10 `standard-framework-page`

适用：

- 等级保护三级。
- NIST CSF 2.0。
- ISO/IEC 27001:2022。
- DSP 2级策略清单。
- CIS CSC v8。
- CRF。
- NIST SP 800-53 Rev.5。

核心区域：

- 标准目录
- 条款 / 控制项列表
- 控制项详情
- 与安全能力映射
- 与技术措施映射
- 与管理工作映射
- 来源证据
- 版本说明

不适合：

- 不只做 PDF 阅读器。
- 不只做静态文档页。
- 不把标准条款和能力映射混在一个不可读长表格中。
- 不忽略版本信息和来源证据。

### 5.11 `placeholder-page`

适用：

- 其他指南。
- 其他知识目录。
- 其他标准 / 框架。
- 尚未建设但已预留的页面。

核心区域：

- 页面说明
- 建设状态
- 后续规划
- 返回入口

### 7.2 安全知识

| 菜单名称 | 路由建议 | 页面类型 | 页面目标 | 设计重点 | 不适合的设计方式 | 优先级 |

| 安全技术模块/措施清单 | `/knowledge/technical` | `knowledge-directory` | 浏览和核对安全技术模块、技术措施及其关联 | 内部 Tab：安全技术模块目录、安全技术措施目录；表格、搜索、详情、来源证据 | 拆成两个外层二级菜单、复杂网络图、组件内临时拼关系 | P2 |
| 安全管理工作/流程清单 | `/knowledge/management-workflows` | `knowledge-directory` | 浏览和核对安全工作、职能流程及其关联 | 内部 Tab：安全工作清单、安全职能流程清单；表格、搜索、详情、来源证据 | 把工作和流程做成无关联的孤立页面、关系大图 | P2 |
| 应用系统目录 | `/knowledge/application-systems` | `knowledge-directory` | 浏览和核对 LC-AP 应用系统类型、定义和应用组件 | 单表展示原始字段：应用系统、定义、应用组件；组件全部展开为标签；保持原始表顺序 | 展示软件开发类型、来源字段、状态字段或临时衍生统计 | P2 |
| 安全职能清单 | `/knowledge/functions` | `knowledge-directory` | 浏览和核对安全工作职能及岗位 / 职能参考 | 内部 Tab：安全工作职能清单、岗位 / 职能参考目录；表格、搜索、详情、来源证据 | 每类职能完全不同结构、PDF 列表、静态链接集合 | P2 |
| Hype Cycle | `/knowledge/hype-cycle` | `knowledge-directory` | 预留 Hype Cycle 知识目录 | 建设状态、目录结构预留、关联入口 | 伪造图表或趋势数据 | P3 |
| 其他知识目录 | `/knowledge/others` | `placeholder-page` | 预留其他知识目录入口 | 建设状态、后续规划、返回入口 | 伪造成完整目录 | P3 |

安全知识内部页面参考 `安全标准 / 框架` 的 CRF 页面结构：页面标题区保留数量徽标和全局搜索；内容区使用紧凑页签承载同组清单，页签下方使用密集表格作为主核对界面。短表保持顶部对齐并显示“已显示全部 X 条记录”的收尾提示，长表保留工作区内滚动。默认结构不再使用旧维护页左侧目录和右侧详情分栏；来源证据和对象详情如需展示，应作为次级抽屉或折叠区，不在主表格展示原始来源字段。

安全知识短表统一采用普通密集表格，字段内容能在单元格内换行时应全量展示；关系、组件、服务等多值字段使用 chip 全量展开，不使用 `+N` 截断。只有长表且确有业务层级字段时才使用分组展开，不能为了填满页面临时制造分组。

安全技术模块目录主表应优先展示可核对的业务事实：领域分类、安全系统、安全技术模块 / 定义、映射安全技术服务，以及措施 / 作用域 / 对象 / 环境的契约状态。领域分类来自原始 `安全技术模块清单` B 列，安全系统来自 C 列，页面应按“领域分类 -> 安全系统 -> 安全技术模块”两级分组展开，并优先保持原始表行顺序。当前维护包中安全系统、定义、技术服务和信息化环境可直接展示；模块-措施映射、模块-作用域映射、模块-信息化对象映射若未进入稳定数据契约，不应在组件中临时反推。

应用系统目录数据来自 `LC-AP 应用安全开发生命周期元素目录` 的“应用系统类型目录”区域。主展示字段只包含原始业务字段：`应用系统`、`定义`、`应用组件`；页面使用普通密集表格展示，每个应用系统一行，`应用组件` 全量展开为标签，不用折叠层级或 `+N` 截断，并按原表行顺序展示“传统应用 -> 微服务应用 -> 中台类应用”。`软件开发类型目录` 是同一 Sheet 中的另一块参考数据，不在本页面混合展示；`type`、`status`、`sources`、`row`、`raw_value` 等维护字段不得出现在主展示区。

### 7.4 安全标准 / 框架数据包边界

安全标准 / 框架页面不得使用单一全量 JSON 作为主数据包。页面数据必须拆为：

- `standards-index.json`：标准目录、版本、统计、Tab 元数据和分包路径；
- `standards-data.json`：旧入口兼容索引，不承载表格 `rows`；
- `public/data/standards/**`：按单个标准 / 框架或 Tab 存放行数据。

设计和实现验收时应确认：

- 标准目录页首屏只需要索引包；
- 单个标准页只加载当前框架或当前 Tab 分包；
- 大型框架（例如 DSP SCF 2026 成熟度、NIST 800-53 Rev.5）不得混入全局首屏包；
- 前端不得直接从多个标准分包拼接或推断安全能力映射关系，映射关系必须来自后端投影。
| 6 | 安全指南文档页 | `document-hub` / `document-page` | 固化文档阅读体验 |
