# SAPD Wiki 项目路线图

> 状态：`active / user-facing roadmap`
>
> 更新日期：2026-07-28

具体未完成事项和停止条件以根目录 `task_plan.md` 为准。本页只说明产品所处阶段和后续
方向。

## 已完成基础能力

- 多来源知识导入、来源追踪、审批和 SQLite 正式库；
- 安全能力、信息化环境、生命周期、知识目录和标准 / 框架工作台；
- 全局搜索、页面内搜索、批注、待复核、数据篮和工作台；
- 基础内容统一查询和独立内容资产库；
- MCP 五个只读知识工具、TLS / OAuth 和持久 Runtime；
- macOS DMG 与 Windows 私有 Runner / `Setup.exe` 交付链路；
- OI-198 导入审批幂等和可重复增量发布工具链。

## 当前阶段：稳定维护与发布

当前重点不是继续堆新页面，而是：

1. 按受控增量发布流程更新知识内容；
2. 保持正式基础数据、内容资产和用户数据相互隔离；
3. 完成 OI-197 的 15 项成熟度 Rubric 业务裁定；
4. 按需生成最新 macOS / Windows 安装包并完成实机 UAT；
5. 持续清理过时文档和重复权威入口。

## 下一阶段

### 知识更新工程化

- 新来源登记、审批和差异审查；
- 候选双库可重复构建；
- apply / accept / rollback 可审计；
- MCP 验收绑定准确 release、runtime、客户端和时间窗口。

### 成熟度正式化

- 完成 Rubric 业务裁定；
- 冻结正式字典映射和评分边界；
- 保持客户评估数据与基础知识库分离；
- 进入 App / DMG / Windows 实包验收。

### 跨平台发布

- macOS 保持正式 Mac 主工作区本地 DMG 流程；
- Windows 保持公开源码 + 私有 Delivery Data + 私有 Runner；
- 自动验证通过后仍保留首次启动、证书、OAuth、保存路径和升级 / 卸载人工 UAT。

## 长期边界

- 不把真实用户库、源资料、SQLite、恢复包和安装器提交到公开 GitHub；
- 不让前端重做后端业务逻辑；
- 不用 Web 5173 验收替代桌面实包验收；
- 不把历史计划或归档文档重新当成当前实施依据。
