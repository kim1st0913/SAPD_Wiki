# 项目愿景

## 项目定位

SAPD Wiki 是一个本地化结构化工作知识库系统，用于统一管理 Excel、DOCX、PPT、Draw.io、Markdown 等多来源工作资料。

它不是普通文件夹，也不是单纯文件预览器，而是：

```text
结构化知识资产管理系统
+ 多来源文件 ETL 系统
+ 本地数据库
+ 本地知识门户
+ 可审查的数据更新机制
```

## 要解决的问题

当前工作知识常散落在不同格式文件中：

- Excel 表格中有能力清单、指标、评估结果；
- DOCX 和 Markdown 中有方法论、流程、说明文档；
- PPT 中有模型、案例、汇报页；
- Draw.io 中有架构节点、流程节点和关系；
- 后续还可能有 PDF、CSV、JSON 或第三方 ETL 数据。

如果只保存原文件，后续会遇到：

- 查找困难；
- 字段不统一；
- 关系不可见；
- 更新时容易覆盖人工修改；
- 导出和复用成本高；
- 难以支持后续 AI/RAG。

本项目希望把这些文件中的内容逐步转为可查询、可关联、可导出、可追溯来源的知识对象。

## 面向用户

第一使用者是非开发背景的项目负责人或知识库维护者。

系统设计应让用户能通过样例文件、字段字典和映射规则逐步推进，不要求用户一开始理解数据库、代码和工程实现。

## 建设目标

- 工程代码托管在 GitHub，便于维护和演进。
- 原始文件保留在本地文件仓库中。
- 结构化数据存入本地数据库。
- 每条知识记录能追溯到来源文件、来源位置和导入任务。
- 支持人工编辑、批量文件导入和第三方 ETL 更新。
- 自动导入必须经过暂存、校验和人工审查，不静默覆盖人工编辑。
- 支持知识浏览、标签分类、关键词搜索、来源追踪、关系查看。
- 支持查询结果导出、主题导出、全量备份包。
- 最终可打包成本地运行程序。

## 当前建设原则

- 先做数据定义，再做功能开发。
- 先跑通最小闭环，再扩展更多格式。
- 先结构化、关系化、检索化，再考虑 AI/RAG。
- V1 从 Excel、Markdown、DOCX 开始。
- PPT 和 Draw.io 深度解析后置。
- 主控 Agent 负责统一阶段边界、字段命名、模块分工和验收标准。
