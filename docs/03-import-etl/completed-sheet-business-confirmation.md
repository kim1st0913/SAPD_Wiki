# 已完成映射原始表业务确认清单

本文档用于把已经进入 ETL / 数据库 / 前端导出的原始 Sheet 再做一次业务确认。目的不是重新写技术方案，而是确认每张表的业务含义、主键、对象边界和关系基数，避免前端页面按错误逻辑展示。

维护规则：

- 每完成一张新原始表建模前，必须先补充或更新本文件。
- 每张表至少确认：业务含义、主对象、主键、是否为映射表、关系基数、与其他 Sheet 的主从关系。
- 用户确认后，把“待确认”改为“已确认”；若需要修改 ETL，则同步新增或更新 `docs/06-implementation/open-issues.md`。

## 建模前必须确认的 7 个问题

| 问题 | 说明 |
|---|---|
| 1. 这张表表达什么业务事实？ | 主数据、映射关系、参考资料、说明文档、统计汇总不能混用。 |
| 2. 哪一列是主键或稳定身份？ | 如果没有编码，需要确认用标题、上下文、序号还是复合键。 |
| 3. 哪些列是描述字段？ | 描述字段不应被误当作对象。 |
| 4. 哪些列是统计合计或辅助字段？ | 统计值不生成知识对象，例如 `安全技术模块清单` 的 C/D 列 `29`、`98`。 |
| 5. 与其他表的关系是什么？ | 明确主从关系，避免前端自己反推。 |
| 6. 关系基数是什么？ | 一对一、一对多、多对一、多对多要提前确认。 |
| 7. 冲突时以哪张表为准？ | 主数据表优先，映射表只建立关系。 |
