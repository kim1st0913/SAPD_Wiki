# 前端关系化重构任务书

本文档用于同步主控 Agent、ETL/Data Worker 和 Frontend Design Owner 的工作边界。当前前端不再按“卡片展示页”继续小修，也不以“追溯某条知识对象来自哪个 Sheet、哪一行、哪个字段”为主要目标，而是围绕现有 Excel 表格中已经表达出的业务关系，构建多维关系展示页面和专项知识维护页面。

## 1. 修正后的前端目标

前端的核心目标是：

- 按业务维度展示知识对象之间的关系；
- 支持用户理解能力、环境、生命周期、流程、职能、作用域、技术模块等对象如何互相支撑；
- 支持专项知识清单维护和核对；
- 后续承载 HTML 知识说明、Draw.io 视图、PPT 使用说明等非表格知识内容；
- 形成关系模式 UI，而不是卡片式资料陈列。

来源追踪仍作为底层数据治理能力保留，但不是当前前端主体验收目标。前端可以在详情或调试信息中保留来源信息，但不应让页面围绕来源单元格组织。

## 2. 前端设计原则

| 原则 | 要求 |
|---|---|
| 关系优先 | 页面优先表达对象之间的映射、包含、支撑、适用、关联和生命周期关系 |
| 维度入口 | 以能力、信息化环境、安全开发、数据生命周期等维度建立独立关系页面 |
| 专项维护 | 作用域、流程清单、职能清单、安全技术模块清单等作为独立知识维护页面 |
| 表格与矩阵优先 | 清单、矩阵、树表、关系链优先，卡片不作为主要模式 |
| 渐进扩展 | HTML 说明页、Draw.io 图、PPT 使用说明后续作为内容型页面接入 |
| 本地性能 | 页面保持本地静态加载能力，优先使用预计算 JSON，不在前端做重型计算 |

## 3. 页面总结构

V1 前端建议按“关系视图 + 专项知识维护 + 内容说明”组织。

| 一级模块 | 页面目标 | 主要视图 |
|---|---|---|
| 关系总览 | 给出知识域和关系域入口，不做卡片墙 | 关系导航、统计、待确认问题入口 |
| 能力维度 | 从安全能力出发看关注点、服务、作用域、流程、职能、技术模块 | 能力树、关系矩阵、节点工作台 |
| 信息化环境维度 | 从信息化环境和信息化对象出发看作用域、服务、模块、系统 | 环境树、对象关系链、连续映射表 |
| 安全开发维度 | 从应用安全开发生命周期出发看阶段、活动、策略、服务、组件 | 生命周期泳道、阶段-活动-策略映射 |
| 数据生命周期维度 | 从数据生命周期出发看过程、场景、服务、模块、策略 | 生命周期矩阵、场景链路 |
| 专项知识维护 | 维护和核对基础知识清单 | 作用域清单、流程清单、职能清单、技术模块清单、标准/岗位参考 |
| 说明与视图 | 承载使用说明、HTML 知识页、Draw.io 图、PPT 页面介绍 | HTML 文档页、Draw.io 只读图、PPT 使用说明 |

## 4. 当前优先页面

当前阶段优先完成前 2 组关系页面和 4 类专项维护页。

| 优先级 | 页面 | 目标 |
|---|---|---|
| P0 | 能力维度关系页 | 以能力目录为入口，展示能力、关注点、服务、作用域、流程、职能、模块之间的关系 |
| P0 | 信息化环境维度关系页 | 展示 `信息化环境 -> 信息化对象 -> 作用域 -> 服务 -> 模块 -> 系统/产品` |
| P0 | 作用域清单 | 独立维护安全能力作用域目录 |
| P0 | 流程清单 | 独立维护安全职能流程清单 |
| P0 | 职能清单 | 独立维护安全工作职能清单 |
| P0 | 安全技术模块清单 | 独立维护技术模块、系统、产品、服务关系 |
| P1 | 安全开发维度关系页 | 展示 LC-AP 应用安全开发生命周期关系 |
| P1 | 数据生命周期维度关系页 | 展示 LC-DT 数据生命周期关系 |
| P1 | 标准与岗位参考 | 独立展示标准引用、Gartner 岗位参考 |
| P2 | HTML 知识说明 | 展示知识库使用说明、方法说明、页面说明 |
| P2 | Draw.io 视图 | 只读展示元模型、技术架构、流程图、功能架构图 |
| P2 | PPT 使用说明 | 展示知识库使用说明幻灯片或转换后的 HTML 内容 |

## 5. UI 模式要求

禁止把主要页面做成卡片墙。允许少量摘要块，但不能让卡片成为主要信息结构。

推荐使用：

- 左侧维度树 + 中间关系表 + 右侧关系详情；
- 树表结构；
- 映射矩阵；
- 分组清单；
- 关系链；
- 局部关系图；
- 生命周期泳道；
- 可展开表格行。

不推荐使用：

- 卡片墙；
- 大面积营销式首页；
- 只展示标题和摘要的详情卡；
- 只靠标签 chip 表达关系；
- 把业务关系压缩进不可比较的卡片列表。

## 6. 前端数据契约方向

### 6.1 能力维度

前端需要能消费：

- 能力分类、L1、L2、关注点层级；
- 关注点到安全技术服务的关系；
- 关注点到作用域的关系；
- 关注点到 L2流程组、L3流程、L4关键活动占位的关系；
- 关注点到组织职能相关方的关系；
- 服务到技术模块、系统、产品的关系。

### 6.2 信息化环境维度

前端需要能消费：

```text
信息化环境
└── 信息化对象
    └── 安全作用域
        └── 安全技术服务
            └── 安全技术模块/措施
                └── 安全系统/产品
```

### 6.3 安全开发维度

前端后续需要能消费：

```text
应用安全开发生命周期
└── 阶段
    └── 主要活动 / 安全活动
        └── 安全策略要求
            └── 开发技术服务
                └── 产品 / 组件 / 系统类型
```

### 6.4 数据生命周期维度

前端后续需要能消费：

```text
数据生命周期
└── 生命周期过程
    └── 生命周期场景
        └── 安全技术服务
            └── 安全技术模块
```

### 6.5 专项知识维护

专项维护页需要以清单、表格、树表或矩阵方式展示：

- 安全能力作用域目录；
- 安全职能流程清单；
- 安全工作职能清单；
- 安全技术模块清单；
- 标准与规范参考；
- Gartner 岗位参考。

## 7. Agent 分工

### 7.1 主控 Agent

主控 Agent 负责：

- 维护数据口径、页面目标和验收标准；
- 决定哪些关系进入哪个页面；
- 维护统一 issue；
- 协调 ETL/Data Worker 与 Frontend Design Owner；
- 做最终集成验收。

主控 Agent 不直接长期接管前端设计。主控只做边界、契约、验收和必要的短期救火。

### 7.2 Frontend Design Owner

Frontend Design Owner 是前端设计和前端实现的唯一负责人。

职责：

- 统一前端信息架构；
- 统一页面模式、导航结构、布局和交互；
- 设计能力维度、信息化环境维度、安全开发维度、数据生命周期维度等关系页面；
- 设计专项知识维护页；
- 设计后续 HTML 说明页、Draw.io 图、PPT 使用说明页接入方式；
- 在需要新数据字段时向主控提出数据契约变更，不自行改变 ETL 口径；
- 负责 `frontend/capability-browser/` 下的前端代码质量和浏览器验证。

允许修改：

- `frontend/capability-browser/index.html`
- `frontend/capability-browser/app.js`
- `frontend/capability-browser/styles.css`
- 必要时可新增 `frontend/capability-browser/` 下的前端模块文件，但必须保持本地静态可运行。

不允许修改：

- `src/sapd_wiki/`
- `docs/06-implementation/open-issues.md`
- `task_plan.md`
- `progress.md`
- 数据模型和 ETL 口径文档。

### 7.3 ETL/Data Worker

ETL/Data Worker 负责：

- 根据主控确认的数据契约，导出前端所需 JSON；
- 保证关系链和专项维护清单的数据完整；
- 将无法生成的数据缺口反馈给主控，不直接设计页面。

## 8. 本轮验收标准

下一轮前端重构不是检查“是否更漂亮”，而是检查：

- 是否能从能力维度看清能力、服务、流程、职能、作用域、模块关系；
- 是否能从信息化环境维度看清对象、作用域、服务、模块、系统关系；
- 是否能以专项维护页维护作用域、流程、职能、技术模块；
- 是否明显减少卡片化表达；
- 是否为安全开发维度和数据生命周期维度预留清晰入口；
- 是否为 HTML 说明、Draw.io 视图、PPT 使用说明预留清晰入口；
- 是否保持本地静态页面性能。

## 9. 后置内容
