# 能力目录浏览页设计

本文档定义第一版本地浏览页面。目标不是做完整前端，而是先做一个能验证数据结构是否符合工作使用方式的页面。

## 1. 页面目标

能力目录浏览页用于回答三个问题：

1. 某个安全能力体系下有哪些 L1、L2 和关注点；
2. 某个关注点关联哪些安全技术服务；
3. 用户能否从能力层级一路查到服务、作用域和来源。

第一版页面只读，不提供编辑。

2026-05-11 更新：此前 `T-AD.SV-01` 曾因标题差异被误判为“未挂接关注点”。已确认其上级编码是 `T-AD.SV`，并通过 ETL 去重规则修复；最新能力树导出统计 `unlinked_focuses: 0`。

2026-05-11 更新：能力树顺序必须遵循 Excel `安全能力目录` 的原始行顺序，不按编码或标题重新排序。该顺序体现滑动标尺模型和 EA 定义，是业务语义的一部分。

左侧能力树支持按层级展开/收起，并明确区分能力分类、L1 高阶战略能力、L2 安全能力和能力关注点。

## 2. 数据范围

第一版使用已导入 SQLite 的 5 个核心 Sheet 数据：

| 数据 | 对应对象或关系 |
|---|---|
| 安全能力分类 | `capability_category` |
| L1 高阶战略能力 | `capability_domain` |
| L2 安全能力 | `capability` |
| 关注点 | `capability_focus` |
| 安全技术服务 | `security_technical_service` |
| 作用域 | `scope_type` |
| 层级关系 | `belongs_to` |
| 服务支撑关注点 | `supports_focus` |
| 服务适用作用域 | `applies_to_scope` |
| 来源追踪 | `source_references` |

## 3. 页面结构

```text
顶部工具栏
├─ 搜索框
├─ 对象类型筛选
└─ 导出按钮

主体
├─ 左侧：能力树
│  └─ 能力分类 → L1 → L2 → 关注点
├─ 中间：当前节点详情
│  ├─ 编码、名称、描述
│  ├─ 上下级关系
│  └─ 来源位置
└─ 右侧：关联服务
   ├─ 服务列表
   ├─ 适用作用域
   └─ 服务来源
```

## 4. 关键交互

| 操作 | 行为 |
|---|---|
| 点击能力分类 | 展开 L1 高阶战略能力 |
| 点击 L1 | 展开 L2 安全能力 |
| 点击 L2 | 展开关注点 |
| 点击关注点 | 中间显示关注点详情，右侧显示关联服务 |
| 搜索关键词 | 在编码、标题、描述中查找 |
| 点击服务 | 显示服务编码、名称、适用作用域和来源 |
| 点击来源 | 显示来源文件、Sheet、行号、单元格 |
| 导出当前结果 | 导出当前节点及其关联服务为 CSV/JSON |

2026-05-10 更新：服务卡片已增加来源追踪展开区；`ALL&T-*` 类型服务编码已按完整服务编码解析，`ALL` 作用域显示为“全部作用域”。

## 5. 第一版不做

| 暂不做 | 原因 |
|---|---|
| 不做复杂图谱 | 先验证层级和关联是否正确 |
| 不做编辑 | 更新机制仍应先走导入和审查 |
| 不做权限 | 当前是本地单机使用 |
| 不做 PPT/Draw.io 页面 | 待 Excel 主链路稳定后再做 |
| 不做全局 AI 问答 | 等数据模型和来源追踪稳定后再考虑 |

## 6. 需要的查询接口

第一版前端需要后端或本地 API 提供这些查询：

| 查询 | 输入 | 输出 |
|---|---|---|
| 能力树 | 无 | 分类、L1、L2、关注点层级 |
| 节点详情 | `item_id` | 对象基础字段、描述、metadata |
| 关注点关联服务 | `capability_focus_id` | 服务列表、作用域 |
| 来源引用 | `target_type + target_id` | source file、sheet、row、cell |
| 搜索 | keyword、type | 匹配对象列表 |
| 导出当前节点 | `item_id` | CSV/JSON |

## 7. 验收标准

第一版页面完成时应满足：

- 能展示完整能力树；
- 能点击到 L2 能力和关注点；
- 能看到关注点关联的安全技术服务；
- 能看到服务适用的作用域；
- 能追溯来源文件、Sheet 和行号；
- 页面加载本地 SQLite 导出的数据时不卡顿；
- 页面结构方便后续扩展到技术模块、信息化对象、流程和 Draw.io 视图。

## 8. 后续实现建议

建议下一步先实现一个最小本地页面：

1. 写一个查询层，把 SQLite 中的能力树导出为 JSON；
2. 用 React + TypeScript 做单页能力浏览；
3. 先读取静态 JSON，不急着做完整后端；
4. 页面验证通过后，再决定是否引入 Tauri 本地 API。
