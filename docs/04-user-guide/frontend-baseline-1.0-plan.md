# Frontend Baseline 1.0 独立任务说明

## 任务目标

Frontend Baseline 1.0 的目标，是把当前 SAPD Wiki 已形成的核心业务关系视角，统一整理为一套本地关系知识库工作台的前端基线。

本阶段不是新增业务功能，不进入新 Sheet 扩展，也不启动 Phase 7 多格式增强。它只用于明确三个已确认业务视角的页面范围、共同组件、数据边界和验收标准，为后续前端代码实施提供稳定任务说明。

## 三页范围

Frontend Baseline 1.0 覆盖以下三个页面：

1. 安全能力映射页
   - 对应当前安全能力、关注点、作用域、服务、模块、措施和来源证据的关系展示。
2. LC-AP 开发安全生命周期页
   - 对应 LC-AP 开发安全生命周期阶段、活动、策略要求、开发技术服务、安全技术服务、技术模块、技术措施和开发类产品组件的关系展示。
3. 信息化环境维度页
   - 对应第一批核心数据中的信息化环境、环境子类、信息化对象、作用域、安全技术服务、安全技术模块、安全系统和产品关系展示。
   - 该页面是第一批核心数据的第三个业务视角，不是新 Sheet 扩展，也不是新功能范围扩张。

## 三页共同组件基线

三页应保持同一套前端组件基线和视觉语言。页面可以有不同主对象、概览字段和关系表字段，但不应形成三套割裂的交互方式。

共同组件基线包括：

- `AppShell`：提供本地工作台外壳、主导航和页面容器。
- `LocalNavigator`：提供当前页面内的对象列表、层级导航或筛选入口。
- `ObjectOverview`：展示当前选中对象的业务概览、状态、标签和关键字段。
- `RelationshipTable`：展示当前对象的核心关系链、映射结果和可核对字段。
- `SourceEvidencePanel`：展示来源证据、来源位置和必要的追溯信息，默认不干扰主业务阅读。

## 页面主视角与核心关系

### 安全能力映射页

主视角：

- 安全能力；
- 安全关注点。

核心关系：

- 安全能力到安全关注点；
- 安全关注点到作用域；
- 作用域到安全技术服务；
- 安全技术服务到安全技术模块；
- 安全技术模块到安全技术措施；
- 安全关注点到管理工作、流程或职能；
- 对应来源证据。

页面目标：

- 帮助用户从能力或关注点出发，查看其关联的服务、模块、措施、管理工作和来源依据。
- 优先服务业务关系核对，不展示非必要技术字段。

### LC-AP 开发安全生命周期页

主视角：

- LC-AP 开发安全生命周期阶段。

核心关系：

- 生命周期阶段到主要活动；
- 主要活动到安全活动；
- 安全活动到安全策略要求；
- 安全策略要求到开发技术服务；
- 开发技术服务到安全技术服务；
- 安全技术服务到安全技术模块；
- 安全技术模块到安全技术措施；
- 生命周期阶段或服务到开发类产品组件；
- 对应来源证据。

页面目标：

- 帮助用户按开发安全生命周期阶段查看安全活动、策略要求、服务、模块、措施和产品组件之间的关系。
- LC-AP 参考数据不放在同页参考区，应进入 `专项知识维护 > LC-AP参考数据`。

### 信息化环境维度页

主视角：

- 信息化环境；
- 环境子类；
- 信息化对象。

核心关系：

- 信息化环境到环境子类；
- 环境子类到信息化对象；
- 信息化对象到作用域；
- 作用域到安全技术服务；
- 安全技术服务到安全技术模块；
- 安全技术模块到安全系统；
- 安全系统到产品；
- 对应来源证据。

页面目标：

- 帮助用户从信息化环境或信息化对象出发，核对其受哪些作用域保护、需要哪些安全技术服务、由哪些技术模块、安全系统和产品支撑。
- 明确该页面是第一批核心数据的第三个业务视角，不代表启动新 Sheet 扩展。

## 信息化环境维度页数据对象清单

信息化环境维度页至少覆盖以下对象或等价能力：

- `information_environment`：信息化环境。
- `environment_segment`：环境子类。
- `information_object`：信息化对象。
- `scope_type`：作用域。
- `security_technical_service`：安全技术服务。
- `security_technology_module`：安全技术模块。
- `security_system`：安全系统。
- `product`：产品。

如果当前数据投影中使用了不同字段名或聚合结构，前端实现时可以使用等价能力，但必须保证页面表达的业务含义一致。

## 信息化环境维度页关系清单

信息化环境维度页至少覆盖以下关系或等价能力：

- `protects_object`：作用域或安全能力保护信息化对象。
- `deployed_in_environment`：信息化对象、安全系统或产品部署在对应环境中。
- `applies_to_scope`：服务、模块或措施适用于对应作用域。
- `implements_service`：安全技术模块、安全系统或产品支撑对应安全技术服务。
- `part_of_system`：模块、组件或产品属于对应安全系统。
- `maps_to_product`：安全系统、模块或服务映射到产品。

如果当前数据尚未具备完整显式关系，后续前端实施应优先复用现有投影和 ViewModel 输出，不在页面内临时编造业务关系。

## 本阶段不做事项

Frontend Baseline 1.0 明确不做以下事项：

- 不修改前端代码。
- 不修改 ETL。
- 不修改数据库 schema。
- 不修改 `dataClient`。
- 不修改 ViewModel。
- 不运行 `npm`。
- 不启动本地前端。
- 不打开浏览器。
- 不进入 Phase 7。
- 不启动 maturity 模块。
- 不继续做新 Sheet。
- 不引入 React / Vue 重构当前 MVP 前端。
- 不把 LC-AP 参考数据塞入生命周期页的同页参考区。
- 不在主展示区暴露非业务字段。

## 后续前端实施边界

后续如进入前端代码阶段，应遵守以下边界：

- 只围绕三页进行现状核查、组件统一和必要页面补齐。
- 优先复用已有静态前端、`dataClient`、ViewModel 和 JSON 数据投影。
- 页面只消费后端或投影层提供的业务字段，不在页面内重新实现 ETL、主数据归一、关系生成或冲突处理。
- 三页保持统一的信息密度、表格样式、标签规则、来源证据折叠方式和导航体验。
- 信息化环境维度页只作为第一批核心数据的第三个业务视角实现，不扩大为新 Sheet 导入或新模块开发。
- 如发现数据缺口，应记录为待确认问题或数据契约问题，不在前端临时硬编码补齐。

## 验收标准

Frontend Baseline 1.0 任务说明文档的验收标准如下：

- 文档明确覆盖三个页面：安全能力映射页、LC-AP 开发安全生命周期页、信息化环境维度页。
- 文档明确说明信息化环境维度页是第一批核心数据的第三个业务视角，不是新 Sheet 扩展，也不是新功能范围扩张。
- 文档列出三页共同组件基线：`AppShell`、`LocalNavigator`、`ObjectOverview`、`RelationshipTable`、`SourceEvidencePanel`。
- 文档分别说明每个页面的主视角和核心关系。
- 文档列出信息化环境维度页至少需要覆盖的数据对象或等价能力。
- 文档列出信息化环境维度页至少需要覆盖的关系或等价能力。
- 文档明确本阶段不修改前端代码、ETL、数据库 schema、`dataClient`、ViewModel，不运行 `npm`，不启动浏览器。
- 文档明确后续进入前端代码阶段前，需要用户确认。
