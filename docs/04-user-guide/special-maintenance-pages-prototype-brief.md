# 专项知识维护页面原型说明

本文档用于导出给 Stitch 进行页面原型设计。它描述当前 `专项知识维护` 模块的页面逻辑、信息架构、表格字段、详情面板和交互规则。

本文档只描述原型设计口径，不修改前端代码、不修改 ETL、不修改数据库 schema。

## 0. 前后端边界

专项知识维护页面先采用本地 API 过渡模式。

数据链路：

```text
SQLite / ETL
-> 后端导出数据包
-> /api/v1/data-packages/*
-> 前端 dataClient
-> ViewModel
-> 页面组件
```

当前本地 API：

| 接口 | 用途 |
|---|---|
| `GET /api/v1/maintenance` | 专项知识维护导航和数量 |
| `GET /api/v1/maintenance/scopes` | 作用域清单数据 |
| `GET /api/v1/maintenance/processes` | 流程清单数据 |
| `GET /api/v1/maintenance/work-functions` | 职能清单数据 |
| `GET /api/v1/maintenance/security-works` | 安全工作清单数据 |
| `GET /api/v1/maintenance/modules` | 安全技术模块清单数据 |
| `GET /api/v1/maintenance/measures` | 安全技术措施清单数据 |
| `GET /api/v1/maintenance/lcap-references` | LC-AP 参考数据 |
| `GET /api/v1/maintenance/references` | 岗位参考页面数据 |

说明：当前前端仍保留静态 JSON 降级能力；Stitch 原型只需要按页面结构设计，不需要表现数据加载实现细节。

## 1. 页面定位

`专项知识维护` 是 SAPD Wiki 的主数据和参考数据核对区，不是来源文件浏览器，也不是客户评估页面。

它的目标是让用户以“专项对象清单 + 关系详情”的方式维护和核对以下知识对象：

- 安全作用域；
- 安全流程；
- 安全职能；
- 安全工作；
- 安全技术模块；
- 安全技术措施；
- LC-AP 参考数据；
- 岗位参考数据。

页面应优先服务人工核对、关系理解和数据质量确认，不展示无业务含义的调试字段。

## 2. 总体页面布局

建议采用三栏结构。

| 区域 | 用途 | 设计要求 |
|---|---|---|
| 左侧导航 | 展示专项页面入口和数量 | 使用垂直导航，当前页高亮；每项显示名称和数量 |
| 中间主区 | 展示当前专项对象表格 | 表格优先，支持滚动、选择行、搜索和筛选扩展 |
| 右侧详情 | 展示当前选中对象的业务详情和关联对象 | 以事实卡片、关系分组和来源证据组成 |

建议布局：

```text
专项知识维护
├─ 左侧：专项导航
├─ 中间：当前专项清单 / 页签表格
└─ 右侧：对象详情 / 关系详情 / 来源证据
```

## 3. 左侧导航

当前专项页面入口如下。

| 导航项 | 页面 ID | 页面说明 |
|---|---|---|
| 作用域清单 | `scopes` | 维护和核对安全作用域 |
| 流程清单 | `processes` | 维护和核对安全流程，展示 L2 流程组、L3 流程、L4 活动 |
| 职能清单 | `work-functions` | 维护和核对安全职能，展示 4 层职能结构 |
| 安全工作清单 | `security-works` | 维护和核对安全工作，展示与安全能力 / 关注点的关系 |
| 安全技术模块清单 | `modules` | 维护和核对安全技术模块 |
| 安全技术措施清单 | `measures` | 维护和核对安全技术措施 |
| LC-AP参考数据 | `lcap-references` | 维护 LC-AP 页面使用的软件开发类型、应用系统类型和应用组件 |
| 岗位参考页面 | `references` | 展示 GB/T 42446-2023 和 Gartner 工作岗位参考 |

导航交互：

- 点击导航项切换中间主区；
- 切换页面时清空当前选中对象；
- 默认进入 `作用域清单`；
- 每个导航项可显示对象数量；
- 未接入数据时显示空状态，不隐藏入口。

## 4. 页面顶部摘要

中间主区顶部应显示当前专项页的标题、说明、必要提示和统计摘要。

| 页面 | 标题 | 说明 |
|---|---|---|
| 作用域清单 | 作用域清单 | 用于维护和核对安全作用域，展示处理后的业务字段和关联数量 |
| 流程清单 | 流程清单 | 用于维护和核对安全职能流程，展示流程域、L2 流程组、L3 流程和 L4 关键活动状态 |
| 职能清单 | 职能清单 | 用于维护和核对安全工作职能，统一使用“安全职能”业务口径 |
| 安全工作清单 | 安全工作清单 | 安全工作作为独立对象展示，编码由关注点编码和关注点内序号稳定派生 |
| 安全技术模块清单 | 安全技术模块清单 | 用于维护和核对安全技术模块，区别于安全技术措施，不把系统或产品作为主列 |
| 安全技术措施清单 | 安全技术措施清单 | 用于维护和核对安全技术措施，展示措施与安全技术服务、作用域、信息化环境和信息化对象的关系 |
| LC-AP参考数据 | LC-AP参考数据 | 维护和核对 LC-AP 页面使用的软件开发类型、应用系统类型和应用组件参考数据 |
| 岗位参考页面 | 岗位参考页面 | 展示 GB/T 42446-2023 与 Gartner 工作岗位参考；映射结果只作为候选或待复核信息 |

摘要统计可使用紧凑数字标签，不要变成大卡片堆叠。

| 作用域编码 | 标准作用域编码 |

| 分区 | 内容 |

## 8. 安全工作清单

业务含义：安全工作是围绕安全能力和安全关注点展开的管理类工作对象。它是独立对象，不等同于安全职能或流程。

表格字段：

| 字段 | 说明 |
|---|---|
| 序号 | 当前列表序号 |
| 安全工作编码 | 稳定派生编码 |
| 安全工作名称 | 安全工作名称 |
| 关联安全能力 | 所属安全能力 |
| 关联关注点 | 所属安全关注点 |
| 状态 | 当前数据状态 |

右侧详情：

| 分区 | 内容 |
|---|---|
| 基本事实 | 正式编码、关联安全能力、关联关注点、状态 |
| 关联安全能力 | 所属能力对象 |
| 关联关注点 | 所属关注点对象 |
| 来源证据 | 当前可为空，后续可补充 |

设计注意：

- 当前口径下，不在安全工作清单中直接展示安全工作到安全职能的强关系；
- 如果需要展示安全工作到安全流程 / 职能，应等待 ETL 提供可靠关系后再接入。

业务含义：安全技术模块是支撑安全技术服务的标准技术能力模块，不等同于安全技术措施、安全系统或产品。

表格字段：

| 字段 | 说明 |
|---|---|
| 模块分类 | 模块分类 |
| 安全技术模块 | 模块名称 |
| 关联安全技术服务数 | 关联服务数量 |

| 关联作用域数 | 关联作用域数量 |
| 关联信息化对象数 | 关联信息化对象数量 |

右侧详情：

| 分区 | 内容 |
|---|---|
| 基本事实 | 模块分类、关联服务、关联措施、关联作用域、关联信息化对象 |
| 关联安全技术服务 | 该模块实现或支撑的服务 |

右侧详情：

| 分区 | 内容 |
|---|---|

## 12. 岗位参考页面

业务含义：岗位参考页面展示外部标准和岗位参考，不直接作为最终内部职责事实。

页面使用两个页签：

- `GB/T 42446-2023`
- `Gartner 工作岗位参考`

### 12.1 GB/T 42446-2023

表格字段：

| 字段 | 说明 |
|---|---|
| 标准来源 | 标准名称或来源 |
| 任务分类 | 标准任务分类 |
| 任务名称 | 标准任务名称 |
| 关联安全职能 | 与内部安全职能的关联 |
| 关联流程 | 与流程的关联 |
| 状态 | 映射状态 |

### 12.2 Gartner 工作岗位参考

表格字段：

| 字段 | 说明 |
|---|---|
| 岗位来源 | Gartner 或其他岗位来源 |
| 岗位分类 | 岗位分类 |
| 岗位名称 | 岗位名称 |
| 候选安全职能 | 自动或人工候选的内部安全职能 |
| 匹配依据 | 候选匹配依据 |
| 复核状态 | 是否已人工复核 |

设计注意：

- GB/T 映射支持反向查看，但不自动作为最终事实；
- Gartner 候选映射统一显示为“待复核”；
- 岗位参考页的目标是辅助人工确认，不是自动替换内部职能体系。

## 13. 右侧详情面板通用规则

右侧详情面板应包含：

| 区块 | 说明 |
|---|---|
| 对象标题 | 显示对象类型、编码和名称 |
| 对象描述 | 显示业务说明 |
| 关键事实 | 以短字段展示数量、层级、状态等 |
| 关联对象 | 分组展示服务、作用域、流程、职能、能力、关注点等 |
| 来源证据 | 默认折叠或低干扰展示 |

交互规则：

- 中间表格选择一行后，右侧详情同步更新；
- 默认选中当前列表第一行；
- 没有选中对象时显示“请选择专项对象”；
- 来源证据不应占据主阅读区域；
- 不在主表中展示 `sheet`、`row`、`column`、`raw_value`、`metadata`、`debug` 等非业务字段。

## 14. 搜索与筛选

当前前端已有搜索入口，原型可按以下方式设计：

- 全局搜索框位于专项主区顶部或工具栏；
- 搜索结果只过滤当前专项页；
- 搜索字段包括编码、名称、说明和主要关联对象名称；
- 后续可增加表头筛选，但原型阶段先保留简洁表格。

## 15. 空状态

| 页面 | 空状态提示 |
|---|---|
| 作用域清单 | 暂无作用域数据 |
| 流程清单 | 暂无流程清单数据 |
| 职能清单 | 暂无职能清单数据 |
| 安全工作清单 | 暂无安全工作数据 |
| 安全技术模块清单 | 暂无安全技术模块数据，请确认 ETL 是否已导出 `security_technology_modules` |
| 安全技术措施清单 | 暂无安全技术措施数据，请确认 ETL 是否已导出 `security_technical_measures` |
| LC-AP参考数据 | 暂无 LC-AP 参考数据，请确认 `lifecycle-knowledge.json` 是否已导出 |
| 岗位参考页面 | 暂无岗位参考页面数据，请确认 ETL 是否已导出 `gbt_42446_references` 与 `gartner_roles` |

## 16. 不做事项

原型设计阶段不做以下内容：

- 不做编辑保存；
- 不做删除；
- 不做批量导入；
- 不做数据库 schema 设计；
- 不做复杂图谱；
- 不展示调试字段；
- 不把来源文件行列作为主展示内容；
- 不把候选映射当成已确认事实；
- 不混淆安全技术模块和安全技术措施；
- 不把 LC-AP 参考数据放回 LC-AP 主页面。

## 17. Stitch 输出建议

建议让 Stitch 输出以下原型：

1. `专项知识维护` 总页面，包含左侧导航、中间表格、右侧详情。
2. `安全技术措施清单` 页面，重点展示服务、作用域、环境、对象关系。
3. `岗位参考页面`，重点展示 GB/T 与 Gartner 双页签。
4. `LC-AP参考数据` 页面，重点展示两个参考分区。

视觉风格建议：

- 本地知识库工作台风格；
- 表格密度适中，适合反复核对；
- 右侧详情轻量，不做营销卡片；
- 使用清晰标签区分“已确认”“待复核”“待补充”；
- 页面应偏工作台和治理台账，而不是展示型官网。
