# NIST CSF 2.0 原始表翻译核对与入库说明

生成日期：2026-05-18

## 1. 结论

- `CSF2.0` sheet 的编号和表结构可以用于后续入库。
- 入库前建议先调整部分中文翻译，主要是术语不统一、个别误译、个别错字和少量语序问题。
- 本轮不直接修改原始 Excel，只给出待确认修订建议。
- 用户已确认后续按两类入库：`CSF Core` 和 `CSF Tiers`，都展示在三级页面 `CSF` 下，并用 tab 页区分。

## 3. 建议统一但不影响入库的问题

| 范围 | 当前表现 | 建议 |
|---|---|---|
| Function 名称 | `治理Govern（GV）`、`识别IDENTIFY (ID)`、`保护PROTECT（PR）` 等格式不统一 | 统一为 `治理 GOVERN (GV)`、`识别 IDENTIFY (ID)`、`保护 PROTECT (PR)`、`检测 DETECT (DE)`、`响应 RESPOND (RS)`、`恢复 RECOVER (RC)` |
| `Strategy` | 有时译为“战略”，有时译为“策略” | CSF Function / Category 中 `Strategy` 建议统一译为“战略”；`Policy` 统一译为“政策” |
| `risk appetite / risk tolerance` | 当前为“风险容忍度和风险偏好” | 可统一为“风险偏好和风险容忍度”，与英文顺序一致 |
| `adverse event` | 当前译为“不良事件” | 可以保留；如后续和国内安全运营术语统一，也可改为“负面事件/不利事件” |
| `provenance` | 当前译为“来源” | 可以保留；更严谨可译为“来源/出处” |
| 中文标点 | 部分半角分号、括号、冒号不统一 | 入库前建议统一为中文标点，并保留英文括号内容 |

## 4. 结构顺序提醒

原始表中 `GV.PO` 位于 `GV.RR` 前面；NIST CSF 2.0 PDF 的 Table 1 和附录 A 详细章节顺序为：

1. `GV.OC`
2. `GV.RM`
3. `GV.RR`
4. `GV.PO`
5. `GV.OV`
6. `GV.SC`

这不是内容缺失问题，但后续页面展示和入库排序建议按 PDF 顺序展示。

## 5. 入库和页面展示建议

- `CSF` 作为标准/框架三级页面。
- 页面内使用两个 tab：
  - `CSF Core`：展示 6 个 Function、22 个 Category、106 条 Subcategory。
  - `CSF Tiers`：展示 4 条 Tier，以及 `Cybersecurity Risk Governance`、`Cybersecurity Risk Management` 两列说明。
- 两类数据应独立建模或至少独立投影，不混为同一张控制项清单。
- 入库前建议先按本文第 2 节完成原始表翻译修订，或在 ETL 投影层做“规范化展示字段”，避免修改原始表。
