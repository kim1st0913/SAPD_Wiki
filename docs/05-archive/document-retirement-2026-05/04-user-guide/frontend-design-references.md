# 前端设计参考：知识库与治理台账页面

本文记录当前 SAPD Wiki 前端重构可借鉴的 3 类系统参考。目标不是复制外观，而是借鉴信息架构和交互模式。

## 参考 1：OpenMetadata / Data Catalog

参考链接：<https://docs.open-metadata.org/latest/how-to-guides/data-discovery>

适合借鉴：

- 左侧统一导航区，按资源类型进入页面。
- 列表页支持搜索、筛选和分类。
- 详情页把概览、关系、来源、治理信息拆成清晰区域。
- 对象之间的 lineage / relation 不混入主列表，而作为详情页中的独立关系视图。

对本项目的启发：

- `能力目录` 应像业务主目录，支持树、搜索、详情、关联关系。
- `知识来源` 应像数据目录，按来源类型进入清单页。
- 每类对象都应该有“清单页 + 详情页 + 关系区”，而不是把所有信息堆在一个长页面里。

## 参考 2：DataHub / Metadata Platform

参考链接：<https://docs.datahub.com/docs/features/feature-guides/>

适合借鉴：

- 用统一实体页承载不同类型资产。
- 首页不是功能说明，而是搜索、浏览和最近/常用入口。
- 关系、血缘、ownership、domain、glossary 等信息分区展示。

对本项目的启发：

- 后续可以把 `能力`、`流程`、`职能`、`标准`、`岗位` 都视为统一知识实体。
- 顶层导航不宜按技术实现命名，而应按用户任务命名：`能力地图`、`知识来源`、`关系查询`、`导出审查`。
- 页面应该支持从任一实体跳转到相关实体，而不是只能单向从能力树进入。

## 参考 3：Backstage Software Catalog

参考链接：<https://backstage.io/docs/features/software-catalog/>

适合借鉴：

- 资源目录以表格/列表为核心，支持类型、系统、所有者、标签等维度筛选。
- 详情页以 tab 或分区展示 Overview、Relations、Docs、Dependencies 等内容。
- Catalog 页面先解决“找对象”和“理解对象关系”，不是做花哨展示。

对本项目的启发：

- `安全工作职能`、`安全流程`、`标准与规范参考`、`岗位参考` 更适合清单表格，而不是大块卡片。
- 清单页应有固定列：编码、名称、类型/分组、上级、来源 Sheet、关联数量。
- 详情页再展示说明、来源引用、关联能力/流程/职能。

## 当前前端重构建议

下一版建议采用：

- 顶层：`能力地图`、`知识来源`、`关系查询`、`导出与审查`
- `能力地图`：保留能力树，但右侧改成对象详情页，而不是同时塞大量关联卡片。
- `知识来源`：二级页面保留 `安全工作职能`、`安全流程`、`标准与规范参考`、`岗位参考`，但每页改为清单表格优先。
- `关系查询`：专门展示“能力-流程-职能-标准-岗位”的交叉查询。
- `导出与审查`：显示导入任务、数据质量问题、导出入口。

近期最小调整：

- 先把 `安全工作职能` 和 `安全流程` 从卡片列表改为可扫描的表格清单。
- 卡片只留给详情展开或图片资产。
- 每个清单页保留搜索、筛选和来源追踪入口。
