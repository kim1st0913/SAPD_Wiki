# 专项知识维护页面原型说明

> 归档状态：`historical / superseded prototype brief`

本文档用于导出给 Stitch 进行页面原型设计。它描述当前 `专项知识维护` 模块的页面逻辑、信息架构、表格字段、详情面板和交互规则。

本文档只描述原型设计口径，不修改前端代码、不修改 ETL、不修改数据库 schema。

## 0. 前后端边界

专项知识维护页面先采用本地 API 过渡模式。

数据链路：

```text
SQLite / ETL
-> 后端导出数据包
-> /api/v1/data-packages/*
-> 前端 dataClient
-> ViewModel
-> 页面组件
```

当前本地 API：

| 接口 | 用途 |
|---|---|
| `GET /api/v1/maintenance` | 专项知识维护导航和数量 |
| `GET /api/v1/maintenance/scopes` | 作用域清单数据 |
| `GET /api/v1/maintenance/processes` | 流程清单数据 |
| `GET /api/v1/maintenance/work-functions` | 职能清单数据 |
| `GET /api/v1/maintenance/security-works` | 安全工作清单数据 |
| `GET /api/v1/maintenance/modules` | 安全技术模块清单数据 |
| `GET /api/v1/maintenance/measures` | 安全技术措施清单数据 |
| `GET /api/v1/maintenance/lcap-references` | LC-AP 参考数据 |
| `GET /api/v1/maintenance/references` | 岗位参考页面数据 |

说明：当前前端仍保留静态 JSON 降级能力；Stitch 原型只需要按页面结构设计，不需要表现数据加载实现细节。

## 1. 页面定位

`专项知识维护` 是 SAPD Wiki 的主数据和参考数据核对区，不是来源文件浏览器，也不是客户评估页面。

它的目标是让用户以“专项对象清单 + 关系详情”的方式维护和核对以下知识对象：

- 安全作用域；
- 安全流程；
- 安全职能；
- 安全工作；
- 安全技术模块；
- 安全技术措施；
- LC-AP 参考数据；
- 岗位参考数据。

页面应优先服务人工核对、关系理解和数据质量确认，不展示无业务含义的调试字段。

## 2. 总体页面布局

建议采用三栏结构。

| 区域 | 用途 | 设计要求 |
|---|---|---|
| 左侧导航 | 展示专项页面入口和数量 | 使用垂直导航，当前页高亮；每项显示名称和数量 |
| 中间主区 | 展示当前专项对象表格 | 表格优先，支持滚动、选择行、搜索和筛选扩展 |
| 右侧详情 | 展示当前选中对象的业务详情和关联对象 | 以事实卡片、关系分组和来源证据组成 |

建议布局：

```text
专项知识维护
├─ 左侧：专项导航
├─ 中间：当前专项清单 / 页签表格
└─ 右侧：对象详情 / 关系详情 / 来源证据
```

## 3. 左侧导航

当前专项页面入口如下。

| 导航项 | 页面 ID | 页面说明 |
|---|---|---|
| 安全能力清单 | `capability-directory` | 维护和核对安全能力与安全关注点，按 L0 / L1 / L2 归纳展开 |
| 作用域清单 | `scopes` | 维护和核对安全作用域 |
| 流程清单 | `processes` | 维护和核对安全流程，展示 L2 流程组、L3 流程、L4 活动 |
| 职能清单 | `work-functions` | 维护和核对安全职能，展示 4 层职能结构 |
| 安全工作清单 | `security-works` | 维护和核对安全工作，展示与安全能力 / 关注点的关系 |
| 安全技术服务清单 | `services` | 维护和核对安全技术服务编号、作用域和关联安全技术模块 / 措施，后续补充服务定义 |
| 安全技术模块清单 | `modules` | 维护和核对安全技术模块 |
| 安全技术措施清单 | `measures` | 维护和核对安全技术措施 |

导航交互：

- 点击导航项切换中间主区；
- 切换页面时清空当前选中对象；
- 默认进入 `作用域清单`；
- 每个导航项可显示对象数量；
- 未接入数据时显示空状态，不隐藏入口。

## 4.1 表格关联属性统一样式

适用范围：`信息化环境安全能力映射`、`安全知识`、`安全标准/框架` 下所有表格页面。

表格中如果某列不是当前表格的主键字段，而是关联属性，应统一使用关联属性 chip 样式展示。典型字段包括：

- 归属安全能力 / 关注点；
- 关联安全技术服务；
- 关联安全技术模块 / 措施；
- 关联安全系统；
- 关联信息化环境；
- 关联信息化对象；
- 关联流程、职能、标准控制项等关系字段。

统一样式要求：

- 关联对象按类型使用低饱和莫兰迪色系区分，避免高亮绿或高饱和色；推荐口径为：安全技术服务用雾蓝，能力关注点用鼠尾草绿，安全技术模块用灰绿，安全技术措施用暖杏，安全系统用薰衣草灰，信息化环境 / 对象用青灰；
- 不同类型仍应通过 chip 前缀文字明确表达，例如 `安全技术模块 | 名称`、`安全技术措施 | 名称`；颜色只做辅助识别，不能替代文字语义；
- chip 使用圆角胶囊形态，字号、字重、内边距和行高保持一致；
- chip 支持自然换行和长词断行，不能撑破单元格；
- 同一单元格内多个 chip 应左上对齐、等间距换行排列；
- 空值、待补充、待确认使用灰色或提示色，不伪装成已存在的关联对象；
- 表头保持居中，关联属性列的正文靠左上展示，优先保证可读性；
- 表格列宽应为关联属性预留稳定宽度，避免某一列过窄导致文字竖排或频繁横向跳动。
- 表格容器高度应按内容和视口收敛，避免在明细不足时出现大面积无效留白。

## 4.2 层级分组行统一样式

适用范围：`安全知识` 下带层级归纳展开的目录表格，例如安全能力清单、安全技术模块清单，以及后续新增的同类目录页面。

统一样式要求：

- 层级标签使用无圆点胶囊，不使用关联对象 chip 的黑点前缀；
- 层级标签必须使用业务名称，不使用 `L0 / L1 / L2` 作为页面文案；安全能力清单使用“能力分类 / 能力域 / 能力 / 关注点”，安全技术模块清单使用“领域分类 / 安全系统”；
- 层级越深，标题区应有适度左缩进，帮助用户快速识别归属关系；
- 分组标题是当前层级主信息，应比统计数量、说明文字更重；统计数量保持右侧弱强调；
- 下级已用胶囊表达的层级文案，不在分组行下方重复显示；
- 目录表格宽度必须随窗口和父容器自适应，默认使用 `width: 100%`，不得用固定超宽 `min-width` 把页面顶出一屏；
- 层级缩进应轻量克制，避免压缩编码和长文本列；安全能力清单参考 `10 / 30 / 50 / 56px` 的分类、能力域、能力和关注点缩进；
- 1920px 宽屏下优先保证主编码、名称和长描述可读，编码列不得过宽，长描述列应获得主要宽度；
- 编码列必须保持单行，不得因为胶囊或中划线编码被拆行；名称列按当前表内最长名称计算受控宽度，不能无限抢占描述列；
- 分组行和明细行的长描述可以在当前可用宽度内单行截断并保留完整 tooltip，但不得通过横向溢出或自动换行撑高表格行。

## 5. 安全能力清单

业务含义：安全能力清单用于查看安全能力树的主数据结构。页面不承担关系映射核对，关系核对仍由“安全能力映射”工作台完成。

表格结构：

| 层级 | 展示方式 |
|---|---|
| L0 能力分类 | 一级分组行，展示分类编码 / 名称，不再展示重复的“能力分类”说明 |
| L1 能力域 | 二级分组行，展示能力域编码 / 名称，不再展示重复的“能力域”说明 |
| L2 安全能力 | 三级分组行，使用“能力”胶囊展示安全能力编码 / 名称，并直接展示完整安全能力定义文本，不再显示“安全能力定义”前缀 |
| 安全关注点 | 明细行在关注点编码前显示“关注点”胶囊，并展示关注点编码、名称和关注点描述；安全能力定义只在所属 L2 分组行展示 |

表格字段：

| 字段 | 说明 |
|---|---|
| 编码 | 安全关注点编码 |
| 名称 | 安全关注点名称 |
| 关注点描述 | 安全关注点的原始描述 |

设计注意：

- L0、L1、L2 使用表格内分组行，不新增独立树导航；分组胶囊文案为“能力分类 / 能力域 / 能力”，安全能力定义只在 L2 分组行展示；
- 关注点明细行使用随容器伸缩的比例列宽，压缩编码列，名称和描述列优先获得宽度，减少 1920px 宽屏下的截断；
- 分组行默认展开第一条路径，保留 CRF / 知识清单类表格的层级展开交互；
- 主表只显示安全能力和关注点原始业务字段，不展示 `metadata`、`sources`、`sheet`、`row` 等来源或中间字段。

## 9. 安全技术服务清单

业务含义：安全技术服务是能力关注点在某个作用域下的技术服务单元，是“作用域 → 服务 → 模块 / 措施”链路的中间层。服务在表格中必须带编号显示，例如 `I-NT&T-PD.PP-03 网络隔离`。

表格字段：

| 字段 | 说明 |
|---|---|
| 序号 | 当前列表序号 |
| 安全技术服务 | 服务编号 + 服务名称 |
| 定义 | 服务定义，当前可显示为待补充定义 |
| 归属安全能力-关注点 | 从服务编号映射出的安全能力 / 关注点归属 |
| 关联安全技术模块/措施 | 来自权威安全技术模块清单和措施清单的关联对象 |
| 关联安全系统 | 由模块关联出的安全系统 |
| 关联信息化环境 | 由服务 / 模块映射出的环境 |

右侧详情：

| 分区 | 内容 |
|---|---|
| 基本事实 | 服务编号、归属安全能力 / 关注点、关联安全技术模块 / 措施、定义状态 |
| 归属安全能力-关注点 | 相关安全能力和关注点 |
| 关联安全技术模块/措施 | 与该服务关联的安全技术模块或安全技术措施 |
| 关联安全系统 | 由模块归属得到的安全系统 |
| 来源证据 | 来源追踪信息 |

设计注意：

- 安全技术服务在所有表格 chip 中都应显示编号 + 名称；
- 服务定义暂缺时显示 `待补充定义`，不在前端伪造定义；
- 安全技术服务清单必须保持完整表格，不使用左侧作用域目录或独立树形导航；
- 需要“归纳、收纳、展开”时，应在表格内部按作用域生成分组汇总行，并支持展开 / 收起；
- 安全技术服务清单分组默认收起；用户展开后刷新页面时，应保留已展开分组和刷新前停留位置；
- `ALL` 服务在表格中显示为 `安全运行类安全技术服务`，并排在 `M` 开头服务之前；
- `M` 开头服务单独显示为 `安全管理类安全技术服务`，不混入用户作用域分组；
- 表格分组内的服务明细依据能力树中的能力和关注点顺序排序，不能只按导入顺序或字符串顺序排列；
- “关联安全技术模块/措施”表达服务与模块 / 措施的映射关系，不使用“实现安全技术模块”作为表头或详情分区文案；
- “关联安全技术模块/措施”列中的 chip 必须显式区分 `安全技术模块 | 名称` 与 `安全技术措施 | 名称`，并使用低饱和莫兰迪色系做辅助区分；能力关注点、安全技术服务、安全系统、信息化环境等关联字段也按全局关联属性 chip 色板展示，不能再回退到单一亮绿色；
- 服务页只承载服务目录与关系核对，不把模块或措施混成服务。

## 10. 安全技术模块清单

业务含义：安全技术模块是支撑安全技术服务的标准技术能力模块，不等同于安全技术措施、安全系统或产品。

表格字段：

| 字段 | 说明 |

展示规则：按工作类别归纳收纳展开；展开后显示 `承担的工作任务` 和 `工作任务描述` 两列。描述列遵循全局表格基线，优先占用剩余宽度，长文本在单行中省略并通过悬停标题保留完整内容。

## 13. 右侧详情面板通用规则

右侧详情面板应包含：

| 区块 | 说明 |
|---|---|
| 对象标题 | 显示对象类型、编码和名称 |
| 对象描述 | 显示业务说明 |
| 关键事实 | 以短字段展示数量、层级、状态等 |
| 关联对象 | 分组展示服务、作用域、流程、职能、能力、关注点等 |
| 来源证据 | 默认折叠或低干扰展示 |

交互规则：

- 中间表格选择一行后，右侧详情同步更新；
- 默认选中当前列表第一行；
- 没有选中对象时显示“请选择专项对象”；
- 来源证据不应占据主阅读区域；
- 不在主表中展示 `sheet`、`row`、`column`、`raw_value`、`metadata`、`debug` 等非业务字段。

## 14. 搜索与筛选

当前前端已有搜索入口，原型可按以下方式设计：

- 全局搜索框位于专项主区顶部或工具栏；
- 搜索结果只过滤当前专项页；
- 搜索字段包括编码、名称、说明和主要关联对象名称；
- 后续可增加表头筛选，但原型阶段先保留简洁表格。

## 16. 不做事项

原型设计阶段不做以下内容：

- 不做编辑保存；
- 不做删除；
- 不做批量导入；
- 不做数据库 schema 设计；
- 不做复杂图谱；
- 不展示调试字段；
- 不把来源文件行列作为主展示内容；
- 不把候选映射当成已确认事实；
- 不混淆安全技术模块和安全技术措施；
- 不把 LC-AP 参考数据放回 LC-AP 主页面。

## 17. Stitch 输出建议

建议让 Stitch 输出以下原型：

1. `专项知识维护` 总页面，包含左侧导航、中间表格、右侧详情。
2. `安全技术措施清单` 页面，重点展示服务、作用域、环境、对象关系。
3. `岗位参考页面`，重点展示 GB/T 与 Gartner 双页签。
4. `LC-AP参考数据` 页面，重点展示两个参考分区。

视觉风格建议：

- 本地知识库工作台风格；
- 表格密度适中，适合反复核对；
- 右侧详情轻量，不做营销卡片；
- 使用清晰标签区分“已确认”“待复核”“待补充”；
- 页面应偏工作台和治理台账，而不是展示型官网。
