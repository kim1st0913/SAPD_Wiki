# SAPD Wiki 执行线收敛说明

> 归档状态：`retired / historical`

> 状态：2026-07-17 已收敛为历史背景说明。当前可执行规则以仓库根 `AGENTS.md` 的 `Parallel Agent Orchestration`、`Session Health And Handoff` 和 `codex-session-handoff` Skill 为准。

## 为什么曾经采用多会话

此前的多会话、固定主控、执行线台账和频繁交接，是在内部子 Agent 不稳定、主任务无法可靠编排并行工作、长会话恢复变慢时形成的临时替代方案。它们短期增加吞吐，长期也造成了同一 checkout 并发写入、dirty diff 混杂、验收归属不清和上下文重复。

这段历史不应被解释为用户偏好多开会话，也不再作为当前工作流。

## 当前结论

- 当前任务内只有存在可独立推进的实质工作流时，才由父 Agent 通过内部子 Agent 编排。
- 父 Agent 保留关键路径、集成、项目记忆和最终合并态验收。
- 编码子任务必须使用隔离 workspace 和互不重叠的 write set。
- 设计、调研和验证可以作为只读或边界清晰的 sidecar 并行；不得和实现 Agent 争写同一 owner。
- 独立 Codex task 只用于用户明确要求的长期工作流，并使用独立 worktree；同一 checkout 不承担多 writer 并行。
- handoff 用于上下文恢复或用户明确的任务迁移，不再作为正常并行开发机制。
- 慢任务先区分模型推理、命令执行、审批等待、工具挂起、上下文压力和并发写入，再选择恢复措施。

## 已停用的旧机制

以下内容不再定义当前执行状态：

- 固定 `EL-xxx` 执行线和 fan-in；
- 按线程标题判断主控或优先级；
- 子 Agent 默认只读；
- 为卡顿自动创建同名递增 task；
- 每次交接都更新多个状态文档；
- 把多个同目录主会话当作实现 worker。

历史记录仍可从 Git 追溯，不应复制到新提示词或交接包。
