# ArchiMate 建模语言页优化评估

> 归档状态：`completed / historical page plan`

本文档用于把 `安全指南 / 安全架构建模语言` 页面的优化纳入统一项目治理，记录用户否定旧“下方区域阅读器”方案后的最新目标和验收门槛。

## 2026-06-07 最新用户确认方向

用户明确要求：不要在 Poster 下方做区域阅读器。最新纠偏要求是先保留整张 ArchiMate PDF / Poster 图的清晰阅读和近满屏查看；如果区域浮层不能严格按图片切割，则先不要做分块点击，避免误导。

最新实现方向：

- 第一 tab 保留为 `ArchiMate® 3.2 - 企业架构建模标准`，`SAPD 元素图例` 作为第二 tab 并列。
- tab 组跟在最大标题 `安全架构建模语言` 后面，`全页面显示` / `下载 PDF` 跟在第二标题 `ArchiMate® 3.2 - 企业架构建模标准` 后面。
- 删除 `ArchiMate® 3.2` 胶囊、顶部说明文案和内容区说明文案。
- 删除下方 `区域阅读`、区域目录、当前区域阅读器和区域卡片。
- 主体只保留整张 ArchiMate Poster，并允许页面内纵向滚动查看。
- 当前不渲染不精确热区；后续如要恢复分块点击，必须先有严格切割坐标或可靠的源图区域标定。
- 点击图片或 `全页面显示` 时采用页面内 Image Lightbox / Fullscreen Modal，对预览容器调用 Fullscreen API，不使用新窗口、`Blob` 页面或浏览器原生新窗口 UI。
- `SAPD 元素图例` registry 受控渲染保持不变。

  - 提供上方 PDF 下载入口和近满屏整图查看。

## 当前主要问题

### 1. 页面仍像“素材陈列”，不是“建模语言工作页”

当前页面把 ArchiMate Poster 图片放进了页面，但没有形成清晰的阅读任务：

- 用户不知道先看整页、区域还是 SAPD 图例。
- 区域卡片只是切图入口，不说明“这个区域和 SAPD 安全架构建模有什么关系”。
- ArchiMate 标准、SAPD 元素图例、后续元模型 / 信息化环境建模之间的层级关系还不够清楚。

### 2. 首屏信息密度和阅读路径不理想

当前首屏主要由大图占据。大图能作为参考，但用户真正需要的是：

- 快速知道 ArchiMate 3.2 提供了哪些元素层；
- 哪些元素会被 SAPD 使用；
- 当前 SAPD 图例对应哪些 ArchiMate 元素；
- 后续建模时如何从“标准元素”走到“安全架构对象”。

### 3. 放大阅读需要优先清晰和少干扰

当前用户更关注全页面图片是否足够清晰、是否尽量覆盖屏幕，以及弹层是否减少干扰。因此当前不优先做区域切换，而是先保证：

- 弹层不显示标题栏和下载入口；
- 退出按钮浮在图片右上角附近；
- 大图区域可滚动，不截断底部内容；
- 图片尽量使用原始整页 JPG 尺寸缩放，避免模糊。

### 4. 加载效率仍有优化空间

当前虽然避免了 PDF iframe 卡顿，但仍存在潜在浪费：

- 首屏 eager 加载整页大图。
- 页面不应加载不使用的区域缩略图。
- 弹层只加载当前整页图，不预加载不精确切片。
- 缺少图片尺寸声明，浏览器布局可能先渲染后回流。

## 推荐目标体验

该页后续应从“PDF / 图片查看器”升级为“建模语言参考工作页”：

```text
页面顶部：安全架构建模语言标题
右上：ArchiMate 标准 / SAPD 元素图例 tab + 工具按钮
主区：整张 ArchiMate Poster
Poster 覆盖层：当前不渲染不精确热区

第二 tab：SAPD 元素图例，按 registry 受控渲染
```

## 优化建议

### P0：先分清页面职责

建议把页面拆成三个清晰层次，而不是继续叠在一个 tab 内：

| 层次 | 目标 | 展示方式 |
|---|---|---|
| ArchiMate 标准概览 | 阅读标准海报，不承担 SAPD 映射结论 | 整张 Poster + 全页面显示 + 下载 PDF |
| SAPD 元素图例 | 展示 SAPD 使用哪些 ArchiMate notation | registry 驱动图例表 |
| SAPD 建模方法 | 说明如何把标准元素用于环境 / 安全架构建模 | 后续独立说明区或新 tab |

### P1：暂缓不精确热区，先保证整图阅读

用户已明确不需要下方区域阅读器，也指出如果区域浮层不能严格按照图片切割，还不如不要。当前更适合的结构是：

- 中间只显示整张 ArchiMate Poster。
- 不渲染透明点击热区和 hover 标题。
- 保证 Poster 容器可纵向滚动，不截断页面底部。
- 后续如恢复分块点击，先建立严格坐标或源图区域标定，再做交互。

这样可以同时增强显示效果和减少首屏加载。

### P2：增强放大阅读

全页面显示采用当前页面内 Image Lightbox / Fullscreen Modal，当前优先实现：

- 点击图片或 `全页面显示` 均打开同一个预览层；
- 对预览容器调用 Fullscreen API；
- 深色遮罩底色；
- 右上角关闭按钮；
- 不显示标题、下载 PDF、下载图片按钮和区域切换；
- 键盘支持：`Esc` 关闭；
- 点击遮罩空白区域关闭；
- 默认 contain 适配屏幕，支持工具栏按钮和鼠标滚轮缩放；
- 放大后可按住图片区域拖动平移；
- 整图预览资源从 PDF 重新导出为 `6741 x 4768` 高分辨率 JPG，优先保证放大后的文字清晰度；
- 大图区域内只滚动图片，不让整页滚动链路混乱。

### P3：加载效率优化

建议加载策略：

- 首屏只加载整张 Poster，不再加载 6 张区域图。
- 图片标签补 `width` / `height` 或 `aspect-ratio`，减少布局抖动。
- PDF 不参与首屏加载，只保留下载链接。

### P4：让 SAPD 图例和 ArchiMate 区域发生关系

后续真正有价值的是建立“区域 -> SAPD 元素类型”的关联，例如：

| ArchiMate 区域 | SAPD 图例关联 |
|---|---|
| 业务层与通用元素 | 安全组织、岗位、人员、职能 / 角色、流程 |
| 应用层 | 应用组件、应用功能、应用服务、数据对象 |
| 技术层与物理层 | 节点、设备、系统软件、通信网络、设施、制品 |
| 关系与视图 | Serving、Flow、Access 等关系线 |

该关联应来自 registry 或受控配置，不应在页面中临时写死。

## 建议验收标准

- 进入页面首屏不加载 PDF。
- 首屏图片请求不超过 2 张。
- 默认整图在固定 `5173` 下快速显示。
- 用户能在 2 次点击内完成：查看整页、下载 PDF、切到 SAPD 元素图例。
- `SAPD 元素图例` 仍按 notation registry 受控渲染，不自由绘制。
- 页面不展示非业务字段。
- 移动 / 窄屏下 Poster 不被额外浮层遮挡，独立窗口退出按钮不压住主要阅读区。

## 后续执行建议

该优化应作为单独执行线处理，不与安全能力映射、LC-DT、Delivery 或全局 CSS 治理混写。

建议下一轮先做只读设计验收：

1. 固定当前页面截图或 DOM 摘要。
2. 记录当前图片加载请求和首屏渲染结构。
3. 用户确认整图阅读效果后，再决定是否需要基于严格坐标恢复分块点击。
