# 主工程与成熟度模块集成检查

> 归档状态：历史集成检查证据，不作为当前验收结论。

本文档用于主控 Agent 判断 SAPD Wiki 主工程是否已经具备承接 maturity 模块后续 M1 的边界条件。本文档不替代 `task_plan.md`，也不启动 maturity 代码实现。

本轮检查范围：

- 主工程架构边界；
- 主知识库数据模型边界；
- maturity 运行数据与客户敏感数据边界；
- 总控计划边界；
- 进入 M1 前的必要条件；
- 不能被 maturity 打断的主工程工作。

本轮不做：

- 不修改数据库 schema；
- 不实现 maturity CLI；
- 不改前端；
- 不改 ETL；
- 不生成评估模板；
- 不导入客户数据。

## 1. 总体结论

主工程已经具备 maturity 模块后续接入的基本边界，但尚不建议立即进入 M1。

当前更稳妥的主控判断是：

```text
主工程可以承接 maturity 模块
但 maturity 仍停留在 M0
下一主线继续是已导入 Sheet 业务含义复核
```

理由：

- `docs/08-maturity/` 已经形成 maturity 需求、模型、规则、模板和计划；
- `config/maturity/` 已经有评分、等级、关键词、模板和报告配置占位；
- `architecture.md` 已明确 maturity 是主工程下的独立业务模块；
- `data-governance.md` 已明确客户评估输入、证据、报告不进入 GitHub；
- `.gitignore` 已忽略 `data/maturity/`；
- `task_plan.md` 已将 maturity 标记为 `m0_complete`；
- 但当前主工程仍处于 Phase 5 的 Sheet 业务复核阶段，第二批和第三批业务语义尚未完成最终确认。

```text

+

+

```

## 7. 不能被 maturity 打断的主工程工作

以下主工程工作优先级高于 maturity M1：

1. 第二批管理 / 流程 / 职能 / 岗位 Sheet 业务含义复核；
2. 第三批 LC-AP 生命周期 Sheet 业务语义确认；
3. 已有前端关系展示中“技术上可显示但业务表达不准确”的校正；
4. `open-issues.md` 中仍处于待确认或处理中的主工程问题；
5. 数据导入、复导、旧对象停用和 source traceability 的稳定性。

主控原则：

```text
maturity 是旁路模块
不能抢占主工程数据语义复核
不能推动前端提前扩页面
不能让客户评估数据进入主知识库
```
