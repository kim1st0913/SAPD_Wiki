# ArchiMate 建模语言页优化评估

本文档用于把 `安全指南 / 安全架构建模语言` 页面的后续优化纳入统一项目治理。当前不直接改前端代码，先固定页面现状、问题判断、优化方向和验收门槛。

## 当前页面现状

- 页面入口：`/guides/security-architecture-modeling-language`
- 页面类型：`document-page`
- 当前 tab：
  - `ArchiMate® 3.2 - 企业架构建模标准`
  - `SAPD 元素图例`
- 当前素材：
  - 本地 PDF：`archimate-poster-v3.2-zh.pdf`，约 `1.9M`
  - 整页 JPG：`archimate-poster-overview.jpg`，`2600×1839`，约 `572K`
  - 6 个区域 JPG：合计约 `1M`
- 当前实现：
  - 不再直接 iframe 嵌入 PDF。
  - 首屏显示整页 JPG。
  - 区域阅读以 6 个卡片缩略图呈现，点击后弹层放大。
  - 提供 PDF 下载入口。

## 当前主要问题

### 1. 页面仍像“素材陈列”，不是“建模语言工作页”

当前页面把 ArchiMate Poster 图片放进了页面，但没有形成清晰的阅读任务：

- 用户不知道先看整页、区域还是 SAPD 图例。
- 区域卡片只是切图入口，不说明“这个区域和 SAPD 安全架构建模有什么关系”。
- ArchiMate 标准、SAPD 元素图例、后续元模型 / 信息化环境建模之间的层级关系还不够清楚。

### 2. 首屏信息密度和阅读路径不理想

当前首屏主要由大图占据。大图能作为参考，但用户真正需要的是：

- 快速知道 ArchiMate 3.2 提供了哪些元素层；
- 哪些元素会被 SAPD 使用；
- 当前 SAPD 图例对应哪些 ArchiMate 元素；
- 后续建模时如何从“标准元素”走到“安全架构对象”。

### 3. 放大阅读缺少导航能力

当前点击区域后可以放大，但缺少：

- 区域内锚点；
- 上一区域 / 下一区域；
- 当前区域与 tab、目录、SAPD 元素类型的关联；
- 缩放级别或适屏 / 原图切换。

### 4. 加载效率仍有优化空间

当前虽然避免了 PDF iframe 卡顿，但仍存在潜在浪费：

- 首屏 eager 加载整页大图。
- 页面渲染时一次性生成 6 个区域卡片和缩略图。
- 弹层打开区域时复用同一张区域图，但没有明确加载状态和预加载策略。
- 缺少图片尺寸声明，浏览器布局可能先渲染后回流。

## 推荐目标体验

该页后续应从“PDF / 图片查看器”升级为“建模语言参考工作页”：

```text
页面顶部：一句话说明 ArchiMate 与 SAPD 的关系
左侧 / 顶部：标准海报区域目录
主区：当前区域阅读器
右侧 / 下方：SAPD 映射说明与下一步建模入口
第二 tab：SAPD 元素图例，按 registry 受控渲染
```

## 优化建议

### P0：先分清页面职责

建议把页面拆成三个清晰层次，而不是继续叠在一个 tab 内：

| 层次 | 目标 | 展示方式 |
|---|---|---|
| ArchiMate 标准概览 | 阅读标准海报，不承担 SAPD 映射结论 | 区域阅读器 + 下载 PDF |
| SAPD 元素图例 | 展示 SAPD 使用哪些 ArchiMate notation | registry 驱动图例表 |
| SAPD 建模方法 | 说明如何把标准元素用于环境 / 安全架构建模 | 后续独立说明区或新 tab |

### P1：把“区域卡片”改为“区域导航 + 阅读器”

当前 6 个区域卡片更像缩略图库。更适合的结构是：

- 左侧竖向区域目录：业务 / 应用 / 技术物理 / 动机战略 / 风险迁移 / 关系视图。
- 中间只显示当前选中区域图。
- 顶部保留整页缩略图或“查看整页”按钮。
- 区域切换不重新渲染整个页面，只替换主阅读器图片。

这样可以同时增强显示效果和减少首屏加载。

### P2：增强放大阅读

弹层不应只是大图容器，建议增加：

- `适应窗口` / `原图尺寸` 两种模式；
- 上一区域 / 下一区域；
- 当前区域标题固定在弹层顶部；
- 键盘支持：`Esc` 关闭，左右键切区域；
- 大图区域内只滚动图片，不让整页滚动链路混乱。

### P3：加载效率优化

建议加载策略：

- 首屏只加载当前默认区域的图片，不 eager 加整页大图。
- 整页图改为用户点击“查看整页”后再加载。
- 缩略图可使用更小尺寸或 CSS 背景占位，避免加载完整区域图做缩略图。
- 图片标签补 `width` / `height` 或 `aspect-ratio`，减少布局抖动。
- 区域图在用户 hover / idle 时预加载下一张。
- PDF 不参与首屏加载，只保留下载链接。

### P4：让 SAPD 图例和 ArchiMate 区域发生关系

后续真正有价值的是建立“区域 -> SAPD 元素类型”的关联，例如：

| ArchiMate 区域 | SAPD 图例关联 |
|---|---|
| 业务层与通用元素 | 安全组织、岗位、人员、职能 / 角色、流程 |
| 应用层 | 应用组件、应用功能、应用服务、数据对象 |
| 技术层与物理层 | 节点、设备、系统软件、通信网络、设施、制品 |
| 关系与视图 | Serving、Flow、Access 等关系线 |

该关联应来自 registry 或受控配置，不应在页面中临时写死。

## 建议验收标准

- 进入页面首屏不加载 PDF。
- 首屏图片请求不超过 2 张。
- 默认区域图在固定 `5173` 下快速显示。
- 用户能在 2 次点击内完成：查看整页、查看任一区域、下载 PDF、切到 SAPD 元素图例。
- `SAPD 元素图例` 仍按 notation registry 受控渲染，不自由绘制。
- 页面不展示非业务字段。
- 移动 / 窄屏下区域目录和阅读器不发生文字重叠。

## 后续执行建议

该优化应作为单独执行线处理，不与安全能力映射、LC-DT、Delivery 或全局 CSS 治理混写。

建议下一轮先做只读设计验收：

1. 固定当前页面截图或 DOM 摘要。
2. 记录当前图片加载请求和首屏渲染结构。
3. 用户确认目标方向后，再实现 P1 区域导航 + 阅读器。
