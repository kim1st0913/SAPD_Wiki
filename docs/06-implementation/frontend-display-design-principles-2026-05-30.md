# 前端展示类型与文字表格设计原则

日期：2026-05-30

适用范围：`frontend/capability-browser/` 当前正式前端。后续所有页面、组件、样式和局部视觉调整必须先判断属于本文哪一类展示类型，再按对应规则实现。

## 1. 目标

本文件用于解决当前前端视觉推进中的三个问题：

1. 文字、表格、标签、目录、图谱等展示类型缺少统一边界，容易局部修复后误伤其他页面。
2. 同一类业务对象在不同页面展示方式不一致，例如安全技术服务、作用域、安全职能、流程、标准 / 框架。
3. 后续工程需要明确可执行的设计约束，避免再次出现“配色改了但不明显”“tab 被改坏”“表格字段语义不对”“图谱和表格投影展示口径不一致”等问题。

本文不是新的 UI 实现任务，不修改数据链路，不修改 ETL，不定义新业务字段。

## 2. 基准与强制入口

- 正式前端视觉方向以 `DESIGN.md` 和 `frontend/capability-browser/apple-morandi-color-demo.html` 为准。
- 后续所有视觉改动必须先查看 `http://127.0.0.1:5173/apple-morandi-color-demo.html` 的 token、表格、tab、chip、状态色和 graph 语义色。
- 组件样式优先复用 `styles.css` 已有 token、语义 class 和展示 helper，不新增一次性颜色、一次性字号或一次性边框。
- 新增展示类型前，必须先判断是否能归入本文已有类型；确实不能归入时，应同步更新本文。

## 3. 当前前端展示类型穷举

### 3.1 全局应用壳展示

涉及文件：

- `frontend/capability-browser/index.html`
- `frontend/capability-browser/app.js`
- `frontend/capability-browser/components/AppShell.js`
- `frontend/capability-browser/styles.css`

展示类型：

- 全局侧边栏品牌区
- 一级导航项
- 二级导航项
- 导航分组标题
- 当前导航选中态
- 顶部栏页面上下文
- 全局搜索入口
- 顶部工具按钮
- 本地模式 / 数据状态标签
- 页面标题区
- 面包屑
- 页面说明
- 页面标签
- 页面操作按钮
- 主内容承载区
- 右侧洞察 / 详情承载区

约束：

- 侧边栏一级导航负责全局定位，字号不得小于主内容区普通正文。
- 二级导航必须清晰可读，当前基准为 `14px` 左右，不能降回过小的辅助文本。
- 彩色导航图标必须保证前景图案可识别；图案和底色不得使用过近的同色系低对比组合，必要时使用白色前景、轻描边和阴影提升可读性。
- 一级导航主入口名称优先可读，不用过宽侧栏挤压主工作区；桌面紧凑基准宽度约 `246-258px`，一级字号约 `13-14px`，图标约 `28-32px`，长中文入口允许自然换行，窄屏才进入折叠或省略策略。
- 顶部栏不得重复品牌表达；品牌只保留一个主入口。
- 顶部状态信息必须轻量，不能抢过页面标题和当前工作台。
- 搜索入口是全局入口，不实现真实搜索时也必须像真实控件一样稳定、清晰、低噪声。

### 3.2 工作台布局展示

涉及：

- 能力映射工作台
- 信息化环境映射工作台
- LC-AP 安全开发生命周期
- LC-DT 数据生命周期
- 知识库字典维护
- 安全标准 / 框架维护
- 说明页 / 内容页

展示类型：

- 左侧目录区
- 中央表格 / 矩阵区
- 中央关系图谱区
- 右侧详情区
- 右侧洞察区
- 分栏拖拽区
- 折叠目录区
- 横向滚动表格区
- 空状态工作台
- 占位页面

约束：

- 工作台第一目标是扫描、比较、定位，不做营销页、hero 区或大 KPI 卡墙。
- 三栏结构中，左栏是定位，中栏是主任务，右栏是辅助信息；右栏不得挤压核心表格或图谱。
- 1440px 下优先保证主任务可读；1920px 下允许更舒展，但不能只横向拉长空白。
- 目录折叠、表格横向滚动、详情收敛是合法响应式策略，不能把核心表格压成竖排字。
- 工作台高度必须由应用壳和当前 pane 的真实剩余空间决定，不能依赖 `100vh` / `100dvh` 减固定数值推算。
- 多层工作台必须形成明确高度链：外层工作区、pane、内容区、tab panel、表格容器逐层设置 `min-height: 0`，并用 `grid-template-rows: auto minmax(0, 1fr)` 或等价布局把剩余高度交给主内容区。
- 一个工作台内只能定义一个主纵向滚动边界；矩阵类页面优先让表体滚动，目录 / 外层 pane 不应同时产生会截断内容的纵向滚动。

涉及组件：

- `DimensionTree.js`
- `EnvironmentTree.js`
- `MaintenanceNavigation.js`
- `ApplicationSecurityLifecycle.js`
- `AppShell.js`
- `app.js` 内内容目录、dashboard 入口、placeholder 入口

展示类型：

- 能力对象树
- 关注点目录
- 信息化环境树
- 知识库字典维护目录
- 安全标准 / 框架目录
- LC-AP / LC-DT 阶段导航
- 内容页目录
- dashboard 快捷入口列表
- 目录搜索结果
- 展开 / 收起行
- 当前选中行
- 数量角标
- 层级编码

约束：

- 目录文本以对象名称为主，编码为辅助，不允许编码压过名称。
- 层级越深，视觉越轻，但字号不得小到不可读。
- 当前选中态只能用于用户正在查看的对象，不用于 hover 或装饰。
- 展开 / 收起状态必须明确，默认展开策略应按页面规则执行，不能因为配色调整改掉交互。
- 长名称使用省略号，不得撑破侧边栏或把行高撑到失控。

### 3.4 Tab、分段控件和视角切换展示

涉及：

- 能力映射的 `能力关系图谱 / 技术视角 / 管理视角 / 标准 / 框架映射`
- 环境映射页的视角切换
- LC-AP / LC-DT 阶段 tab
- 安全标准 / 框架 tab
- 知识库字典维护 tab
- 内容页 source mode switch

展示类型：

- 横向 tab
- 分段控件
- 阶段胶囊 tab
- 图谱 zoom 控制
- 表格筛选 chip
- 视图模式按钮

约束：

- tab 是导航控件，不是大卡片。高度、内边距和 active underline 必须受控。
- tab / segmented control 只显示稳定视图名称，不显示统计数字、对象数量、KPI、状态摘要或当前筛选条件。
- 统计数字应放在页面标题区、内容区标题右侧、表格摘要或轻量统计区，不能塞进 tab 按钮。
- 多 Tab 页面必须按 Tab 类型选择宽度策略：
  - 视角切换 Tab：数量少、语义稳定，使用内容自适应宽度或 segmented control；典型例子是能力映射的四个视角。
  - 视角切换 Tab 应采用紧凑 Apple segmented control：控件高度约 34-38px，单个按钮约 30-32px，active 为浅白胶囊和轻阴影，文字不做页面标题级加粗。
  - 视角切换 Tab 不能贴住区域外框；应与外框、内容区标题和主内容保持清晰间距，优先放在内容面板顶部内侧的自然起点。
  - 阶段序列 Tab：数量多、同一业务序列，使用组内等宽；宽度由当前组最长标签测算，外层横向滚动，不手写固定最大值。
  - 业务分类 Tab：名称长度差异大时使用内容自适应宽度，优先完整显示名称；不得为了等宽牺牲识别。
  - 过滤 / 筛选 chip：不是主导航 Tab，不和 Tab 混排。
- LC-AP / LC-DT 阶段 tab 是阶段导航，不能被通用 tab 样式改成过高胶囊或重叠文字。
- LC-AP / LC-DT 阶段导航必须为阶段标题、阶段编码、箭头和右侧搜索框建立明确布局边界；窄屏允许横向滚动，但单个阶段按钮不得被裁切。
- 阶段 tab 遇到空间不足时，按钮仍保持组内测算等宽，外层用横向滚动和右侧安全留白承载溢出；不能压缩到截断主名称，也不能让搜索框覆盖最后一个阶段按钮。
- LC-AP / LC-DT 阶段 tab 当前不使用箭头图标；按钮文本由阶段名称和阶段编码构成，允许统一宽度以保持横向扫描节奏，但该宽度必须按当前阶段组最长标题 / 编码测算，不得手写固定最大值。
- 阶段 tab 必须保留轻微 hover / click / active 动效，不能因为局部覆盖变成静态按钮。
- 阶段 tab 的 active 外框、底部选中线和 focus ring 必须属于同一语义色系，避免用户误判为两种状态。
- 能力映射视角必须使用既定命名：`能力关系图谱`、`技术视角`、`管理视角`、`标准 / 框架映射`。
- 不再使用未经确认的“技术路径”“管理路径”等替代名。
- active 状态使用 Apple blue 或对应语义色，hover 只能轻微提示，不能像选中态。

### 3.5 表格展示

涉及组件：

- `FocusScopeServiceMatrix.js`
- `FocusManagementMapping.js`
- `CapabilityLocalRelationMap.js`
- `EnvironmentScopeServiceMatrix.js`
- `ApplicationSecurityLifecycle.js`
- `ApplicationSystemDirectoryTable.js`
- `TechnicalServiceMaintenanceTable.js`
- `TechnologyModuleMaintenanceTable.js`
- `TechnicalMeasureMaintenanceTable.js`
- `WorkFunctionMaintenanceTable.js`
- `ProcessMaintenanceTable.js`
- `ScopeMaintenanceTable.js`
- `StandardFrameworkTable.js`
- `StandardRoleReferenceTable.js`
- `LcapReferenceMaintenanceTable.js`
- `TechnicalMeasureMaintenance.js`
- `app.js` 内 dashboard 表格、内容列表

展示类型：

- 普通数据表
- 关系矩阵表
- 语义映射表
- 原始映射矩阵
- 预览映射表
- 维护清单表
- 标准 / 框架分组表
- 树形分组表
- 生命周期阶段表
- 安全系统目录表
- dashboard 汇总表
- 内容资源列表
- 折叠分组行
- 明细行
- 空表格
- 横向滚动表格

通用约束：

- 表格是当前产品的核心展示类型，必须比卡片更优先。
- 表头使用低噪声浅色背景，文字权重清晰，但不要厚重色块。
- 普通业务列左对齐；数字、数量、短状态可居中；操作列靠右或居中。
- 不允许因为容器窄把中文表头压成竖排，必要时使用 `min-width` 和横向滚动。
- 单元格默认展示业务字段，不展示派生解释字段、调试字段或来源原始字段。
- 长表格和关系矩阵必须有自适应滚动体：表格滚动区跟随父容器尺寸变化，表头 sticky，纵向和横向滚动都在表体内完成。
- 禁止用固定 `min-height`、`max-height: calc(100vh - 固定值)` 或一次性窗口估算来控制矩阵高度；这些规则在顶部栏、页面标题、搜索区或 tab 区换行时会裁掉数据。
- 需要横向滚动的宽表，应保证列宽、`min-width: 0`、`max-width: 100%` 和 `overflow-x: auto` 同时成立；不能让 chip / badge / 长文本把相邻列挤出可视区。
- 表体滚动区应保留稳定滚动条空间，例如 `scrollbar-gutter: stable` 或等价策略，避免内容被滚动条遮住。
- 表格中的业务级 `参考来源` 是允许展示的辅助业务字段，但必须统一为“标签 + 浅色圆角引用框”：标签固定使用 `参考来源`，引用内容放在一个低噪声盒子里。
- `参考来源` 不做 chip、不做状态 badge、不做按钮；多条来源合并到同一个引用框，避免一格里堆叠多个胶囊。
- `参考来源` 只展示用户可读的业务引用，例如标准条款、文件级业务引用、数据库表或字段级业务引用；不得把 `sheet`、`row`、`source_file`、`raw_value` 等原始追溯字段作为表格来源展示。
- 空值统一使用轻量空状态，例如 `/` 或 `待补充`，不能用大块空卡占据表格列。
- 表格 hover 只能轻微变亮；selected 行才允许更明确背景。
- 表格内 chip 不得撑破行高；一行对象过多时使用数量收敛或详情区承载。
- 表格内 chip、badge、按钮必须受单元格边界约束，不能跨列、遮挡分隔线或覆盖相邻单元格。
- 长对象名必须在本列内省略、换行或通过详情区承载；不能通过强制 `nowrap` 或固定宽度把相邻列挤压变形。
- 密集矩阵表中关系对象必须有可收缩文本容器，主体文本可省略，类型前缀和语义色保持稳定。
- 矩阵表中的关系对象默认不可点击；除非有明确业务详情页或用户确认的跳转目标，不得让安全技术服务、模块、措施等 chip 触发能力选择或页面切换。

特殊表格约束：

- 知识库字典类表格必须统一 Apple / Morandi 表头、边框、hover、空值、chip 和分组行样式。
- 安全标准 / 框架表格必须保留标准类型语义色，但色彩只能作为轻提示，不做强背景墙。
- 生命周期阶段表格的阶段导航和数据表必须分离，不能把 tab 样式套进表格行。
- 环境映射表存在 5 列和 3 列两类列宽规则，后续不得用单一表格规则覆盖。
- 能力映射表格必须和图谱使用同一 ViewModel 投影，只允许展示形式不同，不允许出现数据口径不同。

### 3.6 文本层级展示

展示类型：

- 全局页面标题
- 工作台标题
- 面板标题
- 分组标题
- 表格表头
- 表格正文
- 描述文本
- 空状态标题
- 空状态说明
- 辅助说明
- 元信息
- 对象编码
- 按钮文字
- tab 文字
- chip 文字
- 图谱节点文字
- 证据折叠标题

约束：

- 全局页面标题用于页面定位，不进入卡片墙式放大。
- 工作台标题服务当前任务，字号应小于页面标题，高于表格表头。
- 表格正文优先可读，中文正文不低于 `12.5px`，常规建议 `13px` 至 `14px`。
- 目录二级项不低于 `14px`，避免知识库字典目录变成脚注。
- 元信息、数量、状态说明可更小，但不得作为主要字段承载业务名称。
- 对象名称优先于编码；标题中使用“名称为主，编码为辅”，表格中使用“编码 + 名称”或分行显示。
- 不使用负 letter spacing，不用 viewport 字号。
- 英文导航、阶段名、chip、表格正文的常规字重应保持清爽，避免 heavy / black 风格；英文对象名如 `Hype Cycle` 不得因局部强调变成过重展示。

字符规则：

- `import_id`
- `source_id`
- `source_ref`
- `source_label`

### 3.8 Chip、Badge 和状态标签展示

涉及：

- `displayLabels.js`
- `StatusBadge.js`
- 所有 `relation-chip`
- `type-pill`
- `missing-pill`
- `exception-pill`
- `preview-status`
- `count-pill`
- `filter-chip`
- `shell-tag`

展示类型：

- 关系对象 chip
- 类型 chip
- 状态 badge
- 缺失状态 pill
- 异常状态 pill
- 数量角标
- 页面标签
- 筛选 chip
- 标准 / 框架语义标签

约束：

- 关系对象 chip 必须优先使用 `display.relationChip` 或 `display.relationChipList`。
- chip 颜色按语义对象，而不是按所在页面随意变化。
- 安全技术服务使用 muted blue。
- 安全技术模块使用 sage。
- 安全技术措施使用 clay 或低饱和暖色。
- 能力关注点 / 当前对象使用 muted lavender。
- 标准 / 框架使用 sand。
- 环境和弱结构对象使用 blue-gray / slate。
- 安全技术服务、模块、措施、管理对象、标准 / 框架在能力映射、环境映射、LC-AP / LC-DT、知识库字典维护和安全标准 / 框架页面中必须使用同一语义色。
- 关系对象 chip 的主体文本必须有独立可收缩容器，例如 `relation-chip-text`；长文本在 chip 内省略，不能越过所在表格单元格或面板边界。
- 类型前缀可以固定展示，主体对象名称可以省略；不得为了完整展示长名称破坏表格列宽。
- 关系对象 chip 默认是静态标签，不是按钮；可点击 chip 必须有显式视觉 affordance 和明确目标，不能复用父行的能力选择行为。
- chip 不承载长段说明；长说明应放在正文或详情区。
- 空值不得做成 chip，避免把缺失数据伪装成对象。

- 环境拓扑关系图

- 连线

- 图例
- zoom 控制
- hover 节点关联线

约束：

- 图谱是同一数据投影的视图形式，表格是分 tab 的表格式展示，两者数据源必须一致。
- 当前能力 / 关注点是唯一中心锚点，显示名称即可；不额外堆叠摘要统计。
- 没有真实数据的业务节点不显示，不用空节点撑场面。
- 视角命名使用 `技术视角`、`管理视角`、`标准 / 框架映射`。
- 技术视角按 `作用域 -> 安全技术服务` 展开；没有真实模块 / 措施映射时不在主图伪造。

- 标准 / 框架映射无数据时显示可信空状态，不伪造控制项。
- 连线必须低噪声、方向明确；节点文本只显示业务对象名或必要编码。
- 图谱颜色按语义角色，不按层级随意换色。
- ArchiMate / SAPD 元素图例必须按 notation registry 受控渲染，不得由页面临时手写自由图形；图标中的中英文标题必须使用统一字号、行高、最大宽度和基线规则。当前图标 label rule：中文标题默认 `15px / 820 / 16.5px line-height`，英文基准名默认 `8.8px / 680 / 9.8px line-height`；不得按单个元素自由降字号，长中文优先换行并使用最大宽度约束防止出框。
- 未登记到 notation registry 的 draw.io 图形只能显示为 `待映射 / 非标准图例`，不得冒充标准 ArchiMate 3.2 元素。
- 不在图谱里显示 raw 字段、来源字段或调试字段。

## 4. 页面级执行约束

### 4.1 安全能力映射

- 目录：对象树和关注点目录必须清晰，当前选择对象和图谱中心必须一致。
- 图谱：能力关系图谱是总体展示，技术视角、管理视角、标准 / 框架映射是 tab 内表格或局部关系展示。
- 技术表格：只展示真实技术映射字段，当前真实主链路为 `作用域`、`安全技术服务`。
- 管理表格：展示 `安全工作`、`安全职能`、`L2 流程组`、`L3 流程`、`L4 活动`。
- 标准 / 框架：无直接映射时显示可信空状态，不伪造。

### 4.2 信息化环境安全能力映射

- 环境目录、分段、对象和关系表不得共用能力映射的列宽规则。
- 5 列环境表和 3 列环境表必须保持各自列宽与滚动策略。
- 环境对象、系统、模块、服务等 chip 使用环境语义色，不随页面主色漂移。

### 4.3 LC-AP / LC-DT 生命周期

- 阶段导航保持阶段式横向结构，不使用通用大胶囊 tab。
- 阶段名称、编码和箭头必须不重叠。
- 关系表、策略表、参考表使用表格规则，不做卡片堆叠。

### 4.4 知识库字典维护

- 安全能力作用域目录、安全技术服务清单、安全技术模块 / 措施清单、安全管理工作 / 流程清单、应用系统目录、安全职能清单、Hype Cycle、其他知识目录必须统一表格基线。
- 分组行默认收敛策略不能被视觉调整改坏。
- 模块 / 措施 / 服务对象名称优先，关联对象以 chip 辅助。

### 4.5 安全标准 / 框架

- NIST、ISO、CIS、MLPS、CSF 等标准表格必须使用统一表格系统。
- 标准类型可以有语义 tint，但表格头、边框、hover 和正文密度必须一致。
- 条款 / 控制项 / 参考要求不得被图标、chip 或色块压过。

## 5. 后续工程执行清单

任何修改 `frontend/capability-browser/` 的任务，开工前必须完成：

1. 读取 `DESIGN.md`。
2. 查看或至少对照 `apple-morandi-color-demo.html`。
3. 判断本次修改涉及本文哪一类展示类型。
4. 确认是否触碰字段边界、数据投影或 ViewModel。

实现时必须遵守：

1. 不用一次性颜色、一次性字号、一次性边框。
2. 不用宽泛选择器误伤其他展示类型。
3. 不把图谱、tab、表格、目录混用同一套尺寸规则。
4. 不新增未经确认的业务字段。
5. 不展示原始字段、调试字段、派生解释字段。

完成后必须验证：

1. `git diff --check`
2. 如改 JS，执行相关 `node --check`
3. 如改数据边界相关展示，执行 `python3 scripts/check_github_data_boundary.py`
4. 如改前端页面，执行相关 `node scripts/frontend_smoke_check.mjs --page <page>`
5. 视觉改动较大时输出 1440px / 1920px 截图或用浏览器确认
6. 如果 `localhost` 沙箱不可访问，按项目规则使用已批准的轻量验证路径，不默认启动系统 Chrome

## 6. 禁止事项

- 不把当前页面改成营销官网风。
- 不用大面积 hero 区、大 KPI 卡墙或重渐变背景承载业务工作台。
- 不把所有展示都改成卡片墙。
- 不把表格列压成竖排字。
- 不把 tab 改成挤压标题的高胶囊。
- 不在主展示区展示来源原始字段或调试字段。
- 不伪造标准 / 框架映射、模块 / 措施映射、成熟度或证据数。
- 不让同一数据投影在图谱和表格中展示不同对象。
- 不因为配色任务改动数据读取、ViewModel 业务逻辑、ETL、数据库或导出 JSON。

## 7. 验收口径

后续前端任务只有同时满足以下条件，才算符合本文：

1. 展示类型归属明确。
2. 字体层级、表格密度、chip、tab、图谱、目录与 Apple / Morandi demo 一致。
3. 主展示区没有非业务字段泄露。
4. 业务对象命名稳定，不新增未确认名词。
5. 表格和图谱使用同一数据口径，只是展示形式不同。
6. 1440px 下不拥挤、不竖排、不重叠。
7. 1920px 下能舒展，但不出现无效空白。
8. 现有页面入口、切换、数据读取不失效。
9. 必要的 `node --check`、smoke、数据边界和 `git diff --check` 已执行并记录。
