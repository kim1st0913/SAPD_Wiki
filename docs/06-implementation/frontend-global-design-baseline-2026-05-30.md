# SAPD Wiki 前端全局设计基线

日期：2026-05-30

适用范围：`frontend/capability-browser/` 当前正式前端、后续新增页面、后续重构页面、所有知识库字典 / 标准 / 框架 / 能力映射 / 环境映射 / 生命周期页面。

## 1. 结论

用户不需要再写复杂提示词。后续只要表达：

```text
按全局设计基线统一这个页面。
```

或：

```text
这个页面像 Apple demo 一样整理。
```

Codex 就必须自动执行以下动作：

1. 读取 `DESIGN.md`。
2. 读取本文。
3. 读取 `docs/06-implementation/frontend-display-design-principles-2026-05-30.md`。
4. 对照 `frontend/capability-browser/environment-object-apple-shell-demo.html#color-system`。
5. 判断当前页面涉及哪些展示类型。
6. 使用 scoped 样式和组件级修正统一页面。
7. 验证不破坏其他页面。

这件事以后是 Codex 的责任，不是用户的提示词负担。

## 2. 单一视觉方向

SAPD Wiki 的正式前端视觉方向为：

```text
Apple shell + restrained Morandi + 专业安全架构工作台
```

含义：

- 像 macOS / iOS 工具界面一样清晰、轻、稳定。
- 使用明亮 tinted neutral 背景，不使用纯白和纯黑。
- 使用 Apple blue 作为主选中态，不到处铺蓝色。
- 使用低饱和 Morandi 语义色区分对象类型。
- 优先服务表格、矩阵、目录、图谱和关系审阅。
- 不做营销官网、卡片墙、装饰 dashboard 或泛 AI 风。

## 3. 全局设计基线

### 3.1 背景与容器

- 页面背景使用浅 tinted neutral，不使用纯白大平面。
- 应用壳、侧边栏、顶部栏、主内容区必须像一个系统，不像旧页面被塞进新壳。
- 主工作区使用低噪声边界、轻阴影、细边框。
- 不使用厚边框、重色块、强渐变、玻璃拟态。
- 不嵌套卡片。一个区域需要边界时，用 pane / section / table，而不是卡片套卡片。

### 3.2 颜色

全局颜色语义固定：

| 语义 | 颜色方向 | 用途 |
|---|---|---|
| 选中 / 当前 | Apple blue | 当前导航、当前 tab、当前选中行 |
| 当前能力 / 关注点 | muted lavender | 图谱中心、当前对象 |
| 技术视角 / 安全技术服务 | muted blue | 技术视角、服务对象 |
| 安全技术模块 | sage | 模块对象 |
| 安全技术措施 / 待补充 | clay | 措施对象或缺失提示 |
| 管理视角 / 安全职能 | sage green | 管理对象、职能、流程 |
| 标准 / 框架 | sand | 标准、条款、控制项 |
| 环境 / 弱结构 | blue-gray / slate | 信息化环境、系统、辅助结构 |
| 风险 / 异常 | muted amber / red | 仅用于异常，不用于装饰 |

禁止：

- 纯蓝、亮绿、荧光橙、紫蓝渐变。
- 每个页面临时定义一套颜色。
- 为了“好看”改变业务对象语义色。

### 3.3 字体与文字

- 使用系统字体。
- 中文业务名称优先清晰，不追求装饰。
- 页面标题紧凑，工作台标题更克制，表格正文必须可读。
- 二级目录不小于 `14px`。
- 表格正文建议 `13px` 左右，不得低到看不清。
- 表头可以比正文略强，但不能像大标题。
- 对象名称优先，编码辅助。
- 长名称省略或换行，但不得撑破布局。
- 英文标题、编码、对象名不得使用过粗字重；正常导航、表格和 chip 中英文建议控制在 `600-700`，避免 heavy / black 风格造成不清爽。
- 不使用负 letter spacing。
- 不使用 viewport 字号。
- ArchiMate / SAPD 元素图标内文字必须使用统一 label rule：中文标题在标准 draw.io `150×75` 或 `150×82.947` 图形中默认 `15px / 820 / 16.5px line-height`，英文基准名默认 `8.8px / 680 / 9.8px line-height`。不得因单个元素名称长短随意降字号；长中文优先按规则换行，并通过 SVG `textLength` / 最大宽度约束保持不出框。

### 3.4 表格

表格是 SAPD Wiki 的核心展示方式。

统一规则：

- 表头低噪声浅底。
- 表格线细、浅、稳定。
- 行 hover 轻微提示。
- selected 行才使用明确选中态。
- 空值 `/` 使用弱样式，不做 chip。
- 对象 chip 不得比正文更重。
- 表格必须保留横向可读，不能把中文压成竖排。
- 密集表格允许横向滚动，但不能遮住关键列。
- 分组行默认策略必须稳定，不能被颜色调整改坏。
- 表格单元格必须给内部对象建立收缩边界；chip、badge、按钮不得跨出单元格、遮挡相邻列或覆盖分隔线。
- 长对象名优先在本列内省略或分行；不得依赖继续放大 / 缩小字体来掩盖列宽和溢出问题。
- 横向滚动可以承载宽表，但列内内容不得因为 `nowrap`、固定宽度或缺少 `min-width: 0` 把相邻列挤压或覆盖。
- 长矩阵 / 长表格必须遵守滚动容器契约：外层工作台、pane、内容区、tab panel 和表格滚动体逐层传递 `min-height: 0` 与 `minmax(0, 1fr)` 剩余高度；表格滚动条必须跟随浏览器视口和父容器尺寸自适应。
- 禁止用 `100vh` / `100dvh` 减固定数值、历史固定 `min-height` 或硬编码高度来决定矩阵可视区；顶部栏、页面标题、搜索区、tab 区一旦换行，硬编码高度会导致下方数据被裁切。
- 工作台内部只能有一个明确的主滚动边界。对关系矩阵而言，优先让表体滚动，父容器负责裁剪和高度传递；不得让页面、pane、tab panel 和表体同时竞争纵向滚动。
- 长矩阵表头默认 sticky，表体纵向 / 横向滚动；滚动体必须保留 `scrollbar-gutter: stable` 或等价稳定策略，避免出现内容被滚动条遮挡或窗口尺寸变化后无法看到底部数据。
- 关联统计列必须“数量 + 清单”同时可达：`关联服务数`、`关联对象数`、`关联安全职能数`、映射数量等不得只显示裸数字，默认使用统一数字气泡或等价轻量控件显示数量，并在 hover / focus tooltip 中列出对应关联清单。
- 关联数量为 `0` 时也保留可达说明，tooltip 显示 `暂无关联...`；不得为了填满表格自建或推断不存在的关系。
- 如果某个关联统计没有可用清单来源，应先补齐 ViewModel / 数据契约中的清单字段，或移除该统计列；不得只保留不可核对的统计数字。
- 表格长文本采用“扫描优先、全文可达”的统一策略：
  - 编码 / 编号列使用固定窄列，默认单行展示，不为了长编码放大主表宽度。
  - 名称 / 标题列优先展示完整业务名称，可按内容自然换行到 1-2 行，但不得压缩成竖排。
  - 关键定义 / 描述字段必须完整换行展示，例如安全能力定义、关注点描述、工作任务描述、措施 / 模块定义；不得用单行或固定行数省略隐藏主业务信息。
  - 次要说明字段可使用 2 行受控展示，但完整长文本必须通过 `title`、选中详情、行内展开或详情面板可达；不得只保留省略号。
  - 分组行的说明文字只在对应层级展示，子行不得重复上一层定义。
- 矩阵里的安全技术服务、模块、措施等关系对象默认只是展示对象，不自动成为能力导航入口；只有业务上明确存在目标详情页时，才允许显示为可点击控件。

禁止：

- 把表格改成卡片墙。
- 使用强色表头。
- 使用厚边框网格。
- 每个表格单独写一套字体和 chip。
- 在表格主展示区暴露调试字段或来源字段。

### 3.5 Tab 与切换

统一规则：

- tab 是导航，不是装饰卡片。
- tab 只承载稳定视图名称，不承载统计、对象数量、KPI、状态摘要或当前筛选条件。
- active 状态清晰但轻。
- 高度、间距、underline、文字大小统一。
- 不允许文字重叠。
- 不允许胶囊过大压缩内容。
- 多 Tab 场景必须先判断 Tab 类型再定布局，不允许所有 Tab 共用一种宽度策略：
  - 视角切换类 Tab，例如 `能力关系图谱 / 技术视角 / 管理视角 / 标准 / 框架映射`，数量少、语义稳定，使用内容自适应宽度或分段控件，不放统计。
  - 视角切换类分段控件必须轻：容器使用低噪声灰底，active 使用浅白胶囊和轻阴影，按钮高度和文字权重不得接近页面标题。
  - 阶段序列类 Tab，例如 LC-AP / LC-DT 阶段，数量多、结构同类，使用组内等宽；等宽值由当前组最长阶段名称 / 编码测算得出，外层横向滚动承载总宽度。
  - 长文本业务分类 Tab，如果名称差异很大，优先使用内容自适应宽度和横向滚动；不得为了整齐压缩到截断主名称。
  - 统计、数量、状态不进入 Tab；如需统计，放在 Tab 下方标题区、右侧摘要或表格摘要。
- LC-AP / LC-DT 阶段导航是特殊阶段控件，不套普通 tab 样式。
- LC-AP / LC-DT 阶段导航必须为阶段名称、编码、箭头和搜索框保留固定布局边界；窄屏可横向滚动，但单个阶段按钮不得被裁切。
- 阶段 tab 遇到空间不足时应保持组内测算等宽，由外层横向滚动承载溢出；不得把阶段按钮压缩到截断主名称，也不得让搜索框覆盖或切断最后一个阶段按钮。
- LC-AP / LC-DT 阶段 tab 不展示箭头图标；阶段按钮使用统一宽度，但统一宽度必须由当前阶段组中最长的阶段名称 / 编码测算得出，不得手写固定最大宽度；以“阶段名称 + 阶段编码”为核心内容，并保留轻微 hover / click / active 动效。
- 阶段 tab 的 active 外框、底部选中线、focus ring 必须使用同一语义色系，不允许上下两条线看起来像不同状态。
- 统计信息应放在页面标题区、内容区标题右侧或独立摘要区，不能塞进 tab / segmented control。

### 3.5A Frontend Lazy Data Contract Baseline 1.0

适用范围：所有索引先行、分片按需加载、跨包补关系的前端页面，当前优先覆盖 `知识库字典` 与 `安全标准 / 框架`。

全局规则：

- 每个页面必须显式声明加载契约，至少区分 `required` 和 `supplemental`：
  - `required`：不加载就不能显示主表 / 主视图。
  - `supplemental`：主表可先显示，但关系气泡、反向映射、详情补充、排序补充或来源补充依赖它。
- ViewModel 不得读取未声明的数据分片或跨包数据；若 ViewModel 读取 `security_processes`、`gartner_roles`、`work_function_layers`、`security_technical_measures`、标准 / 框架 tab rows 等字段，对应页面契约必须声明对应分片或表。
- 组件只负责渲染和发出交互事件，不得直接调用 `dataClient` 获取业务数据；业务数据加载统一由 `app.js` 或等价 loader 管理。
- `required` 数据缺失时显示主 loading；`supplemental` 数据缺失时显示 partial 状态或后台补全，不得让整页长期卡在 loading。
- 补充分片未加载完成前，不得把未知关系显示成真实 `0`；应使用 `加载中`、`待加载`、空态说明或等价 partial 表达，待数据完成后再显示真实数量。
- 任意属于当前页面契约的分片、包或标准 / 框架 tab 加载完成后，都必须触发当前页重新渲染，并保持当前搜索、当前 tab 和当前选中行状态。
- 多 tab 标准 / 框架页面必须有 `activeStandardTableId` 或等价状态；tab 切换只改变状态，由统一 loader 负责加载目标表，不在表格组件内部取数。
- 大型 tab 不默认全量预取；例如 `DSP Secure Controls Framework (SCF) - 2026` 的两个 1468 行 tab 只在首次进入或切换到目标 tab 时加载。小型补充 tab 可以按 idle / supplemental 策略后台预取。

验收规则：

- 必须覆盖首次直接进入、左侧导航切入、当前页刷新、搜索后补充分片返回、tab 切换、加载失败不整页卡死。
- 轻量 HTTP smoke 只能证明 route 可访问，不能单独证明前端 JS 冷启动后主表和补充关系已渲染；关键变更必须增加本地逻辑断言或 DOM / 浏览器验证。
- 新增或修改索引 / 分片页面后，必须运行 `node scripts/audit_frontend_lazy_load_contract.mjs`，并确保结果为 `pass`。

能力映射固定 tab 名称：

- `能力关系图谱`
- `技术视角`
- `管理视角`
- `标准 / 框架映射`

禁止：

- 使用“技术路径”“管理路径”等未经确认的替代名。
- 用全局 tab CSS 误伤生命周期阶段导航。

### 3.5B Route / Refresh State Baseline 1.0

适用范围：所有左侧全局导航、二级导航、页面内 tab、分段控件和可直接访问的 route。

全局规则：

- 直接输入固定根地址 `http://127.0.0.1:5173/` 时默认进入首页。
- 当前 URL 中存在显式 route 时，例如 `#/guides/security-architecture-modeling-language` 或等价路径，页面刷新必须保留当前页面，不得回退到首页、上次缓存页面或默认二级页。
- 页面内 tab / segmented control 如果代表用户当前阅读位置，必须进入可恢复状态；刷新、补充分片返回或当前页重渲染后不得重置到默认 tab。
- `localStorage` 只能恢复与当前显式 route 一致的页内状态；不能用上次保存的 route 覆盖用户当前输入的 URL。
- 左侧导航切换、二级导航切换、浏览器前进 / 后退、刷新必须走同一 route normalization 规则。

验收规则：

- 必须覆盖直接输入 `/`、直接进入具体 route、当前 route 刷新、页面内 tab 刷新、浏览器前进 / 后退。
- 修复根路径默认首页时，不得破坏“当前页刷新保留当前页”的基线。

### 3.5C Apple Shell 浮层 / 搜索 / 批注基线 1.0

适用范围：右侧浮层批注抽屉、全局搜索框、页面标题区搜索框、表格行 / 字段选中和后续工作台浮层。

批注模块的详细需求、页面级验收矩阵和关闭条件以 `docs/06-implementation/global-annotation-requirements-and-regression-matrix.md` 为准。本文保留全局视觉原则；具体到批注颜色、常驻态、定位态、抽屉行为、遮挡收起和逐页回归，不得绕过该需求文档。

2026-06-05 `OI-128C` 基本验收通过后，当前批注设计已固化为全局基线。后续新增页面、重构页面或新增复杂组件时，不重新设计批注样式和定位逻辑，必须按该需求矩阵的“新页面接入清单”声明页面对象、值锚点、行锚点、幻灯片 / 子页上下文和回归命令。

全局批注契约适用范围：`安全能力映射`、`信息化环境安全能力映射`、`LC-AP安全开发生命周期`、`LC-DT数据生命周期安全`、`知识库字典`、`安全标准 / 框架`、`安全指南` 和后续工作台页面。批注不是单页功能，任何页面只要展示可审阅业务值，都必须接入同一套锚点、悬停提示、定位和高亮规则。

统一规则：

- 右侧浮层必须悬浮在表格、矩阵和指南内容上层，不改变主工作区列宽、表格宽度或矩阵布局。
- 浮层打开 / 收起只改变自身 `transform`，动画控制在 `180ms` 到 `260ms`，并支持 `prefers-reduced-motion`。
- 批注浮层参考 Office Word 批注栏的阅读方式：固定宽度，作为右侧评论栏浮在页面上方；不得被长标题、长编码或长批注撑宽。长标题和长编码必须单行截断，并通过 Apple shell 风格的自定义悬停气泡展示完整文本；原生 `title` 只能作为兼容兜底，不作为唯一验收方式。
- 浮层内容不得重复页面标题、对象标题和自动标签。头部只保留当前页数量、功能标题和一个紧凑锚点栏；详细上下文进入折叠区或工作台详情。
- 批注抽屉默认只显示“当前上下文批注”一个清单。当前上下文可以是页面、对象、表格行或字段；不得同时展示两个空列表占位。
- 批注标签数量只统计当前页面批注，不统计全局所有页面。
- 抽屉内的“添加批注”默认用于当前页面或当前选中锚点；页面整体批注可以直接在抽屉内写入，行 / 字段 / 值批注必须先通过表格行、关系 chip、字段值的右键菜单或等价选中入口建立锚点。
- 所有可做值级批注的页面组件必须显式声明值锚点，统一使用 `data-annotation-value="true"` 和 `data-copy-text`。批注模块只能通过统一值锚点选择器识别字段 / 值，不得因页面私有 class 缺失而自动退化成行批注。
- 共享关系 chip（`display.relationChip` / `relationChipList`）必须默认输出同一值级锚点属性。页面局部组件只负责为不走共享 chip 的纯文本字段补锚点，不得再让批注模块维护页面私有 class 白名单。
- 普通表格单元格也必须有值级兜底：当 `td` 中没有共享 chip 或显式 `data-annotation-value`，且单元格文本不是 `/`、`暂无`、`待补充` 时，右键批注应创建字段 / 值锚点，而不是退化为整行批注。表头 `th` 不作为业务值兜底。
- 知识库字典、安全标准 / 框架、生命周期和指南页面的折叠目录必须支持批注定位恢复：点击批注项时，系统应先恢复 route、子页面、tab、对象或幻灯片状态，再自动展开目标所在父级分组，最后滚动到具体值 / 行。不得因为父级分组收起就判定定位失败。
- 当前页批注清单必须显示当前页所有批注，并在每条批注上标明锚点类型与锚点标题，例如 `页面`、`对象`、`行`、`值`。不得只显示当前对象批注而隐藏同页其他批注。
- 批注卡片默认折叠，折叠摘要依次显示状态、批注序号、锚点类型小圆标签和锚点值；展开后显示正文、状态下拉和操作。卡片不得显示无业务意义的头像或“本地用户”占位。
- 批注卡片操作顺序为 `定位 / 编辑 / 删除`；已有状态下拉时，不再额外重复状态按钮；点击 `编辑`、保存编辑、取消编辑或修改状态后必须保持当前抽屉滚动位置和当前卡片展开状态，不得跳回顶部或自动收起批注。
- 已保存的行 / 字段 / 值批注必须在原始页面锚点上可见，采用类似 Office Word 批注的“文字级批注墨水”而不是整块荧光底色。常驻状态保留对象自身语义色，优先在文字 / chip 内部铺一层自适应暖色底色，随文字换行而不是铺满单元格或整行；点击定位状态使用低噪声 Apple blue 焦点扫光 / 柔和发光动画，明确提示当前定位目标。不使用粗边框、强紫色描边、整块黄色区域、横向背景条或角标。页面级批注只进入抽屉清单和右侧标签提示，不强行高亮整页。
- 点击抽屉内某条批注必须尝试定位到原始页面锚点；同页批注直接滚动到锚点，跨页或跨子页面批注先切换到对应页面、目录、tab、对象或幻灯片，再定位。若目标锚点落在右侧展开抽屉覆盖区域，定位前允许自动收起抽屉以露出数据。定位必须使用批注创建时的上下文锚点，不能只按同名值匹配第一个结果。定位高亮范围必须匹配批注锚点类型：`值 / 字段` 批注只高亮具体值本身，不得高亮整行或整片关系区域；`行` 批注才高亮整行；`单元格 / 区域` 批注后续按对应范围单独定义。页面级批注只定位页面顶部，不做锚点高亮，不使用强弹窗。
- 页面、对象、二级页面或 route 切换后，批注抽屉默认收起；如存在未保存草稿，必须先提供“保存并切换 / 放弃并切换 / 继续编辑”保护。
- 搜索框必须留在自己的布局区域内，设置 `min-width: 0`、`box-sizing: border-box` 和清晰的最大宽度；不得被统计区、右侧浮层或宽表格挤压到裁切。
- 能力映射页标题 / 统计 / 搜索区域必须保持工作台密度，默认控制在紧凑两行内；不得为了放大搜索框或统计卡片挤占下方矩阵、图谱和表格主工作区。
- 表格行选中态使用轻 Apple blue 背景和细边框，不使用强色块。字段级批注锚点应使用 hover / focus 轻提示，不在每个单元格常驻强按钮。
- 右键菜单使用低噪声浮层，不使用系统默认强样式，不阻塞主表格阅读；菜单只承载当前必要动作，例如 `添加批注`。
- 后续所有页面级搜索、右侧抽屉、批注入口和行 / 字段选中效果应优先抽象为共享组件规则，再做页面局部实现。
- 新页面上线前必须先通过 `node scripts/audit_user_annotation_contract.mjs`；如果页面已有用户保存批注或本轮改动触及批注视觉 / 定位 / 抽屉 / 锚点解析，还必须跑 `scripts/audit_saved_user_annotations.mjs` 的真实浏览器回归。

禁止：

- 在每个页面单独定义浮层宽度、搜索框样式或行选中样式。
- 用横向收藏 / 备注条替代右侧批注 / 工作台入口。
- 未保存批注草稿在页面切换后继续挂到新页面。
- 为自动页面标签、对象类型标签使用大量胶囊重复页面标题。

### 3.6 目录与树

统一规则：

- 一级导航负责全局定位。
- 二级导航负责模块入口，必须清晰可读。
- 页面内树目录负责对象选择。
- 一级导航的彩色图标底必须和前景图案形成清晰对比；图案不可被渐变底、选中态内层底或同色系低对比色吞掉。
- 一级导航主入口名称优先可读，同时不能过度挤压主工作区；桌面侧栏宽度以约 `246-258px` 为紧凑基准，字号和图标应随之收敛，长中文入口允许自然换行，不能通过持续加宽侧栏来解决截断。
- 当前选中态要明显，但不能大面积高饱和。
- 展开 / 收起必须保留原交互。
- 默认展开 / 收起策略不能因为视觉修改改变。
- 长名称必须省略或合理换行。

禁止：

- 二级目录变成脚注大小。
- 目录选中态和 hover 态混淆。
- 目录项高度被图标、chip 或临时 padding 撑坏。

### 3.7 Chip、Badge、状态

统一规则：

- chip 表示业务对象，不表示空值。
- badge 表示状态，不表示对象。
- 数量角标只承载数量，不抢主内容。
- chip 颜色按对象类型，不按页面喜好。
- 同一对象在不同页面颜色一致。
- 安全技术服务、模块、措施、管理对象、标准 / 框架在能力映射、环境映射、LC-AP / LC-DT、知识库字典和安全标准页面中必须使用同一语义色。
- 关系对象 chip / 胶囊不使用前置圆点、黑点或色点。对象类型通过类型前缀、语义色和列头表达，不再用装饰点表达。
- 关系清单列必须完整展示业务对象名称。不得把 `关联安全技术模块/措施`、`关联安全技术服务`、`关联流程` 等清单型关系隐藏成纯数量；可通过换行、紧凑 chip、分组标签和列宽控制密度。
- 关联统计列才使用数字气泡，例如 `关联服务数`、`关联对象数`、`关联安全职能数`、映射数量。数字气泡必须在 hover / focus tooltip 中提供对应清单。
- 类型前缀规则：关系对象 chip 默认保留对象类型前缀，例如 `安全技术服务 |`、`安全技术模块 |`、`安全技术措施 |`。尤其是同一单元格可能出现多类对象时，不得省略类型前缀。只有用户明确确认某个页面采用分组标签替代前缀时，才允许在该页面局部省略。
- 关系对象 chip 必须包含可收缩文本容器，主体名称不得被无故省略；类型前缀和对象类型颜色保持稳定。
- chip 必须受所在单元格、面板或列表边界约束，不能为了显示完整文本跨列、悬浮到相邻区域或改变表格列宽。
- 主关系矩阵、语义映射表和原始映射矩阵中的业务对象字段必须完整展示并可选择复制，尤其是安全职能、安全工作、流程、技术服务、模块 / 措施和标准条款；这些主审阅字段不能使用省略号截断，空间不足时通过换行、横向滚动和稳定列宽承载。
- `归属安全能力 / 关注点` 属于归属路径字段，不属于普通关系对象 chip。该字段必须使用低噪声归属路径块，分行展示 `安全能力` 与 `关注点`，完整换行、可选择复制，不使用绿色胶囊，不继承 `relation-chip` 的单行省略规则。
- 省略号只允许用于侧边导航、概览卡片、紧凑统计或非主审阅列表；若用于这些非主区域，必须保留 `title`、详情入口或复制文本来源。
- chip 只有在具有明确业务跳转目标时才能表现为链接或按钮；普通关系对象 chip 不承担页面导航，避免点击安全技术服务 / 模块误跳到能力图谱。

禁止：

- `/`、`暂无`、`待补充` 被渲染成对象 chip。
- 一个单元格里堆满无分组、无类型上下文的 chip 导致行高失控。
- 关系清单列只显示数量，不显示主业务对象名称。
- chip 内用黑点、色点、项目符号替代清晰的类型前缀。
- 状态 badge 使用过强颜色。

### 3.8 图谱

统一规则：

- 图谱用于总体关系展示。
- 表格用于分 tab 的结构化审阅。
- 图谱和表格必须使用同一数据投影，只是展示形式不同。
- 当前能力 / 关注点作为中心锚点时，只显示必要名称和编码。
- 没有真实数据的节点不显示。
- 线条低噪声，节点层级清楚。
- 颜色按语义角色，不按临时层级随意变化。

禁止：

- 伪造节点。
- 用空节点撑画面。
- 图谱里显示 raw / debug / 来源字段。
- 因视觉修改改变数据来源或 ViewModel 业务逻辑。

### 3.9 空状态与来源证据

统一规则：

- 空状态要说明为什么为空。
- 无直接映射时写清楚“当前数据包暂未提供直接映射”。
- 业务级 `参考来源` 可以作为表格单元格内的辅助信息展示，但必须使用统一结构：上方标签 `参考来源`，下方低噪声浅色圆角引用框。
- `参考来源` 引用框用于承载标准条款、文件级业务引用、数据库表或字段级业务引用等用户可读来源，不使用 chip、不使用强色块、不裸露为普通长文本。
- 同一单元格内有多条业务参考时合并到同一个引用框内，用中文分隔符串联，避免一格内堆叠多个胶囊。
- 业务级 `参考来源` 和原始来源证据必须区分：前者是业务可读引用，后者是导入、行列、原始文件等追溯证据。
- 来源证据默认折叠。
- 来源证据不挤压主表格、主图谱。
- 错误状态不展示技术堆栈。

禁止：

- 用假数据填空。
- 用大面积空卡占据主界面。
- 把 `sheet`、`row`、`source_file`、`raw_value` 等原始来源字段放入主表格。
- 把业务 `参考来源` 显示成裸文本、重边框胶囊、导航按钮或状态 badge。

### 3.10 主表字段新增确认规则

前端主展示区不得随意加入衍生字段、自建字段、维护字段或中间判断字段。即使这些字段已经存在于 ViewModel、数据包或组件临时对象中，也不能默认上主表。

必须先由用户明确确认后，才允许新增到主表的字段包括但不限于：

- 衍生状态：`状态`、`映射状态`、`定义状态`、`待补字段`、`待复核`、`待确认`。
- 自建统计：关联数量、缺失数量、中间计数、临时汇总。
- 维护判断：是否归入清单、是否来自目录、候选映射、匹配依据、校对结论。
- 来源追踪：来源文件、来源行列、导入批次、生成时间、原始值。

如果确实需要展示这类字段，优先放在详情面板、折叠维护视图或用户明确要求的校对视图中，不进入默认主表。新增前必须说明字段来源、业务用途、展示位置和是否属于原始业务字段。

### 3.11 知识库字典类层级目录基准

`安全能力清单` 是知识库字典、安全标准 / 框架下同类型层级目录页的全局设计基准。后续安全技术模块 / 措施、安全管理工作 / 流程、安全职能、标准 / 框架条款等页面，如果属于“层级目录 + 主业务定义 / 描述 + 可搜索展开”的结构，应优先复用安全能力清单的开发要求。

统一规则：

- 默认收起顶层分组，避免首次进入页面时主表被大段层级内容淹没。
- 搜索状态自动展开命中的层级路径，避免用户搜到结果但看不到位置。
- 层级行必须稳定区分 L0 / L1 / L2 / 明细对象，编码为辅助，业务名称为主。
- 关键定义 / 描述字段完整换行展示，不用单行或固定行数省略隐藏主业务信息。
- 非关键长说明可以收敛到详情区、行内展开或折叠说明，但全文必须可达。
- 主表只展示用户可理解的业务字段，不展示候选映射、维护状态、来源追踪、中间统计或调试字段。
- 同类型页面优先复用现有 table、description cell、empty state、chip、badge 和搜索展开逻辑，不为每个目录单独发明一套样式。

适用页面包括但不限于：

- 知识库字典：安全能力清单、技术模块 / 措施清单、管理工作 / 流程清单、安全职能清单。
- 安全标准 / 框架：标准分组、框架条款、控制项、条款关系等同类层级目录。

例外：

- 如果某页面是阶段序列、关系矩阵、图谱或纯参考表，而不是层级目录，不强行套用默认收起规则。
- 如果用户明确要求某个目录作为教学 / 演示页默认展开，应在任务文档中记录原因和影响范围。

## 4. 页面一致性要求

后续新页面和已完成页面都必须按本文统一。

### 4.1 新开发页面

新页面必须先套全局基线，再写业务细节：

1. 应用壳一致。
2. 页面标题一致。
3. tab 一致。
4. 表格一致。
5. 目录一致。
6. chip / badge 一致。
7. 空状态一致。
8. 字段边界一致。

### 4.2 已完成页面

已完成页面如果与基线不一致，应作为视觉债务处理。

优先级：

1. 表格可读性。
2. tab 不重叠。
3. 目录字号和层级。
4. chip / 空值口径。
5. 图谱语义色和布局稳定。
6. 详情 / 来源证据收敛。

### 4.3 局部修改

即使用户只说“这个地方像 demo 一样改”，Codex 也必须检查：

- 是否误伤同类 tab。
- 是否误伤同类表格。
- 是否误伤 LC-AP / LC-DT 特殊控件。
- 是否误伤环境映射 5 列 / 3 列列宽。
- 是否造成字段泄露。
- 是否改变数据投影。

## 5. 用户最简需求表达

用户以后可以只说：

```text
按全局设计基线统一这个页面。
```

或：

```text
这个页面参考 Apple demo 调整。
```

或：

```text
这里看起来不统一，按基线修。
```

或：

```text
表格 / tab / 目录 / 图谱 按全局基线整理。
```

Codex 必须自己补齐：

- 要读哪些文件。
- 涉及哪些展示类型。
- 哪些样式需要 scoped。
- 哪些页面需要回归。
- 哪些字段不能显示。
- 哪些验证必须执行。

## 6. Codex 后续执行协议

每次涉及前端视觉、展示或页面改动时，Codex 必须在执行前确认：

```text
本轮按全局设计基线执行。
涉及展示类型：[表格 / tab / 目录 / 图谱 / ...]
不会修改数据链路、ETL、数据库、导出 JSON。
```

实现时：

- 优先复用现有 token 和 class。
- 优先 scoped 到具体组件或页面。
- 不使用宽泛选择器批量覆盖。
- 不改变业务数据投影。
- 不引入新依赖。

完成时：

- 说明修改了哪些展示类型。
- 说明是否影响其他页面。
- 说明验证命令。
- 说明字段边界是否检查。

## 7. 验收标准

全局设计基线执行合格，必须满足：

1. 看起来属于同一个产品。
2. 与 Apple demo 的颜色、表格、tab、chip、目录方向一致。
3. 表格不竖排、不挤压、不重边框。
4. tab 不重叠、不变形。
5. tab 不显示统计、KPI 或对象数量。
6. 二级目录清晰可读。
7. 表格内 chip 不跨列、不遮挡、不把相邻列挤压变形。
8. LC-AP / LC-DT 阶段导航不裁切阶段按钮，搜索框位置稳定。
9. 安全技术服务、模块、措施等语义对象在不同页面颜色一致。
10. 图谱和表格数据口径一致。
11. 空值、缺失、待确认状态一致。
12. 主展示区无非业务字段泄露。
13. 1440px 可读。
14. 1920px 舒展。
15. 不破坏已有页面。
16. `git diff --check` 通过。
17. 前端页面修改后执行对应 smoke 或浏览器验证。
