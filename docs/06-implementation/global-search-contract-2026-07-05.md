# 全局搜索契约

日期：2026-07-05

关联问题：`OI-155`、`OI-175`、`OI-176`、`OI-149`、`OI-154`、`OI-144`、`OI-185`

本文是 SAPD Wiki 全局搜索的当前完整规则入口。后续用户给出的搜索词、截图或单条结果，默认按“问题样例”处理：先判断哪条全局搜索契约被破坏，再修同类问题和审计门禁。

## 1. 产品职责

全局搜索负责“跨知识域找到一个可点击定位的业务对象”。

全局搜索包括：

- 顶部全局搜索框。
- 轻量结果面板。
- 独立搜索结果页 `#/search?q=...`。
- 结果类型 / 知识域筛选。
- 点击结果后进入目标页面，并按 `targetRef`、目标对象 ID 或目标文本定位。

全局搜索不负责：

- 过滤当前能力树、环境树、标准表、字典清单或生命周期阶段。
- 代替页面内搜索做当前上下文筛选。
- 把一个页面内局部搜索失败的问题扩大成全量数据扫描。
- 在输入阶段加载完整 workbench、完整字典、完整标准详情包或环境全量包。

页面内搜索负责当前页面、当前表格、当前阶段或当前关系图内的筛选、展开、定位和空态。页面内搜索不得写入顶部全局搜索状态。

## 2. 权威源和对象粒度

全局搜索首选数据源是 `/api/v1/search-index`。前端 fallback 只作为 API 不可用或当前会话已加载数据的补充，不是新的权威源。

全局搜索对象粒度必须是可点击定位对象：

- 安全能力、关注点、能力关系对象。
- 信息化环境、环境子类、信息化对象、环境关系节点。
- LC-AP / LC-DT 阶段、活动、策略、服务、模块、措施等可定位单元。
- 知识库字典主对象。
- 标准 / 框架、标准表、标准控制项明细行。
- 指南、页面、工作台入口。

禁止把 DOM 文本、父级路径、最近选中对象、首个子节点或旧缓存行当成搜索结果对象。

## 3. 命中通道

全局搜索必须区分三类命中通道：

- `identity`：对象自身身份字段，包括 `code`、`title`、`name`、`targetText` 和受控 alias。
- `content`：对象正文说明字段，包括 `description`、`summary`、`definition`、标准控制项正文等。
- `context`：关系路径和展示上下文，包括父级能力、阶段、环境、作用域、关联服务路径等。

排序和结果队列遵守身份优先：

- 当同一查询已有 `identity` 命中时，`content` / `context` 弱命中不得进入主结果队列。
- 当查询更具体且没有身份命中时，`content` 命中可以进入主结果队列。
- `context` 只能解释“它挂在哪里”，不得单独驱动主命中。

## 4. 禁止推断

全局搜索不得用跨粒度关系制造主命中：

- 不得因为某模块挂在某服务下，就让服务关键词命中模块标题。
- 不得因为某对象所属父级能力、生命周期阶段、环境路径含关键词，就让子对象成为主结果。
- 不得因为安全系统、模块、措施与服务存在关系，就把服务词扩展成不同标题对象。
- 不得为了补命中而新增未经用户确认的业务别名。

关系路径可以显示在 subtitle / match context 中，但不能作为主命中依据。

## 5. 计数和展示窗口

全局搜索必须区分“全量命中计数”和“当前返回 / 展示窗口”。

- `/api/v1/search-index` 必须返回 `facets.total`、`facets.returned`、`facets.limit`、`facets.truncated` 和 `facets.categories`。
- `/api/v1/search-index` 必须支持 `limit`、`offset` 和受控 `category` 参数；`offset` 是结果页翻页窗口，不是新的匹配规则。
- API 返回的 `window.total`、`window.offset`、`window.returned` 用于说明当前结果窗口；`facets.categories` 仍用于全量分类计数。
- 搜索结果页顶部总数和分类 chip 必须使用 `facets` 的全量命中计数，不得用 `results.length` 冒充全量命中。
- 结果列表可以限量展示；列表为空或数量较少时，必须能从摘要看出是“无命中”还是“当前窗口已截断”。
- 顶部轻量面板使用较小展示窗口；独立搜索结果页按页请求结果窗口。单次请求窗口上限为 `120`，当前结果页每页请求 `20` 条。
- 短词和长词的计数差异必须可解释：例如 `人工` 可以比 `人工智能` 命中更多对象，但不应因为前 40 条队列被其他类型占用而让标准 / 框架 chip 看起来反而变少。

## 6. 结果页阅读形态

独立搜索结果页 `#/search?q=...` 是知识库定位页，不是无限滚动信息流。

- 结果页只改变呈现节奏，不改变搜索规则、排序、分类计数、索引来源或数据。
- 结果页按每页 `20` 条分页展示；翻页必须通过 `/api/v1/search-index` 的 `offset` 拉取对应结果窗口，不得只在前 `120` 条返回窗口中做客户端切片。
- 顶部查询框和分类 chip 必须作为 sticky 固定上下文栏保留在结果页视口内，用户滚动结果时仍能看到当前查询词和分类口径。
- 结果页顶部和底部都必须提供分页；顶部分页替代旧的说明文字，底部分页便于读到列表末尾后继续翻页。
- 分页必须支持页码跳转。总页数以当前分类的全量命中计数计算，而不是以当前已加载窗口计算。
- `上一页` / `下一页` 属于文字命令按钮，必须有稳定横向宽度和 `nowrap` 约束，不得继承 30px 图标按钮宽度。
- 分类切换必须回到第 `1` 页，避免用户在某分类第 `n` 页切到另一个分类后看到空白或错觉缺失。
- 当全量命中超过当前返回窗口时，分页区必须表达“已加载窗口”和“全量计数”的区别。
- 预览面板和结果页搜索请求必须使用独立加载状态、独立请求序号和独立结果窗口；顶部预览刷新不得取消或覆盖结果页请求。

## 7. 搜索记忆

全局搜索和页面内搜索可以记录搜索历史，但必须使用统一的自定义组件，不依赖浏览器原生 autocomplete。统一的是交互组件和保留策略，不是把所有搜索词塞进同一个历史桶。

规则：

- 顶部全局搜索框和搜索结果页搜索框共享 `global` 历史。
- 已经执行并完成加载的查询必须立即进入搜索历史，并刷新已打开的历史面板；不得只依赖输入防抖。
- 页面内搜索历史必须按业务域隔离：能力使用 `capability`，信息化环境使用 `environment`，LC-AP 使用 `lc-ap`，LC-DT 使用 `lc-dt`，知识库字典使用 `knowledge`，标准 / 框架使用 `standards`，工作台 Issue 使用 `workbench-issues`。
- 同一页面内的记录删除和清空只影响当前业务域，不得清空全局搜索，也不得影响其他局部页面。
- 工作台 Issue 搜索是 Review Queue 筛选，不是普通页面正文搜索；历史标题、placeholder 和清空行为必须表达为 Issue 筛选记录。
- 默认显示最近 `5` 条，最多保存 `10` 条。
- 当记录超过 `5` 条时，提供“显示全部 / 收起”。
- 必须提供清空全部记录和单条记录删除。
- 所有纳入统一历史组件的输入框必须设置 `autocomplete="off"`，避免某个页面单独弹出浏览器原生历史。
- 历史记录只影响输入建议，不改变搜索规则、排序、命中计数或数据来源。

## 8. 标准 / 框架明细

标准 / 框架页面局部搜索能命中的业务明细，必须进入全局搜索。

标准明细索引规则：

- 从 `standards-index` 的 `dataPath` 精确读取标准分片。
- 不调用全量 `standards` compat 包。
- 标准控制项结果使用 `standard_control` 粒度。
- 结果必须携带 `standardFramework`、`standardTableId`、`selectedMaintenanceId`。
- CRF / DSP 字段如 `Safeguard ID`、`SCF编号`、`保障措施描述`、`SCF控制项` 必须进入身份或内容检索。
- 同一标准控制项在 Core / Maturity 等多表重复出现时，全局结果队列必须做业务去重。
- 当多个标准框架同时命中时，单一框架不得垄断前序展示窗口。

## 9. 激活和定位

点击全局搜索结果后：

- 不得把全局搜索词写入目标页页面内搜索框。
- 必须优先使用显式对象 ID、`targetRef`、`selected*Id`、`standardFramework`、`standardTableId` 等定位字段。
- 对标准 / 框架结果，必须先切换到目标标准框架和标准表，再定位目标行或目标文本。
- 若显式对象不存在，应进入未定位空态或回退文本定位，不得自动展示第一条对象伪装成功。

## 10. 性能和字段边界

全局搜索输入阶段不得预加载完整业务包。

运行态搜索响应必须保持轻量，当前审计预算为常规查询响应小于 `800KB`。

搜索结果不得暴露以下非业务字段：

- `sheet`
- `row`
- `column`
- `raw_value`
- `source_file`
- `import_id`
- `source_id`
- `source_ref`
- `source_label`
- `debug`
- `raw`
- `metadata`
- `intermediate`
- `generated_at`

黄金样例：

- `人工智能`：必须命中标准 / 框架明细，且 CRF 与 DSP 均应可被发现。
- `人工`：总命中应不小于 `人工智能`，分类计数应来自 `facets`，不得被返回窗口污染。
- `组织`：总命中 `473` 这类大结果集时，结果页必须能跳到第 `101-120` 条和末页窗口；不得只显示前 `6` 页或下一页直接空态。
- `密码`：身份字段直接命中保留，弱正文 / 上下文命中被裁掉。
- `密码托管`、`密码策略`：具体正文短语仍可命中真实正文对象。
- `数据脱敏`：命中脱敏对象自身，不得仅因关系路径命中 `数据安全网关` 等不同标题对象。
- `应用页面水印`：命中 AP 服务自身及能力引用，不得串到 DI `数据内容水印`。
- `零信任访问控制台`：环境关系结果必须能定位到所属信息化对象。
