# Local MCP C1 前开发收口执行计划 v0.1

状态：已完成，待用户人工验证  
授权来源：用户确认“完成 C1 之前的所有开发”  
执行日期：2026-07-24

## 1. 目标

在不进入 C1 真实 Codex 客户端验证的前提下，完成稳定本机证书方案的 C0-4 至 C0-7 开发收口，使 Web 开发环境具备可恢复、可观察、可自动验证的证书与 MCP 生命周期。

## 2. 本批范围

- C0-4：CurrentUser 信任适配合同、精确指纹检查、冲突检测、快照与精确清理；自动化使用隔离 fake adapter，平台命令适配器只做可注入、默认禁止写入的实现与测试。
- C0-5：证书生成与轮换事务日志、同 profile 单写者、失败恢复、旧代保留与清理、升级兼容和重置闭环。
- C0-6：AI 功能集成页面和顶部状态补齐轮换、恢复、冲突、信任缺失、有效期与操作反馈。
- C0-7：生命周期、并发、失败恢复、重置、安全负向及前端合同自动化；在稳定 `5173` Web 环境完成验收。

## 3. 明确不在本批执行

- 不配置或连接真实 Codex 客户端，不进入 C1。
- 不写入真实 macOS Keychain/系统信任库或 Windows Certificate Store；真实 CurrentUser 信任实验需在执行前另行确认。
- 不生成 D0-Pilot 内容，不接入正式数据、用户数据或真实用户库。
- 不进行 App 集成、macOS/Windows 打包、签名、公证或安装包验证。
- 不 stage、commit、push 或创建 PR。

## 4. 完成门禁

1. 轮换任何中断点均可恢复到旧代可用或新代已验证状态，不留下无主信任。
2. 信任清理只允许按受管 CA 的完整 SHA-256 指纹执行；同名不同指纹必须阻断。
3. 未知 Schema、跨 profile、并发写者、秘密缺失和不安全文件必须失败关闭。
4. 重置只清理 MCP 受管证书、信任、秘密和授权，不触碰知识库、用户数据或 License。
5. 前端可用业务语言展示证书状态、剩余有效期、MCP 状态和 License 状态，且关键操作有确认及结果反馈。
6. MCP 自动化套件、前端合同审计、目标路由 DOM 验收和 `5173` Web 人工入口均通过。

## 5. 执行顺序

1. 完成受管证书 generation/stage/activate/remove 原语。
2. 完成信任适配合同、隔离快照与平台命令构造器。
3. 完成持久事务日志、单写者锁和轮换/恢复协调器。
4. 接入 Web Dev Supervisor 与 Control API。
5. 补齐前端展示和操作反馈。
6. 补齐 C0-7 自动化并运行完整验收。
