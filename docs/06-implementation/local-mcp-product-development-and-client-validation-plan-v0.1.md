## 1. 业务目标

先把用户可见功能和底层服务开发完整，再在用户本机验证真实连接，最后验证不同客户端版本和操作系统，避免在功能尚未成型时反复围绕单一客户端做零散实验。

完成后，用户应能从 SAPD Wiki 的“系统设置 → AI 集成”完成以下任务：

1. 看懂 MCP 当前是否启用、是否正常、是否已授权、最近是否使用；
2. 启动、停止、重试本地 MCP 服务；
3. 按引导连接 Codex，并查看或撤销已授权客户端；
4. 清楚知道 AI 可以读取和明确不能读取的数据；
5. 查看安全连接、授权、端口、知识状态和审计问题；
6. 在出现问题时获得一个明确的恢复动作；
7. 执行重置时知道会删除什么、保留什么。

## 8. D4：Web 版 AI 集成功能

### 8.1 页面与入口

1. 顶部设置按钮进入“系统设置”；
2. 设置一级导航包含“基础设置”和“AI 集成”；
3. 建议稳定路由为 `/settings/ai-integration`，最终名称在 P0 合同中冻结；
4. 启用后，顶部可以显示紧凑 AI 集成状态和直接恢复入口。

### 8.2 页面功能

页面按用户任务分成六个区域：

1. **服务状态**：启用、启动、停止、重试、运行状态、最近错误；
2. **连接 Codex**：客户端类型、分步引导、检查结果、服务 URL 次动作；
3. **授权客户端**：客户端身份、scope、授权时间、最近使用时间、逐个撤销；
4. **数据访问**：允许的数据类型和字段、明确排除的用户笔记与受限内容；
5. **隐私与审计**：状态、保留期、查看、导出、清除和关闭；
6. **诊断与重置**：端口、TLS、OAuth、策略、Runtime、脱敏日志和重置。

### 8.3 Web 边界

- Web 开发环境应能实际控制 synthetic-only 本地服务，而不是只展示静态原型；
- 浏览器不能直接操作 Keychain、DPAPI、系统证书库或其他客户端配置；
- 这些平台动作通过 Supervisor/Bridge 执行，纯浏览器环境显示明确的引导或“需要桌面应用”，不得伪装成功；
- Web 页面不读取原始 SQLite、控制面文件或系统路径。

### 8.4 设计与可访问性

- 复用现有 Apple Shell、共享按钮、状态 badge、表格、分页、空状态和焦点规则；
- 不新增营销式卡片墙或独立视觉体系；
- 状态不能只依赖颜色；
- 支持键盘、可见焦点、`aria-live`、200% 缩放和 reduced-motion；
- 桌面宽屏、紧凑宽度和 App WebView 均无横向溢出。

### 8.5 完成标准

- 从顶部设置入口可以完成完整业务路径；
- synthetic-only 环境下，启停、状态、客户端引导、撤销、审计和诊断可操作；
- 所有状态都有明确下一步，没有“看似已连接但实际未授权”；
- 路由恢复、刷新、错误恢复和无服务状态通过；
- 定向静态检查与 `5173` 浏览器/DOM 验收通过。

## 9. D5：macOS 与 Windows 控制桥接

### 9.1 macOS

1. App Supervisor 管理 Sidecar 生命周期；
2. Keychain 保存必要秘密；
3. TLS 信任安装、修复、轮换和删除必须逐次确认；
4. 关闭窗口但 App 驻留时，菜单栏可查看并停止 MCP；
5. 授权请求到达时可以恢复或置前确认界面。

### 9.2 Windows

1. Electron 主进程管理 Sidecar 生命周期；
2. 使用 Windows CurrentUser 范围的安全存储和证书能力；
3. 主窗口关闭退出时同步停止 Sidecar；
4. 端口、锁、进程残留和升级路径与 macOS 语义一致；
5. renderer 不直接获得秘密、系统路径写权限或任意进程控制能力。

### 9.3 完成标准

- Web 和 App 展示同一状态合同；
- 两平台敏感操作都需要明确用户确认；
- 启停、崩溃、重启、多开和重置行为可自动化验证；
- 本阶段可以用平台模拟器或隔离测试存储，不写真实客户端配置和系统信任。

3. preview/dev：记录兼容结论，不因未发布客户端缺陷强行降低安全边界。

### 12.2 每个矩阵项

1. 客户端发现和注册；
2. callback 端口、PKCE、resource、audience、scope；
3. initialize、tools/list、五项 tools/call；
4. refresh、撤销、重新授权；
5. 连接中断、客户端重启、App 重启；
6. 端口占用、多实例和版本回滚；
7. UI 状态、诊断和审计一致性；
8. 安装/卸载后的证书、凭据和配置残留。

### 12.3 完成标准

- 形成明确的“支持 / 有条件支持 / 不支持”矩阵；
- 当前主版本和目标 OS 全部通过；
- 失败项有责任归属、复现步骤和产品提示；
- 不通过 insecure fallback 扩大兼容范围；
- Windows 结果必须来自真实 Windows 环境，不能用 macOS 模拟代替。

## 15. 总体停止条件

出现以下任一情况，停止当前批次并报告，不自动扩大范围：

- 必须访问或创建用户库才能完成 MCP 功能；
- 必须使用 HTTP、长期明文 Token 或未加密私钥；
- Web 页面必须持有 OAuth Token、私钥或口令；
- 现有 dirty worktree 与目标文件发生不可安全隔离的重叠；
- 客户端只能通过降低 Host/Origin、resource/audience、PKCE 或策略校验连接；
- 真实数据或受限内容意外进入 synthetic 开发路径；
- Windows 结论只能通过推测或 macOS 模拟获得；
- 完成工作需要 push、打包或其他未批准的外部写入。
