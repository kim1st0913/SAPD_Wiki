## 关键问题

1. `安全能力作用域清单` 应以 `安全能力作用域目录` 为主数据源，但当前导出结果优先采用了 `安全能力-安全技术服务` 的同编码作用域标题和来源证据，导致：
   - `安全能力作用域目录!C4` 原值 `I-DI 数据与信息` 在页面数据包中显示为 `I-DI 数据`；
   - `安全能力作用域目录!C7` 原值 `I-OS 操作系统` 在页面数据包中显示为 `I-OS 操作系统（主机/终端）`；
   - 数据包多出 `ALL 全部作用域`；
   - 顺序不再跟随 `安全能力作用域目录` 原表。

2. `安全职能流程清单` 当前不只来自 `安全职能流程清单（完善L4）`，还混入 `安全能力-安全管理元素（high level）` 的流程参考。典型问题：
   - `安全能力-安全管理元素（high level）!H14` 原值 `身份、凭证与访问管理策略运营流程` 被拆为 `身份` 和 `凭证与访问管理策略运营流程`；
   - `攻防演练/沙盘推演流程`、`制品检测流程`、`威胁情报生产流程` 等只来自 high-level 映射表，不在流程清单原表中；
   - 当前 `process_activity_missing=85`，但原表 `L4关键活动` 列为空，这不是漏导入，而是源数据待补。

3. `安全技术措施目录` 当前 `maintenance-knowledge.json` 包含 32 条，其中 4 条来自 LC-AP / LC-DT 生命周期表，而不是 `作用域-安全技术服务-安全技术模块映射` 的灰色措施单元格：
   - `LC-DT 安全技术服务、模块、策略映射表!N69:N70`、`LC-DT 数据生命周期!I30`：`数据销毁`
   - `LC-AP 应用安全开发生命周期!R5`：`应用程序威胁建模`
   - `LC-AP 应用安全开发生命周期!R7`：`制品安全加固`
   - `LC-AP 应用安全开发生命周期!R8`：`IaC代码安全测试`
   这些对象没有安全知识措施目录所需的安全技术服务和作用域映射。

4. `应用系统目录` 条数完整，但系统类型和组件顺序不跟随 `LC-AP 应用安全开发生命周期元素目录` 原表：
   - 原表系统类型顺序为 `传统应用 -> 微服务应用 -> 中台类应用`，数据包为 `中台类应用 -> 传统应用 -> 微服务应用`；
   - `微服务应用` 原表组件顺序为 `网关层 -> 用户接入层 -> 应用服务层 -> 数据访问层 -> 数据存储层`，数据包改成标题排序；
   - `中台类应用` 原表组件顺序为 `服务层 -> 分析层 -> 管理层 -> 存储计算层 -> 接入层`，数据包改成标题排序。
