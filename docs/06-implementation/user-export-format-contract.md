# 用户导出格式契约

本文件固定 `OI-135` 后续导出能力的格式边界。导出实现必须先满足本契约，再进入前端入口或更多格式扩展。

## 1. 当前结论

- 已实现：最小 `JSON` 导出闭环，用于验证导出任务、下载接口、字段边界和临时 ZIP runtime。
- 用户已确认后续导出以原始业务数据口径为主：表格基本参考原始数据，优先提供 `Excel` / `CSV` / `Markdown`；幻灯片类交付提供 `PDF`。
- 第一批导出数据集不是泛化工作区，而是三个固定业务数据集：能力全量映射、信息化环境映射、字典和标准框架数据。
- 未完成本契约前，不直接实现前端导出中心、ZIP 组合包或可恢复备份。

## 2. 第一批业务导出数据集

第一批导出以“可复核、可二次处理、接近原始业务表”为目标，不先做复杂报告排版。

| 数据集 | 建议 `dataset_key` | 核心粒度 | 主要用途 | 首选格式 |
|---|---|---|---|---|
| 能力全量映射 | `capability_full_mapping` | 安全能力 / 安全关注点 | 复核能力到技术视角、管理视角、标准框架的全量映射 | `xlsx`、`csv`、`md` |
| 信息化环境安全映射 | `environment_technology_mapping` | 信息化环境 / 环境子类 / 信息化对象 | 复核环境对象对应的安全技术服务、安全技术模块 | `xlsx`、`csv`、`md` |
| 字典与标准框架 | `reference_dictionary_and_standards` | 字典项 / 标准框架 / 条款 / 控制项 | 交付基础参考数据、标准框架数据和术语字典 | `xlsx`、`csv`、`md` |
| 幻灯片导出 | `slide_pdf` | 幻灯片 / 页面 | 交付或归档幻灯片版材料 | `pdf` |

### 2.1 能力全量映射

该数据集以能力为核心，必须覆盖：

- 安全能力、能力分组、能力编码和能力说明。
- 安全关注点。
- 技术视角：作用域、安全技术服务、安全技术模块、安全技术措施。
- 管理视角：安全流程、安全活动、安全职能、管理工作。
- 标准视角：标准框架、条款、控制项、映射关系、映射说明。
- 来源摘要：只保留业务可理解来源，不输出内部行列和调试字段。

建议 Excel sheet：

| Sheet | 内容 |
|---|---|
| `能力总览` | 能力、关注点、分组、说明和统计 |
| `技术视角映射` | 能力 / 关注点到作用域、技术服务、技术模块、技术措施 |
| `管理视角映射` | 能力 / 关注点到流程、活动、职能、管理工作 |
| `标准映射` | 能力 / 关注点到标准框架、条款、控制项 |
| `来源摘要` | 业务来源说明和数据更新时间说明 |

CSV 对应拆成多个文件：`capability_overview.csv`、`capability_technical_mapping.csv`、`capability_management_mapping.csv`、`capability_standard_mapping.csv`。

Markdown 输出应偏向可读摘要：按能力 / 关注点分组列出技术、管理和标准映射，不替代表格明细。

### 2.5 幻灯片 PDF

幻灯片导出不应混入表格导出。它是文档交付格式，建议独立为：

- 单个幻灯片 deck 导出为一个 `PDF`。
- 多个 deck 导出时，先生成多个 PDF；是否合并为一个 PDF 后续单独确认。
- PDF 文件名必须体现主题、版本和导出日期。
- PDF 不承担结构化数据恢复，结构化数据仍以 Excel / CSV / JSON 为准。

## 3. 导出对象

导出对象不等同于页面截图，也不等同于原始数据库备份。V4 导出只面向以下业务对象：

| 对象 | `export_type` | 用途 |
|---|---|---|
| 业务数据集 | `business_dataset` | 导出上述固定业务数据集，例如能力全量映射、信息化环境映射、字典和标准框架 |
| 当前视图 | `current_view` | 导出当前页面筛选或当前业务视角结果 |
| 工作区 | `workspace` | 导出一个用户工作区的对象、备注、标签和用户整理结果 |
| 数据篮 | `data_basket` | 导出用户临时收集的一组对象，作为交付或复核素材 |
| 用户 overlay | `user_overlay` | 导出用户备注、标签、收藏、自定义对象和自定义关系 |
| 全量备份 | `full_backup` | 导出可迁移、可恢复的用户库备份包 |

## 4. 格式分层

| 格式 | 状态 | 主要读者 | 适合内容 | 不适合内容 |
|---|---|---|---|---|
| `JSON` | 已有最小闭环 / 待升级为正式 schema | 程序、迁移、后续导入 | 完整结构、嵌套关系、用户 overlay、恢复用数据 | 给业务人员直接阅读 |
| `CSV` | 待确认后实现 | 业务复核、Excel 二次处理 | 扁平清单、对象列表、关系列表、问题清单 | 复杂层级、富文本备注、多文件交付 |
| `Markdown` | 待确认后实现 | 人工阅读、报告草稿、Obsidian / 文档沉淀 | 标题层级、摘要、备注、来源说明、分组清单 | 大规模明细表、机器恢复 |
| `Excel` | 第一批重点格式 | 业务复核、正式表格交付 | 多 sheet 原始口径数据、筛选、人工二次处理 | 机器恢复、复杂嵌套结构 |
| `PDF` | 幻灯片交付格式 | 阅读、归档、汇报 | 幻灯片版材料、视觉交付件 | 结构化表格复核、机器导入 |
| `ZIP` | 待确认后实现 | 交付、备份、迁移 | 多文件组合、manifest、JSON + CSV + Markdown、用户库备份 | 单一清单快速查看 |

推荐实现顺序：

1. 先做第一批业务数据集的 `CSV`，因为最容易验证字段和行数。
2. 再做同口径 `Excel`，按 sheet 组织，尽量参考原始数据结构。
3. 再做 `Markdown` 摘要，用于阅读和文档沉淀。
4. 幻灯片类单独做 `PDF`。
5. 当前 `JSON` 升级为正式 `export_schema_version`，作为机器结构和后续 ZIP manifest 的基础。
6. 最后再做 `ZIP` 组合包。

## 5. 统一请求契约

`POST /api/v1/user/exports/preview` 和 `POST /api/v1/user/exports` 应逐步统一到以下字段：

```json
{
  "export_type": "business_dataset",
  "dataset_key": "capability_full_mapping",
  "format": "xlsx",
  "source_ref": "dataset:capability_full_mapping",
  "profile_id": "optional-profile-id",
  "options": {
    "include_business_summary": true,
    "include_source_summary": true,
    "include_mapping_notes": true
  }
}
```

约束：

- `export_type` 表示导出对象类型。
- `dataset_key` 只在 `export_type = business_dataset` 时必填。
- `format` 表示输出文件格式，不应混在 `export_type` 里。
- `source_ref` 只允许作为 API 请求入参和内部定位，不允许原样泄露到导出主展示内容。
- `profile_id` 是可选配置模板，不应覆盖本次请求中的显式选择。
- `options` 只控制导出呈现，不得触发数据库迁移、ETL 或基础数据重算。

## 6. Excel / CSV 字段原则

Excel / CSV 是第一批业务交付重点，字段原则如下：

- 尽量参考原始数据表口径、字段命名和业务顺序。
- 可以增加少量面向交付的整理字段，例如 `导出分组`、`映射说明`、`来源摘要`。
- 不输出内部 ETL 字段、数据库主键、调试字段和原始行列坐标。
- 多值关系优先拆成长表，不把大量对象挤在一个单元格中。
- Excel sheet 和 CSV 文件必须一一对应，方便从 Excel 退回 CSV 验证。

## 7. JSON 正式结构

当前 JSON 最小闭环后续应收敛到：

```json
{
  "export_schema_version": "user_export_1.0",
  "created_at": "ISO-8601",
  "export": {
    "id": "export-job-id",
    "type": "data_basket",
    "format": "json",
    "source": {
      "kind": "user_data_basket",
      "title": "数据篮名称"
    }
  },
  "manifest": {
    "object_count": 0,
    "relation_count": 0,
    "note_count": 0,
    "tag_count": 0,
    "field_boundary": {
      "forbidden_fields_removed": true
    }
  },
  "objects": [],
  "relations": [],
  "user_overlay": {
    "notes": [],
    "tags": [],
    "custom_items": [],
    "custom_relations": []
  }
}
```

字段约束：

- `created_at` 是导出文件元数据，可以保留；禁止字段列表中的 `generated_at` 不得出现。
- `source` 只能给业务可理解的 `kind`、`title`、`scope`，不得输出内部 `source_ref`、`source_id`、`source_label`。
- `objects` 不得塞入原始行列、原始 sheet 或 ETL 中间字段。

## 8. CSV 文件约定

`CSV` 不应只有一个文件。建议最小输出：

| 文件 | 内容 |
|---|---|
| `objects.csv` | 对象清单：对象类型、标题、编码、摘要、状态、所属分组 |
| `relations.csv` | 关系清单：源对象、关系类型、目标对象、说明 |
| `notes.csv` | 用户备注：对象标题、备注内容、锚点类型、创建时间 |
| `tags.csv` | 用户标签：对象标题、标签名 |

CSV 只保留业务列，不输出 `sheet`、`row`、`raw_value`、`source_ref` 等内部字段。

## 9. Markdown 文件约定

`Markdown` 用于人工阅读，建议最小结构：

```markdown
# 导出标题

## 摘要

## 对象清单

## 用户备注

## 关系说明

## 来源摘要
```

约束：

- 不写内部调试字段。
- 不把大量机器 JSON 直接塞进 Markdown。
- 来源摘要只写业务可理解的来源说明，不写内部 `source_ref`。

## 10. PDF 文件约定

`PDF` 当前只用于幻灯片导出，不用于替代表格数据。

约束：

- 输入应来自已确认的幻灯片页面或 deck。
- 输出以阅读和汇报为主，不要求可导入。
- PDF 文件应独立于 Excel / CSV / Markdown 表格导出。
- 后续若需要报告型 PDF，必须另行定义报告模板，不直接复用幻灯片 PDF 约定。

## 11. ZIP 包约定

`ZIP` 是交付 / 备份格式，建议结构：

```text
sapd-export-<type>-<date>.zip
├── manifest.json
├── data/
│   ├── export.json
│   ├── objects.csv
│   ├── relations.csv
│   ├── notes.csv
│   └── tags.csv
└── docs/
    └── summary.md
```

`manifest.json` 必须记录：

- `export_schema_version`
- `export_type`
- `formats`
- 文件清单
- 记录数摘要
- 字段边界检查结果

## 12. 禁止字段边界

所有导出格式都不得输出以下字段名：

```text
sheet
row
column
raw_value
source_file
import_id
source_id
source_ref
source_label
debug
raw
metadata
intermediate
generated_at
```

例外：

- `created_at`、`updated_at` 可作为用户记录或导出元数据保留。
- `source_summary` 可作为业务来源摘要保留，但不得暴露内部来源键。

## 13. 实现前确认清单

进入代码扩展前需要确认：

- 第一批是否按 `capability_full_mapping`、`environment_technology_mapping`、`reference_dictionary_and_standards` 三个数据集先做。
- Excel sheet 名称和 CSV 文件名是否采用本契约建议。
- 能力全量映射是否以“安全关注点”为最小行粒度，还是以“能力”为最小行粒度。
- 标准映射是否展开到控制项级，还是只到章节 / 条款级。
- Markdown 是否只做摘要，还是需要完整明细。
- 幻灯片 PDF 的输入范围是单个 deck、当前页面，还是多个幻灯片集合。

未确认前，后续实现只能继续完善当前 `JSON` 最小闭环的 schema 和测试，不应扩大到多格式输出。
