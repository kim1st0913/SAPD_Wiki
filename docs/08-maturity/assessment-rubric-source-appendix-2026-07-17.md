# SAPD 成熟度评估对象专用评分依据附录

## 1. 文档定位

本文档是《SAPD 成熟度评估业务设计 V2.1》的补充附录，负责定义“能力关注点 / 评估点实际评分依据”的来源、共享关系、缺级状态、评分限制、API / 数据结构和导出模板行为。它不替代业务设计中的通用四维 L1—L5 矩阵。

本轮只完成源表提取、现状核对和设计冻结，不修改成熟度运行代码、评分数据、模板文件、SQLite、正式数据包或用户库。问题分类必须先通过《SAPD 成熟度评分依据与当前能力字典映射审计》；映射门禁未通过前，本文缺失内容只作为源表初步库存，不进入业务确认。

## 2. 核心修正结论

1. `成熟度级别` Sheet 和 `成熟度分级描述` 第 2 行中的 L1—L5 是统一参考标准，只能作为通用解释或经过明确审批的回退依据。
2. 正式评分应优先使用 `成熟度分级描述` Sheet 中按能力 / 关注点编写的实际四维 L1—L5 依据。当前运行代码统一生成 `GENERIC_FALLBACK`，与该业务真值不一致。
3. 源表用纵向合并单元格表达评分依据共享关系。多个服务、一个关注点下多个服务，以及多个关注点下多个服务，都可以指向同一 `rubric_set`；不得把合并后的依据复制解释为每个服务独立编写。
4. 评分依据的绑定粒度是关注点组。技术能力的每个 `SERVICE` 评估点通过所属 `focus_id` 继承；治理 / 管理能力的 `FOCUS` 评估点直接继承。源表服务列不是当前服务字典的权威。
5. 空白等级必须区分“业务设计不可评分”和“遗漏待补充”。两者在 UI 中都不可选，但前者允许模板发布，后者阻止正式模板发布或导入确认。
6. 通用矩阵不得自动填补业务不可评分等级，也不得静默填补尚未判定的遗漏。

### 3.3 共享与继承规则

```text
rubric_set
  └─ 绑定一个或多个 capability_focus
       ├─ 技术能力：当前字典中的全部 SERVICE 评估点继承
       └─ 治理 / 管理能力：FOCUS 评估点继承
```

共享关系依据 rubric 单元格的显式纵向合并范围建立，包括非空合并和空白合并。空白合并仍保留共享关系，只把内容状态标为待补充。因此 `T-OF.AT-01/02/03` 共用一个空白组，`M-SA.OP-01/02` 共用另一个空白组；没有合并证据时，不得仅因属于同一能力而自动合并。

源表服务编码与当前字典存在历史漂移或笔误，因此评分依据只通过关注点稳定编码绑定，再由当前字典展开服务。不得以源表服务清单覆盖当前受保护服务字典。

## 4. 评分依据状态模型

每个 rubric set 固定保留 `4 × 5 = 20` 个状态槽，但并非所有状态槽都必须可评分。

| `availability_state` | 含义 | `criteria` | 可评分 | 模板发布 |
|---|---|:---:|:---:|:---:|
| `AVAILABLE_OBJECT_SPECIFIC` | 已有对象专用依据 | 必填 | 是 | 是 |
| `UNAVAILABLE_BY_DESIGN` | 该对象业务上不存在此成熟度等级 | 可空 | 否 | 是；须有业务决定与版本记录 |
| `MISSING_PENDING` | 预期应有但源数据遗漏 | 空 | 否 | 否 |
| `UNSTRUCTURED_PENDING` | 有原始文字，但未能拆成四维依据 | 保存原文，四维 `criteria` 为空 | 否 | 否 |
| `GENERIC_REFERENCE` | 仅供统一参考 | 必填 | 否 | 不作为对象专用发布条件 |
| `GENERIC_FALLBACK_APPROVED` | 经逐组业务审批允许通用回退 | 必填 | 是 | 是；必须记录批准人、原因和版本 |

固定知识库模板默认禁止 `GENERIC_FALLBACK_APPROVED`。只有业务明确确认“该组没有对象专用标准且允许使用通用矩阵”时才可启用，不能把它作为解析失败或遗漏的自动兜底。

## 5. 打分与目标等级规则

### 5.1 当前四维评分

- 每个维度独立读取该 rubric set 的 L1—L5 状态。只有 `AVAILABLE_OBJECT_SPECIFIC` 或经批准的 `GENERIC_FALLBACK_APPROVED` 可选。
- 整级空白且已确认为 `UNAVAILABLE_BY_DESIGN` 时，该等级在四个维度中统一禁用。
- 整级空白但仍为 `MISSING_PENDING` 时，该等级统一禁用，并显示“评分依据待补充”；不得用通用矩阵解锁。
- 某个已填等级只缺一个或两个维度时，仅已有依据的维度可展示原文；正式模板仍因 `PARTIAL` 阻止发布，直至缺失维度补齐或业务明确将整级设为不可评分。
- 若一个维度没有任何可评分等级，则该评估点状态为 `rubric_blocked`，不能完成评分。
- 逐级累进只在该对象的 `scoreable_levels` 有序集合内判断。低于业务最低等级的 `UNAVAILABLE_BY_DESIGN` 不作为前置条件，也不换算成 L1 或 0 分。

### 5.2 四维目标状态

- 点级目标按组织与角色、制度与流程、平台与工具、数据与信息四个维度分别选择 L1—L5，并分别复用对应维度的对象专用 Rubric。
- 每个目标维度只能选择该维度自身的可评分等级；任一目标维度缺失时，评估点不完整。四个目标说明均为可选，不进入完成门禁。
- 旧数据仅有单一 `targetLevel / targetReason` 时，首次读取将等级和说明同值展开到四个目标维度；已存在 `targetElements / targetDimensionNotes` 时不得被旧字段覆盖。
- 点级目标指数使用与当前状态相同的四维权重聚合；上层继续按评估点权重聚合，并保留派生 `targetIndex / targetLevel` 供差距、路线图和历史接口使用。
- 每个目标维度不得低于同维度当前有效等级；任一维度冲突使该评估点目标无效，并阻塞切换、统计与完成。综合目标下限继续作为旧数据和派生结果的兼容校验。

### 5.3 状态与错误码

| 场景 | 状态 / 错误码 | 行为 |
|---|---|---|
| 业务不可评分 | `RUBRIC_LEVEL_UNAVAILABLE` | UI / Excel 禁选，导入返回明确错误，不视为数据缺失 |
| 遗漏待补充 | `RUBRIC_LEVEL_MISSING` | 禁选；固定模板发布和正式导入确认阻断 |
| 原文未按四维拆分 | `RUBRIC_UNSTRUCTURED` | 保留原文供复核，不生成四维依据 |
| 评估点无任何可用等级 | `RUBRIC_ITEM_BLOCKED` | 评估点不可完成，进入缺失清单 |
| 非批准的通用回退 | `GENERIC_FALLBACK_NOT_APPROVED` | 拒绝模板发布 |

## 6. 数据与 API 设计

### 6.1 `maturity_rubric_set`

| 字段 | 说明 |
|---|---|
| `rubric_set_id` | 稳定主键；本附录暂以 `ARS-001`—`ARS-032` 表示 |
| `model_version_id/template_version_id` | 所属模型或已发布模板版本 |
| `name` | 面向维护的组名称 |
| `source_type` | `OBJECT_SPECIFIC_XLSX / TEMPLATE_GENERIC / GENERIC_REFERENCE` |
| `source_version/source_hash` | 来源版本与文件哈希 |
| `quality_status` | `READY / PARTIAL / EMPTY / UNSTRUCTURED` |
| `review_status` | `DRAFT / BUSINESS_REVIEWED / PUBLISHED` |

### 6.2 `maturity_rubric_binding`

| 字段 | 说明 |
|---|---|
| `rubric_set_id` | 评分依据组 |
| `focus_code/focus_id` | 当前稳定关注点引用 |
| `binding_role` | 固定为 `ASSESSMENT_RUBRIC` |
| `source_sheet/source_row_range` | 原表定位 |
| `match_method` | `EXACT_CODE / NORMALIZED_CODE / BUSINESS_CONFIRMED` |

一个 rubric set 可绑定多个关注点；一个已发布模板版本中的关注点只能有一个生效 rubric set。

### 6.3 `maturity_rubric`

| 字段 | 说明 |
|---|---|
| `rubric_set_id` | 所属组 |
| `dimension_code` | `ORG_ROLE / PROCESS_SYSTEM / PLATFORM_TOOL / DATA_INFO` |
| `level` | L1—L5 |
| `availability_state` | 第 4 章定义的状态 |
| `criteria` | 对象专用完整判定依据；仅可评分状态必填 |
| `raw_source_text` | 未拆分原文或审计快照 |
| `source_sheet/source_cell/source_range` | 原表来源 |
| `decision_reason/decision_by/decision_at` | 业务不可评分或通用回退的审批证据 |

唯一约束：`(rubric_set_id, dimension_code, level)`。`scoreable` 为派生值，不单独作为可被前端修改的业务字段。

### 6.4 模板与 API 投影

- `template_assessment_item` 增加 `rubric_set_id`，SERVICE / FOCUS 都通过该字段解析依据。
- API 可继续为每个 `scoreItem` 返回 20 条 `rubricEntries`，但每条必须增加 `availabilityState`、`scoreable`、`sourceType`、`sourceVersion`、`sourceRef`。
- 同时返回 `rubricSetId`、`rubricQualityStatus`、`allowedLevelsByDimension`、`allowedTargetLevels` 和 `rubricIssues`。
- 前端只消费 API / ViewModel 结果，不从通用矩阵、相邻关注点、同能力或服务名称自行推断。
- 当前校验“必须有 20 条非空 criteria”调整为“必须有 20 个状态槽；可评分槽 criteria 必须非空；发布模板不得含 `MISSING_PENDING/UNSTRUCTURED_PENDING`”。

## 7. 导出模板与导入校验

### 7.1 `Assessment_Items` / `Score_Input`

每个评估行增加只读字段：`rubric_set_id`、`rubric_quality_status`、四个维度的允许等级集合、`allowed_target_levels`。评分单元格的数据验证只包含允许等级；业务不可评分和遗漏等级均不出现在下拉 / 验证列表中。

### 7.2 `Rubric_Reference`

使用长表而不是只放一份通用矩阵：

```text
rubric_set_id, focus_codes, dimension_code, level, level_name,
availability_state, scoreable, criteria, source_type, source_version,
source_sheet, source_cell, source_range, decision_reason
```

通用矩阵另放 `Generic_Level_Reference`，标题必须明确“统一参考，不代表当前评估点实际可评分等级”。

### 7.3 Excel 交互

- 可评分等级正常显示；`UNAVAILABLE_BY_DESIGN` 使用锁定灰色和“业务不设此级”说明；`MISSING_PENDING` 使用锁定警示色和“待补充”。
- 单维缺失时不得把该维度的空依据替换为同级其他维度或通用文字。
- 导入值不在允许集合内时返回 `RUBRIC_LEVEL_UNAVAILABLE` 或 `RUBRIC_LEVEL_MISSING`，不能静默纠正、降级或改用通用矩阵。
- 导出可以生成“数据审阅版”，但含遗漏的文件必须标记 `release_status=BLOCKED`；不得作为正式可评分模板发布。
