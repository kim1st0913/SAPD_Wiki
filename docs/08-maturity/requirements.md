# 成熟度分析模块需求规划

本文档定义 SAPD Wiki 下独立 `maturity` 模块的需求边界。当前开发基线为《SAPD 成熟度评估业务设计 V2.1》（2026-07-12）；后文保留的早期 CLI / Excel 设想仅作为历史阶段记录，若与本页当前有效契约冲突，以本节和 V2.1 业务设计为准。

## 0. V2.1 当前有效契约

1. 新建项目不选择作用域，评估对象固定为企业组织。项目记录客户企业、负责人、所属行业、企业规模、客户特点、偏好与约束等客户上下文；作用域只来自模板中的真实字典映射或自定义模板配置。
2. 固定知识库模板的能力 L0/L1/L2、关注点、作用域、服务、映射和权重完全只读。技术能力按每条真实“关注点—作用域—服务”映射生成 `SERVICE` 评估点；完全无服务映射时生成 `FOCUS`。治理和管理能力始终以 `FOCUS` 为评估点，关联服务使用 `PLATFORM_EVIDENCE_REFERENCE` 角色，不单独计分。
3. 所有适用评估点统一填写组织与角色、制度与流程、平台与工具、数据与信息四维等级。前端和 API 均不接受人工当前总体分或总体等级；当前指数由后端按四维权重计算。
4. 自定义模板加载固定模板作为来源，可在模板内重组能力 L0/L1/L2、关注点、作用域、服务和服务角色；L0 可删除，最低有效结构为 L1→L2→关注点→服务（可选）。所有变更保留来源、原归属、当前归属和变更类型，不反写主工程字典。
5. 每个适用评估点必须由评估人员填写目标等级和目标理由；后端使用与当前分相同的有效项和权重逐层聚合目标，并计算 `min(100%, 当前指数 / 目标指数)`。项目不设置默认目标等级。
6. 证据字段保留但非必填；无证据不阻止评分、复核、计算和报告，也不默认扣分。证据覆盖率只作为材料完整性指标。
7. 固定模板和已发布自定义模板都支持评分文件导入导出；固定模板评分导入只能更新四维评分、目标、理由、备注和可选证据。自定义模板另支持结构文件导入导出；所有文件交换必须记录批次、结构哈希、行级错误和部分成功结果。
8. 后端按评估点、关注点、能力 L2、能力 L1、可选能力 L0 和总体逐层聚合当前值、目标值、四维结果和目标达成率。客户主结果和报告最细到能力 L2；关注点、服务、四维原始评分和证据只进入内部明细和附录。
9. 模板版本、知识快照、算法版本、计算运行和报告快照必须可重放。当前受控 demo 使用 `sapd-maturity-v2.1.0`，草稿保存在浏览器，不写正式 SQLite、正式 JSON、源 Excel、用户库或 DMG。

## 1. 模块定位

成熟度分析模块不是独立项目，也不是把评估结果塞进知识库主表的新对象类型。它应作为 SAPD Wiki 主工程下的独立业务模块，读取现有安全能力知识库，生成客户安全能力成熟度评估模板，导入员工填写的现状材料，完成匹配、审查、评分和报告输出。

核心定位：

```text
SAPD Wiki 知识库主模块：维护安全能力、关系、来源和前端投影
maturity 模块：基于安全能力知识库执行客户评估，不污染知识主数据
```

### 1.1 产品信息架构定位

2026-07-09 按 Product Design 口径同步后，成熟度相关内容在 SAPD Wiki 中拆为三类入口：

| 内容类型 | 页面归属 | 说明 |
|---|---|---|
| 说明类内容 | `安全指南` | 包括成熟度模型使用指南、评估方法说明、等级解释、填写说明和方法论阅读内容 |
| 评估工作模块 | `工作台 > SAPD 成熟度评估` | 包括评估任务、模板填报、证据导入、匹配审查、评分结果、差距建议和报告导出 |
| 能力数据 | `知识库字典 > 安全能力清单` | 成熟度模块只读引用该权威清单中的安全能力、关注点及相关字典对象，不维护一套平行能力主数据 |

该拆分用于后续 Product Design、Stitch 原型和前端实现，避免把方法说明、评估操作和能力主数据混在同一页面中。

## 2. 设计边界

| 边界 | 规则 |
|---|---|
| 工程归属 | 属于 SAPD Wiki 主工程，后续代码落在独立 `maturity` 模块 |
| 数据边界 | 评估运行数据使用 `maturity_*` 专用表，不写入 `knowledge_items` |
| 知识库依赖 | 只读取现有 `capability_category`、`capability_domain`、`capability`、`capability_focus` 等知识对象 |
| 能力权威源 | 能力、关注点等能力数据以 `知识库字典 > 安全能力清单` 为权威来源，maturity 不另建权威能力清单 |
| 来源追踪 | 复用 `source_files`、`import_jobs`、`source_references` 的思想，记录模板文件、Sheet、行号、字段和规则版本 |
| 当前实施范围 | V2.1 受控 demo 已实现企业组织项目、固定 / 自定义模板、四维评分、目标聚合、可选证据、文件交换、L2 结果、差距和报告；正式持久化后置 |
| 前端边界 | 前端只负责项目和评分交互、展示后端结果；不生成权威评估点、不计算权威分数 |
| 客户数据 | 客户输入、评估结果和报告默认保存在本地 `data/maturity/`，不提交 GitHub |

业务逻辑来源固定为：

- 模型设计严格参考 `sample文档介绍.docx` 第 3.1 章“网络安全能力成熟度模型”，包括模型架构、能力等级定义、能力要素解析、能力域及能力子域；
- 评估逻辑严格参考 `sample文档介绍.docx` 第 4 章“网络安全能力成熟度评估”，包括关注点评估、能力子域评估、能力域评估、总体能力评估、计分方式和评估流程；
- 后续后端代码、模板字段和报告结构都应实现这两部分业务逻辑，不另起一套模型。

## 3. 早期 V1 目标（历史规划）

| 编号 | 目标 | 验收口径 |
|---|---|---|
| G1 | 生成标准 Excel 评估模板 | 模板包含评估信息、现状输入、证据清单、人工调整、能力参考和填写说明 |
| G2 | 导入员工填写模板 | 能解析 50-200 行客户现状输入，并输出校验结果 |
| G3 | 匹配安全能力关注点 | 填写能力编码时精确匹配；未填写编码时输出候选能力、置信度和解释 |
| G4 | 保留人工审查 | 低置信度匹配不得直接进入正式评分，先导出审查表 |
| G5 | 生成 L0-L5 成熟度评分 | 按 `capability_focus` 评分，并向 L2、L1、分类和整体聚合 |
| G6 | 输出离线报告数据 | 输出 JSON、Markdown、HTML 报告和图表数据结构 |
| G7 | 保留完整追溯链 | 结果能追溯到模板版本、规则版本、知识库快照、输入行和匹配依据 |

前端入口验收补充：

- 说明类内容只进入 `安全指南`；
- 评估操作只进入 `工作台 > SAPD 成熟度评估`；
- 能力选择、能力编码、关注点选择只引用 `知识库字典 > 安全能力清单` 的权威数据。

## 4. 早期 V1 非目标（历史规划）

- 不开发复杂前端页面。
- 不开发图表渲染代码。
- 不生成 PPTX 报告。
- 不引入在线 API 或云端语义模型。
- 不把客户现状、评分结果、报告写入 `knowledge_items`。
- 不改动现有 Excel ETL、能力浏览前端和主线导入链路。

## 5. 用户与流程

当前 V2.1 用户主流程为：

```text
查看项目
→ 新建企业组织项目并填写客户上下文
→ 选择固定知识库模板或自定义模板
→ 固定模板按真实映射生成只读评估点，或校验并发布自定义模板版本
→ 在线评分或导出 / 导入评分文件
→ 对每个适用点填写四维当前等级
→ 人工填写目标等级和理由
→ 可选关联证据
→ 提交并逐维复核
→ 后端逐层计算当前、目标、差距和目标达成率
→ 查看能力 L2 结果、差距和演进建议
→ 生成绑定计算运行的报告快照
```

以下导入流程为后续材料导入扩展，不是所有项目的固定前置步骤。

| 用户 | 主要动作 |
|---|---|
| 咨询顾问 / 评估人员 | 生成模板、填写客户现状、导入、审查匹配、导出报告 |
| 售前 / 架构师 | 查看能力短板、优先级、目标等级差距和改进建议 |
| 项目经理 | 跟踪多次评估结果和改进前后变化 |
| 知识库维护者 | 维护安全能力、关键词、评分规则和模板版本 |

V1 流程：

```text
生成评估模板
→ 员工填写客户现状与证据
→ 导入模板并校验
→ 自动匹配能力关注点
→ 导出低置信度匹配审查表
→ 导入人工审查结果
→ 规则评分
→ 汇总到 L2 / L1 / 分类 / 整体
→ 导出 JSON / Markdown / HTML 报告
```

## 6. 初始样例输入

用户已明确 maturity raw sample 包括一个 Word、一个 PPTX 和一个 XLSX。建议后续本地放入：

```text
data/raw-samples/maturity/
├─ <客户现状或访谈纪要>.docx
├─ <现有评估汇报或客户材料>.pptx
└─ <成熟度评估输入模板或样例>.xlsx
```

三类样例在 M1/M2 的用途：

| 样例 | 用途 |
|---|---|
| Word / DOCX | 提炼客户现状描述、证据摘要和报告正文风格，不作为 V1 自动评分必需输入 |
| PPTX | 参考评估汇报结构、图表口径和客户沟通表达，不在 V1 自动生成 PPT |
| XLSX | 作为 V1 模板生成、导入校验、匹配审查和评分闭环的主输入 |

这些样例属于本地敏感资料，默认不提交 GitHub。

## 7. 后端与前端约束

后端负责事实和规则：模板生成、文件登记、模板解析、字段校验、匹配候选、评分、汇总、报告数据导出。

前端只消费后端或静态导出的结果：评估列表、匹配审查、结果总览、能力明细和报告导出。前端不得从原始模板字段自行推断能力关系或评分结果。

## 8. 待进入 M1 前确认

| 问题 | 建议默认值 |
|---|---|
| 成熟度等级是否采用 L0-L5 | 是 |
| 主模型是否采用“安全能力维 × 落地要素维 × 成熟度等级维” | 是 |
| V1 是否先 CLI + HTML 报告，不做完整前端 | 是 |
| 员工是否必须选择能力编码 | 不强制，但强烈建议 |
| 低置信度匹配是否必须人工审查 | 是 |
| V1 是否输出 PPTX | 否，V2 再做 |
