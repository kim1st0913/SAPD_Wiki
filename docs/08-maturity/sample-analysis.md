# 成熟度模块样本分析

本文档记录 maturity 模块样本驱动分析结论。用户已在 2026-05-13 更新 `sample 评分表.xlsx`，本文档以新版 XLSX 为准。

样例目录：

```text
data/raw-samples/maturity/
├─ sample文档介绍.docx
├─ samle 使用教程.pptx
└─ sample 评分表.xlsx
```

本轮目标是理解样例结构和建模含义，不开发功能、不修改主工程 schema、不实现评分算法、不做前端页面。

## 1. 样本文件总体判断

| 文件 | 类型 | 主要用途 | 建模结论 |
|---|---|---|---|
| `sample 评分表.xlsx` | Excel 工作簿 | 成熟度等级与能力关注点分级描述 | 新版 XLSX 是“评价基准表”，应进入 maturity 专用模型基准表，不是客户评分输入表 |
| `sample文档介绍.docx` | Word 文档 | 成熟度模型方法论说明 | 模型基准来源，用于提炼模型概念、能力等级、能力要素、能力域、评估流程和报告叙事 |
| `samle 使用教程.pptx` | PowerPoint | 成熟度工具介绍和使用教程 | 用于提炼工具使用流程、交付场景、报告视图和培训材料结构 |

关键变化：

- 新版 `sample 评分表.xlsx` 只保留 2 个 Sheet：`成熟度级别`、`成熟度分级描述`；
- 旧版中的 `成熟度评分`、`成熟度视图`、`成熟度分级描述 (2)` 已不存在；
- 新版样例不包含客户名称、评估项目、证据、人工评分、汇总视图或报告输出；
- 因此新版 XLSX 只能用于建立模型基准和模板参考能力清单，不能直接作为客户评估输入。

用户已确认本轮建模口径：

- 成熟度模型设计严格参考 `sample文档介绍.docx` 第 3.1 章“网络安全能力成熟度模型”；
- 成熟度评估逻辑严格参考 `sample文档介绍.docx` 第 4 章“网络安全能力成熟度评估”；
- 评分对象包括 `capability`、`capability_focus`，核心都是判断是否具备相关能力；
- 作用域安全技术服务 / 实践项是平台与工具维度的技术输入、证据和匹配线索，不单独作为成熟度评分对象；
- 评分要素固定为组织与角色、制度与流程、平台与工具、数据与信息；
- Word 是模型方法论基准，XLSX 是评价基准表，二者进入 maturity 专用表；
- 成熟度评分结果按 detail → focus → L2 capability → L1/domain → category → overall 聚合；
- maturity 模型中的安全能力、关注点、作用域安全技术服务必须与主工程已治理数据做匹配，并输出不一致项供人工确认。

## 2. XLSX Sheet 结构

| Sheet | 实际数据范围 | 公式数量 | 主要内容 | 建模用途 |
|---|---:|---:|---|---|
| `成熟度级别` | 2 行 × 10 列 | 0 | L1-L5 通用等级定义，每个等级内包含组织、流程、工具、信息四类描述 | 形成 `maturity_level_definition` 和通用等级解释配置 |
| `成熟度分级描述` | 176 行 × 13 列 | 0 | 能力层级、关注点、作用域、技术服务、L1-L5 分级描述 | 形成模型基准库和能力关注点评分规则来源 |

## 3. XLSX 字段字典

### 3.1 `成熟度级别`

| 原始字段 / 区域 | 含义 | 枚举值 | 建模建议 |
|---|---|---|---|
| `Level 1 非正式执行` | 成熟度一级通用定义 | L1 | 映射为 `level_code = L1`、`level_name = 非正式执行` |
| `Level 2 / 计划跟踪` | 成熟度二级通用定义 | L2 | 映射为 `level_code = L2`、`level_name = 计划跟踪` |
| `Level 3/ 充分定义` | 成熟度三级通用定义 | L3 | 映射为 `level_code = L3`、`level_name = 充分定义` |
| `Level 4/ 量化控制` | 成熟度四级通用定义 | L4 | 映射为 `level_code = L4`、`level_name = 量化控制` |
| `Level 5 / 持续优化` | 成熟度五级通用定义 | L5 | 映射为 `level_code = L5`、`level_name = 持续优化` |

每个等级的说明文本内部包含四类要素：

- 组织；
- 流程；
- 工具；
- 信息。

这些要素没有被拆成独立列，因此后续系统如需结构化使用，应在导入时从文本中解析或在配置文件中维护拆分后的版本。

### 3.2 `成熟度分级描述`

| 原始字段 | 含义 | 空值情况 | 建模建议 |
|---|---|---|---|
| `安全能力分类` | 能力大类，如安全技术能力、安全治理能力、安全管理能力 | 采用合并单元格，需向下填充 | 映射到主工程 `capability_category`，作为只读引用 |
| `L1 高阶战略能力` | L1 能力域 | 采用合并单元格，需向下填充 | 映射到主工程 `capability_domain` |
| `L2安全能力` | L2 安全能力 | 采用合并单元格，需向下填充 | 映射到主工程 `capability` |
| `安全关注点` / `序号` | 能力关注点编码，如 `T-AS.AD-01` | 84 个关注点行有值 | 映射到主工程 `capability_focus.code` |
| `关注点` | 能力关注点标题 | 84 个关注点行有值 | 映射到 `capability_focus_title` |
| `关注点描述` | 能力关注点详细描述 | 84 个关注点行有值 | 映射到 `capability_focus_description` |
| `作用域` | 适用作用域，如 `I-DI 数据` | 145 行有值 | 映射到 `scope_type`，属于上下文字段 |
| `技术服务` | 作用域下的安全技术服务或实践项 | 145 行有值 | 映射到 `security_technical_service_name`，作为平台与工具评分输入 |
| `Level 1 非正式执行` | 特定关注点的 L1 描述 | 28 个关注点行有值 | 映射到 `level_criteria.L1` |
| `Level 2 / 计划跟踪` | 特定关注点的 L2 描述 | 29 个关注点行有值 | 映射到 `level_criteria.L2` |
| `Level 3/ 充分定义` | 特定关注点的 L3 描述 | 29 个关注点行有值 | 映射到 `level_criteria.L3` |
| `Level 4/ 量化控制` | 特定关注点的 L4 描述 | 28 个关注点行有值 | 映射到 `level_criteria.L4` |
| `Level 5 / 持续优化` | 特定关注点的 L5 描述 | 19 个关注点行有值 | 映射到 `level_criteria.L5` |

统计结果：

| 指标 | 数量 |
|---|---:|
| 能力分类 | 3 |
| L1 高阶战略能力 | 10 |
| L2 安全能力 | 32 |
| 能力关注点 | 84 |
| 作用域枚举 | 7 |
| 技术服务 / 实践项 | 145 |
| 含任一等级描述的关注点 | 30 |

作用域枚举值：

- `I-DI 数据`
- `I-NT 网络`
- `I-AP 软件应用`
- `I-OS 操作系统`
- `I-HD 硬件`
- `I-PE 物理环境`
- `I_US 用户`

注意：`I_US 用户` 与主工程现有命名可能存在下划线 / 连字符不一致问题，后续需要标准化为主工程权威作用域编码。

## 4. 一行数据代表的业务对象

`成熟度分级描述` 的行粒度有两类：

| 行类型 | 判断方式 | 代表的业务对象 |
|---|---|---|
| `focus_definition` | `安全关注点` 有编码 | 一个能力关注点的模型定义 |
| `scope_practice` | `作用域` 或 `技术服务` 有值 | 某个能力关注点下的作用域安全技术服务 / 实践项 |

需要注意：

- 由于存在合并单元格，`scope_practice` 行必须继承上方最近的能力分类、L1、L2、关注点编码、关注点标题和关注点描述；
- `Level 1` 到 `Level 5` 描述通常只写在部分 `focus_definition` 行上，不会在每个作用域实践行重复；
- 本 Sheet 没有客户评分，因此不存在“评分明细行”。

## 5. 哪些字段可直接用于成熟度评分

新版 XLSX 没有直接评分字段。

| 字段 | 是否可直接评分 | 原因 |
|---|---|---|
| `Level 1` 到 `Level 5` 描述 | 否 | 这是判定标准，不是客户现状得分 |
| `安全关注点` | 否 | 这是评分对象引用 |
| `作用域` | 否 | 这是评估对象的范围限定，不是评分值 |
| `技术服务` | 否 | 这是作用域安全技术服务 / 实践项引用，不是评分值 |

新版 XLSX 可用于支持评分规则解释，但不能直接产生 `maturity_score_result`。

需要注意：`安全关注点` 可以形成成熟度评分对象候选；`作用域` 和 `技术服务` 用于限定技术输入、解释平台与工具维度和提供证据，不能单独形成成熟度评分对象。

## 6. 哪些字段只能作为上下文或证据

| 字段 | 用途 |
|---|---|
| `安全能力分类` | 能力树上下文 |
| `L1 高阶战略能力` | 能力树上下文和报告聚合维度 |
| `L2安全能力` | 能力树上下文和报告聚合维度 |
| `关注点描述` | 评分解释和报告说明 |
| `作用域` | 评估范围、筛选、差距解释 |
| `技术服务` | 平台与工具维度技术输入、匹配提示、差距解释 |
| `Level 1` 到 `Level 5` 描述 | 判定标准、评分解释、报告依据 |

## 7. Word 样例结构说明

`sample文档介绍.docx` 包含约 987 个非空段落和 6 个表格，主要结构包括：

- 网络安全能力成熟度模型概述；
- 设计依据；
- 法律法规及标准实践；
- 模型及方法论；
- 部门实践经验；
- 网络安全能力成熟度模型；
- 模型架构；
- 能力等级定义；
- 能力要素解析；
- 能力域及能力子域；
- 网络安全能力成熟度评估；
- 评估方法、计分方式、评估流程；
- 网络安全能力成熟度模型应用。

对建模有直接影响的结论：

- 模型使用 5 个正式等级：非正式执行、计划跟踪、充分定义、量化控制、持续优化；
- 样例强调并固化四类能力要素：组织与角色、制度与流程、平台与工具、数据与信息；
- 评估层级从下到上为关注点评估、能力子域评估、能力域评估、总体能力评估；
- 计分方式提到算术平均法、加权平均法、最低得分法；
- 应用流程包括现状识别、需求分析、差距分析和优先级设计。

Word 样例更适合作为方法论文档和报告解释来源，不适合作为结构化评分输入。

## 8. PPT 样例结构说明

`samle 使用教程.pptx` 包含 31 页，主要内容包括：

- 成熟度模型概述；
- 最佳实践参考和项目实践分析；
- 部门网络安全能力成熟度工具介绍；
- 能力等级；
- 安全能力要素；
- 能力域；
- 工具说明；
- 成熟度评估过程；
- 规划项目中的应用；
- 现状评估、需求分析、差距识别、优先级识别示例。

对建模有直接影响的结论：

- PPT 明确成熟度工具包括评分表、教程和案例库；
- 工具应用场景覆盖现状调研、需求分析、差距识别和改进优先级；
- 报告视图需要支持能力域评分、要素得分、总体成熟度和差距分析；
- 后续正式系统可把 PPT 的使用说明沉淀为 `Readme` Sheet 或用户指南内容。

PPT 样例更适合作为模板使用说明和报告展示逻辑来源，不作为 V1 评分输入。

## 10. 不确定字段

| 字段 / 现象 | 不确定点 | 建议处理 |
|---|---|---|
| `技术服务` 列 | 部分值实际是“作用域 + 关注点 + 实践项”，不一定等同主工程已治理 `security_technical_service` | 标准字段命名为 `security_technical_service_name`，通过 `scope_type + capability_focus_code + service_name` 与主工程技术服务做一致性核对 |
| `I_US 用户` | 与主工程作用域编码可能不一致 | 后续统一到权威 `scope_type.code` |
| `Level 1` 到 `Level 5` 描述大量为空 | 只有部分关注点有专属分级描述 | 缺失时回退到 `成熟度级别` 的通用等级描述 |
| 当前 XLSX 缺少评分输入 | 无法直接生成客户成熟度结果 | 后续正式模板必须新增 `Score_Input` |
| 当前 XLSX 缺少客户和项目字段 | 无法区分客户、项目和批次 | 后续正式模板必须新增 `Assessment_Info` |
| 当前 XLSX 缺少证据字段 | 无法追溯评分依据 | 后续正式模板必须新增 `Evidence_List` 或证据摘要字段 |

## 11. 字段质量问题

| 问题 | 影响 | 建议 |
|---|---|---|
| 大量合并单元格 | 读取时上级能力、关注点和分类会丢失 | 导入时必须做向下填充 |
| 同一 Sheet 存在关注点定义行和作用域实践行 | 行粒度不一致 | 增加 `row_type`，区分 `focus_definition` 和 `scope_practice` |
| 分级描述覆盖不完整 | 无法为所有关注点生成专属 L1-L5 标准 | 建立通用等级描述和关注点专属描述两级规则 |
| 样例没有评分输入 | 无法验证评分字段和汇总公式 | 下一轮需要正式 `Score_Input` 样例或由系统生成模板后再填写 |
| 文件名 `samle 使用教程.pptx` 存在拼写错误 | 不影响内容，但影响自动识别美观 | 后续可在样例清单中登记原始文件名，不强制重命名 |

## 12. 建模建议

1. 把新版 XLSX 定位为“成熟度模型基准来源”，不是客户评分输入。
2. 从 `成熟度分级描述` 生成 `maturity_capability_baseline`、`maturity_scope_service_baseline` 和 `Reference_Level_Criteria`。
3. 正式客户评估模板必须新增 `Assessment_Info`、`Score_Input`、`Evidence_List`、`Manual_Adjustment`。
4. `Score_Input` 应让评估人员填写四类要素得分：组织与角色、制度与流程、平台与工具、数据与信息。
5. 评分结果后续由系统生成 `maturity_score_result`，不从新版样例直接读取。
6. 客户评估数据继续明确不进入 `knowledge_items`，只进入 maturity 专用模型。
7. 在启用模型基准前，先生成 `maturity_mainline_match_result`，输出与主工程能力、关注点和安全技术服务不一致的数据清单。
