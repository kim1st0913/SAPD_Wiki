# SAPD WIKI 成熟度模型 V3 差异说明

> 比较基线：当前 V2.1 / 使用指南 v1.3 / OI-197 原始评分依据。
>
> V3 状态：业务审阅提案，不进入正式运行态。

## 1. 执行摘要

V3 不推翻 SAPD 的对象分类、五级名称、四维结构和项目工程经验。它把评分文字从“建设了什么”校准为“能力如何持续运行”，并增加逐关注点连续范围、Level 4 量化控制、Level 5 改进验证，以及来源和人工审阅机制。未经业务和数据验证的候选指标已退出正式提案。

SCF 2026.2 的 1,534 个控制并非机械提供五套独立标准：工作簿中 L1、L2、L4、L5 的独立标准数量明显不同，且 Evidence Request List 与 Assessment Objectives 分开维护。V3 因此逐关注点裁定连续范围，并把成熟度正文、证据和人工复核分层；SCF 的个别断级组合和候选指标不直接照搬。

## 2. 保持不变的合同

- T / G / M，10 个 L1 域、32 个 L2 能力、91 个关注点和现有编码。
- 185 个正式评估输入对象，其中 154 个安全技术服务评估点、31 个关注点评估点。
- 五级中文名称和四维中文名称。
- 当前项目“不适用”功能、正式 API、聚合规则、历史评分和用户库。
- 正式名称暂不修改，仅增加建议校准标题。

## 3. 对象结构与评分粒度

| 主题 | v1.3 / 当前 | V3 建议 | 运行影响 |
|---|---|---|---|
| 最小评分对象 | 文档容易理解为关注点 | 185 个评估点是正式输入；91 个关注点定义范围并被评估点继承 | 无，本轮只修文档与提案 |
| 等级范围 | 工作台要求逐行再决定，容易默认五级 | 每个关注点预先给出有依据的连续起止范围 | 无，待业务批准后另行迁移 |
| 评估点覆盖 | 无统一规则 | 默认继承；只有对象或证据显著不同才允许有来源的覆盖 | 无 |

## 4. 五级成熟度语义

| 等级 | 当前主要问题 | V3 校准 |
|---|---|---|
| L1 非正式执行 | 部分文字等同“完全未做”，与非正式执行有张力 | 为保持结果不变，未执行、极弱实践、零散执行或证据不足均落 L1；不新增 Level 0 或状态 |
| L2 计划跟踪 | 仍出现职责不明确、无计划等 L1 语义 | 强制体现负责人、范围、计划、资源、执行记录和状态跟踪 |
| L3 充分定义 | 混入自动化、量化和持续优化 | 回归正式制度、职责、程序、适用范围一致执行、例外和变更 |
| L4 量化控制 | 主要依靠平台、自动化或未经验证的候选指标描述 | 能力稳定运行并形成可跨周期比较结果；依据批准的控制目标、质量要求、时限、容忍边界或验证结果识别偏差、纠正并验证效果，不预设指标清单 |
| L5 持续优化 | 把 AI/ML、“更先进工具”或一般整改当作 L5 | 必须建立在稳定 L4 之上，由趋势、根因、复发问题或外部变化触发，验证前后效果并固化；AI 不是判据 |

## 5. 四维定义与边界

- **组织与角色**：授权关系、结果责任、执行与监督职责、岗位能力、职责分离、资源配置和跨部门协同。
- **制度与流程**：适用范围、触发条件、步骤、频率、审批、例外、变更、复核及业务流程衔接。
- **平台与工具**：覆盖、配置一致性、可靠性、可维护性、集成、自动化、回退、审计和效果验证。
- **数据与信息**：记录、台账、证据、指标、数据质量、口径、责任、分析、复盘和知识沉淀。

四维是同一能力的互补证据，不要求治理类能力为了形式完整购买专用平台，也不允许用“有工具”替代职责、流程和效果。

## 6. 适用性、连续范围与目标建议

- 项目“不适用”：经适用性判断，本组织 / 本范围不评价该关注点。
- 模板“等级不设置”：该关注点的能力语义无法形成该级独立、可验证标准；不是项目不适用。
- 目标建议：一般企业、关键系统或业务、高风险组织三档参考清单，不自动决定得分。
- Sliding Scale 影响能力定位、投资顺序和目标深度，但不机械决定每个关注点的等级数量。

V3 范围分布：

- `L1—L5`：78 个关注点
- `L2—L5`：9 个关注点
- `L3—L5`：4 个关注点

已确认的边界：`T-IN.IP-01` 为 L2—L5；T-OF 三项均条件适用且起点不低于 L3，其中结束级分别按能力语义裁定。

## 7. 91 → 185 的继承规则

关注点承载适用性、连续范围、目标建议和通用理由。185 个评估点默认继承；只有技术服务对象、范围或证据链产生实质差异时才覆盖，且必须保存覆盖理由和来源。本轮提案没有为形式完整而自动制造覆盖。

## 8. Rubric 结构治理

- ARS-001 拆为架构设计与管控、冗余与高可用、可靠性与恢复。
- ARS-007 拆为日志生成、集中收集存储、审计分析。
- ARS-023 拆为网络安全投资、信创措施适配推广。
- ARS-019 补齐并按授权溯源、目标评估、受控执行与效果评估分立。
- ARS-027 补齐并按运行流程、运行指标与效果评价分立。

## 9. Level 4 量化控制与指标退出

30 个通用候选指标、273 个关注点候选指标、评分单元中的候选指标名称和统一“衡量说明”均退出 V3 正式提案。Level 4 仍保留量化控制语义：能力结果可跨周期比较，并依据法规、合同、SLA、业务连续性要求或组织正式批准的控制目标、质量要求、时限和容忍边界识别偏差、纠正并验证效果。后续如需指标库，应作为独立方法项目重新建立来源、口径、数据质量和批准机制。

## 10. 证据和来源

V3 将三类内容分开：成熟度正文说明能力状态；证据提示说明检查、访谈和测试入口；人工复核记录业务裁定。技术服务、工具或项目自行选用的指标只能提供实现及证据线索，不能自动形成得分。

## 11. 自定义模板通用评分依据

自定义模板根节点展示五级通用描述。自定义模板中新建且没有对象专用评分依据的评估点，使用版本化的四维通用 Rubric；从基础模板复制的评估点继续保留对象专用 Rubric。禁止从模板中任取一个完整评估点并复制其评分文字，避免把某个安全对象的专用标准错误套用到其他对象。该通用 Rubric 不用于绕过固定模板的 Rubric 完整性门禁。

| 等级 | 通用描述 |
|---|---|
| L1 非正式执行 | 已开展相关活动，但依赖个人经验或临时安排，范围、方法与证据不稳定。 |
| L2 计划跟踪 | 已明确责任、范围和计划并跟踪重点任务，但跨团队标准和执行一致性不足。 |
| L3 充分定义 | 职责、流程、支撑机制和记录已正式定义，并在适用范围一致执行，例外与变更受控。 |
| L4 量化控制 | 能力稳定运行，结果可跨周期比较，并依据批准目标或控制边界识别偏差、纠正并验证效果。 |
| L5 持续优化 | 基于稳定的 L4 证据、趋势、根因或外部变化持续改进，比较前后效果并固化有效做法。 |

## 12. 工作台变化

- 逐评估点、逐等级、逐维显示原文、精炼后的优化文、修改原因、来源和证据提示。
- 范围外等级保留审阅槽位并逐维说明不设置理由。
- 删除最后一列“确认进度”；顶部只保留离线业务复核统计。
- 人工结论为接受、要求修改、需要讨论，不复用正式评分结果或“不适用”。
- 状态采用新 localStorage key，旧工作台状态不被删除或误迁移为 V3 批准。

## 13. 建议校准标题

带“持续优化”的正式标题在当前代码和正式名称中保持不变；V3 指南、主表和工作台显示建议校准标题，避免标题先天带入 L5。完整映射见主表。

## 14. 兼容性与禁止范围

- v1.4 作为独立文件生成，不覆盖 v1.3，也不自动接入 Web/App。
- 不修改源 Excel、正式 Rubric 字典、API、评分规则、运行模板、历史评分和真实用户库。
- 所有提案文件均为 proposal；必须经过业务审阅、来源确认和回归验证后才可另开正式迁移任务。
