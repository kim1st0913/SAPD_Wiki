# 成熟度分析模块评分规则设计

本文档定义 maturity 模块 V1 的规则评分口径。当前只做规则设计和 YAML 配置占位，不实现评分代码。

## 1. 评分模型

V1 采用三维模型：

```text
安全能力维 × 落地要素维 × 成熟度等级维
```

| 维度 | 说明 |
|---|---|
| 安全能力维 | 读取 SAPD Wiki 现有能力树，以 `capability_focus` 作为最小评分单元 |
| 落地要素维 | 判断能力是否有组织、流程、技术、运营、指标和改进闭环支撑 |
| 成熟度等级维 | 使用 L0-L5 表示从无证据到持续优化的成熟度 |

上下文维度，如业务范围、场景、作用域、信息化环境和生命周期，只用于筛选、解释和报告展示。V1 不把上下文作为主评分轴。

## 2. 成熟度等级

| 等级 | 名称 | 默认分 | 判断含义 |
|---|---|---:|---|
| L0 | 未覆盖 / 无有效证据 | 0 | 没有有效输入、证据或匹配 |
| L1 | 临时执行 | 20 | 有零散实践，依赖个人经验 |
| L2 | 计划跟踪 | 40 | 有职责、计划、局部流程或局部工具，能重复执行但覆盖有限 |
| L3 | 充分定义 | 60 | 组织、流程、技术和运营较完整，能在主要范围稳定落地 |
| L4 | 量化控制 | 80 | 在 L3 基础上，有指标、审计、监控、报表或效果度量 |
| L5 | 持续优化 | 95 | 在 L4 基础上，能基于度量、事件、审计或风险变化持续改进 |

## 3. 落地要素与默认权重

| 要素 | 字段 | 默认权重 | 作用 |
|---|---|---:|---|
| organization | `organization_status` | 0.15 | 判断职责、部门、岗位、责任边界 |
| process | `process_status` | 0.20 | 判断制度、流程、SOP、审批、例外管理 |
| technology | `technology_status` | 0.25 | 判断工具、平台、产品、技术措施 |
| operation | `operation_status` | 0.15 | 判断日常运营、监控、审计、告警、报表 |
| metrics | `metric_status` | 0.15 | 判断指标、度量、SLA、覆盖率、有效性评价 |
| improvement | `improvement_status` | 0.10 | 判断复盘、整改、优化和闭环机制 |

## 4. 等级门槛

| 等级 | 最低条件 |
|---|---|
| L0 | 无有效输入、无证据、无匹配 |
| L1 | 有实践描述，但缺少职责、流程、工具和运营机制 |
| L2 | 组织、流程、技术任一要素有效 |
| L3 | 组织、流程、技术、运营四类中至少三类有效 |
| L4 | 满足 L3，且有指标、审计、监控、报表或有效性度量 |
| L5 | 满足 L4，且有复盘、整改、持续优化或闭环机制 |

## 5. 匹配规则

自动匹配用于把输入行映射到 `capability_focus`。

| 优先级 | 方法 | 分数建议 | 处理 |
|---|---|---:|---|
| P0 | 能力编码精确匹配 | 100 | 自动接受 |
| P1 | 标题 / 别名精确匹配 | 90 | 自动接受 |
| P2 | 关系扩展匹配 | 70-85 | 高分可接受，低分需审查 |
| P3 | 关键词规则匹配 | 50-75 | 多数需要审查 |
| P4 | 本地模糊文本匹配 | 40-70 | 只作候选 |

候选状态：

| 分数 | 状态 | 说明 |
|---:|---|---|
| 85-100 | `auto_accepted` | 可自动进入评分，但保留审查记录 |
| 60-84 | `needs_review` | 进入人工审查 |
| 40-59 | `weak_candidate` | 仅参考，不直接评分 |
| 0-39 | `unmatched` | 未匹配 |

## 6. 评分流程

```text
读取已确认匹配
→ 按 capability_focus 汇总输入行
→ 判断各落地要素是否有效
→ 应用等级门槛
→ 计算成熟度分数和置信度
→ 生成 scoring_detail_json
→ 向 L2 / L1 / 分类 / overall 聚合
```

V1 不使用黑盒模型直接评分。后续可以增加本地语义匹配，但必须保留规则解释和人工覆盖。

## 7. 聚合规则

V1 简化聚合：

```text
聚合成熟度分数 = 子项成熟度分数平均值
```

后续保留权重扩展：

```text
聚合成熟度分数 = Σ(子项分数 × 权重 × 置信度修正) / Σ(权重 × 置信度修正)
```

等级由聚合分数回填：

| 分数 | 等级 |
|---:|---|
| 0-9 | L0 |
| 10-29 | L1 |
| 30-49 | L2 |
| 50-69 | L3 |
| 70-89 | L4 |
| 90-100 | L5 |

## 8. 人工覆盖

人工覆盖必须记录：

- 原始自动等级；
- 覆盖后等级；
- 覆盖原因；
- 审查人；
- 审查时间；
- 影响的输入行或证据。

覆盖后的结果仍写入 `maturity_capability_scores`，但 `reviewer_override` 必须为 true。
