## 3. 已确认的成熟度页面方向

### 3.1 用户选择

- 主结构：从全部评估项纵向平铺改为 L0 分类、L1 主 Tab、L2 次级 Tab；一次只展示当前 L2。
- 完整页面：项目内步骤导航保留；主工作区改为左侧 L0 / L1 / L2 / FOCUS 评分目录与右侧 L2 汇总、关注点摘要、服务 Tab 和主评分表单。评分区继续采用“维度 + 1—5 + 加长评分依据、当前 rubric 下沉一行”。
- 能力切换：复用安全能力映射目录的层级轨道、缩进与展开控件；节点以绿 / 黄 / 冷灰圆点标签分别表达已完成 / 进行中 / 未开始，蓝色只表示当前路径，文字由目录图例与可访问名称提供。
- 汇总区：L2 必须有不可折叠的当前 / 目标 / 差距 / 完成度 / 四维平均分汇总；关注点按块展示后端平均分。
- 打分区：组织、流程、工具、数据使用成熟度 1—5 按钮，并持续完整显示当前已选等级的维度标准；主区不展开全部 L1—L5；人工目标继续使用下拉，是否适用使用方框勾选。
- 证据区：每个评估点增加“评估证据说明（可选）”，文件、链接和等级为次级关联；无证据不阻塞流程。
- 批量与反馈：L2 / 关注点在 `DIRECT` 和 `CHILD_ROLLUP` 中选择一个有效评分来源；直接评分填写节点四维。关注点“统一设置下级”仅在全部下级未评分时选择一个等级初始化全部下级四维，任一下级任一维度已评分后锁定；评分执行页不显示下级聚合出的关注点评级，结果页仍消费后端聚合。
- 评分标准：对象专用 rubric 优先，通用四维五级矩阵只作回退；四个维度分别选择“当前稳定实现的最高完整等级”，计划状态只进入人工目标，不进入当前分。
- 评估点：每个 `SERVICE / FOCUS` 都显示是否适用；完全没有安全技术服务时直接评估真实关注点，不生成空服务或伪作用域。

### 3.2 本质规则

成熟度评分页的主语是“在目录明确定位后完成一个评估点判断”。项目内步骤导航 → 左侧评分目录 → 右侧 L2 汇总 / 关注点摘要 / 服务 Tab / 主评分表单构成唯一工作流，不再并列横向能力 Tab、关注点列表和上一 / 下一服务分页。L2 / 关注点必须明确唯一评分来源：`DIRECT` 消费节点四维，`CHILD_ROLLUP` 消费下级实际结果，二者不能在一次 calculation run 混用。统一设置与实际统计反馈必须分离；当前行的维度标准、加长评分依据、目标、证据和适用性处于同一上下文。任何评分重渲染都必须保持当前目录路径、服务 Tab、滚动位置、页面位置和焦点。

### 3.3 当前真实页问题证据

- 当前真实评分页同时常驻全局导航、能力目录、评分表、右侧说明区，1440px 视口下业务名称被大量截断。
- 评分按钮本身清楚，但被过窄列宽和多层面板削弱。
- 评分说明与证据和当前行分离，用户需要反复确认右侧 inspector 是否仍对应当前行。
- 页面信息密度并非过高，问题是同时可见的结构层级过多。

## 4. 全工程审计工作记录

### 4.1 全局导航 / 总览页

当前优点：一级导航识别度高，工作台、能力、环境、生命周期、知识和标准的业务域可快速扫描。

当前风险：总览页仍以多组指标块、入口块和覆盖率块表达系统，容易落入仪表盘模板；共享页头和内容首屏占用较多垂直空间。应用内浏览器全页截图在半透明顶栏处出现黑块渲染伪影，已拒绝作为页面缺陷证据；页面结构由真实运行态和局部可见区域交叉核对。

### 4.2 安全能力映射页

当前优点：全局导航、能力树、主画布三层关系清楚；语义色已能区分当前对象、技术、管理和标准角色。

当前风险：主画布占据大面积空间，但核心图谱在当前 L0 级状态下过小，视觉重心弱；页面同时使用外层工作区、内层大圆角面板、画布边框和工具条背板，层级边界过多；次级目录与主画布之间的宽度比例缺少按对象粒度变化的规则；关注点图谱在分支负载不均、长中文标签、共享节点和跨分支关联同时存在时，仍可能出现节点 / 标签碰撞、边穿节点和连线交叉，不能只靠增加斥力或缩小字号解决。

### 4.3 信息化环境映射页

当前优点：真实业务底图是页面主角，页面没有再增加第二套目录；视图切换和缩放操作集中在画布顶部。

当前风险：原始 Draw.io 图是用户确认的设计基准，其颜色、边框、字体、节点位置和连线样式均不得修改。页面需要解决的是默认缩放下对象名称过小、用户首先看到“整张图”而不是当前任务、画布工具条与全局页头控制层级不清楚、选中节点后的关联详情过重，以及搜索 / 定位反馈可能遮挡原图。应用内浏览器全页截图在半透明顶栏处出现黑块渲染伪影，已拒绝作为页面缺陷证据。

### 4.4 LC-AP 生命周期页

当前优点：阶段 Tab 是全站最清晰的序列导航之一，当前阶段和阶段编号能快速定位；主表保留了阶段目标、活动、模式、服务和策略等业务关系。

当前风险：首屏同时展示多个宽列，主审阅字段字号偏小，右侧列在 1440px 下被裁切；大量浅色单元格和局部 chip 同时出现，视觉焦点不稳定；`/` 空值虽然不是 chip，但仍作为高频可见内容，降低完成度感；当前阶段的关键行动没有从整张宽表中脱颖而出。

### 4.5 LC-DT 生命周期页

当前优点：数据处理场景、子场景、服务、模块 / 措施和策略矩阵采用纵向分区，比 LC-AP 更接近可扫描工作台；服务作用域色卡有业务辨识度。

当前风险：阶段顶部控件、场景大表、服务 chip 区、模块 / 措施区和策略矩阵仍使用多套局部边界；信息密度较高但层级节奏不统一；服务色彩较多，需要确保只表达作用域，不与状态色竞争。应用内浏览器全页截图在半透明顶栏处出现黑块渲染伪影，已拒绝作为页面缺陷证据。

### 4.6 知识库字典：安全能力清单

当前优点：三列表头、分层行和数量信息清楚，表格比关系画布更接近稳定的 Apple Shell 信息系统；左侧知识目录提供明确的同域导航。

当前风险：默认全部折叠时，三条 L0 行之后留下大面积空白；目录工具栏必须只承担全量展开与回到 L0，不能混入与目录层级无关的最近对象状态；三条分类行使用近似整行蓝底，状态与结构层级的颜色区分不足；页头数量 chip 过多，容易与筛选条件混淆。

### 4.7 安全标准 / 框架页

当前优点：框架标题、搜索、框架内部视图切换、分级表格和能力映射列构成了稳定的数据阅读路径；分组行和控制项行的层级清楚。

当前风险：`CSF Core / CSF Tiers` 使用较厚的双层分段背板，和全站较轻的 Tab 语言不一致；分组行、数据行、映射 chip、数量 badge 和交替底色同时使用多种边界，视觉噪声偏高；页头数量 chip 仍像状态筛选；左侧全局导航较长时当前标准入口不易在首屏保持可见。应用内浏览器全页截图在半透明顶栏处出现黑块渲染伪影，已拒绝作为页面缺陷证据。

### 4.8 指南文档页

当前优点：全局导航、指南目录、正文阅读三层职责明确；目录项可直接定位章节；正文表格和长文排版可读。

当前风险：成熟度指南仍保留大面积高饱和蓝紫渐变 hero，与项目“低噪声 Apple Shell、非营销页、禁止通用蓝紫 AI 风格”的基线冲突；hero 占据首屏大量高度，用户需要向下滚动后才能进入方法论内容；正文卡片边界、外层 iframe / 阅读面边界和指南目录面板形成三层容器。指南页应有文档封面感，但不能使用营销 hero 作为主要识别手段。

### 4.9 Issue 工作台

当前优点：范围、处理队列、选中详情构成明确的三栏 Review Queue；状态、页面、优先级和搜索集中在顶部；批量选择与导出入口可见。

当前风险：页头状态 chip、筛选条、左侧范围卡片、中间每条 Issue 卡片和右侧 inspector 同时存在，出现明显“卡片套工作台”感；中间队列表格已出现横向滚动，说明列宽分配和信息优先级未收敛；未选择时右栏保持大面积空白，应提供选择提示、快捷键或最近项，而不是纯空白；全局侧栏保留其他已展开业务域时，导航高度和认知负担进一步增加。应用内浏览器全页截图在半透明顶栏处出现黑块渲染伪影，已拒绝作为页面缺陷证据。

### 4.10 成熟度项目列表

当前优点：项目、模板、状态、当前结果、完成度、证据覆盖和最近更新字段完整；右侧当前项目摘要能帮助快速继续工作。

当前风险：页面被标题区、demo 提示、四段统计、筛选区、表格和右侧摘要连续横切，像多个组件拼装；`平均评分完成度` 等统计权重过高，抢占项目选择任务；右侧摘要长期占宽，导致项目表列宽紧张；当前列表页和评分页分别采用不同的摘要 / inspector 语言，模块内部不统一。

### 4.11 全局搜索

当前优点：查询、分类 facets、分页和结果定位契约完整；命中词高亮能帮助快速判断相关性。

当前风险：顶栏搜索和页面内搜索同时占据首屏，形成重复入口；大量分类 chip 与结果数量并列，筛选状态、统计和导航的视觉语义混在一起；每条结果都使用完整圆角卡片，重复高亮文字造成“卡片流”，不利于连续扫描。建议保留顶栏快捷搜索，把结果页收敛为单一搜索工具条、轻量 facets 行和分隔线列表。

### 4.12 共享根因

1. **壳层重复**：全局侧栏、页面目录、局部筛选、永久 inspector 经常同时存在；1440px 下主任务宽度被结构层吃掉。
2. **容器过多**：页面、模块、工具条、数据区和每条记录都各自使用边框、底色或圆角，造成“卡片套卡片”。
3. **生成式界面的语义色冲突**：作用域标签、结构层级、选择、状态和关系角色在应用生成的表格、chip、图谱与控制层中没有完全统一优先级。该根因不包含信息化环境原始 Draw.io 图；原图颜色和样式是不可变设计基准。
4. **密度失衡**：部分总览和指南偏松、表格和成熟度评分偏紧；现有成熟度 CSS 出现 `9px—22px` 多档字号和 `2px—999px` 多档圆角，说明模块语言没有完全继承全局 token。
5. **常驻详情过度**：没有选择时仍保留空 inspector，有选择时又把解释内容放到远离当前对象的位置。

## 5. 全局 Apple Shell 设计契约

### 5.1 视觉原则

- **Shell 有材质，内容无玻璃**：半透明 / blur 仅用于全局导航、顶栏和浮动控制层；表格、文档、画布和表单保持实色背景。
- **一屏一主任务**：页面首屏只保留一个主工作区；二级目录、详情 inspector、统计区三者最多常驻一个。
- **内容先于容器**：优先用间距、分隔线和排版组织层级；只有可交互选区、浮层和真正独立模块使用圆角容器。
- **颜色有唯一语义**：蓝色=当前选择 / 主要操作，鼠尾草绿=完成 / 通过，沙金=需要处理的警告，淡紫=当前审阅行 / 复核上下文，红色=阻断 / 错误；业务作用域色不得复用状态色含义。信息化环境 Draw.io 原图不纳入该规则。
- **工作台，不是营销页**：移除大面积蓝紫渐变 hero、虚构 KPI 装饰和视觉噱头；总览页回答“接下来做什么”，不堆“看起来很繁忙”的卡片。

### 5.3 层级与组件规则

- 全局侧栏桌面宽度建议 `220—240px`，支持折叠；当前业务域自动滚入可见区，只展开一个一级域。
- 顶栏高度建议 `52—56px`，保留全局搜索、当前页面上下文和少量全局动作。
- 页面标题区使用共享 `96px` 基线；统计只在能改变决策时出现，最多 3 项并降为次级信息。
- 主按钮使用单一实色；次按钮描边；危险操作只在确认上下文中使用红色。
- chip 只表达标签、筛选值或业务作用域，不用来承载普通数字、段落或所有状态。
- 表格以分隔线为主，分组行用轻底色；不对普通数据行使用整行饱和色。
- 空详情区不常驻。宽屏可在选中后打开 inspector；窄屏改为抽屉或行内展开。

## 7. 成熟度 V2.1 完整页面体系

成熟度模块不再按“评分页局部优化”处理。V2.1 的项目列表、新建项目、固定 / 自定义模板、四维评分、文件交换、复核、客户 / 内部结果和报告快照均按独立页面任务完整设计，直接实现规格见：

- `frontend/design-handoff/implementation-specs/maturity-assessment-v2-1-complete-frontend-design-2026-07-12.md`

全局层只保留以下稳定规则：

1. 成熟度所有路由继承全局 Apple Shell：共享顶栏、侧栏、唯一页面标题和 `main-only` 工作区；项目列表与项目页不得再创建第二套主页头。
2. 项目列表是操作队列，不是 KPI 首页；全宽表格取代常驻项目摘要，主动作进入共享页头。
3. 新建项目固定评估企业组织，不提供项目作用域或评估对象类型；入口在项目列表上方打开居中的三步 workflow overlay，不使用右侧抽屉或占满工作台的创建页。
4. 评分页保持项目内步骤导航，主区改为左侧安全能力评分目录与右侧评分工作台；目录统一定位 L0 / L1 / L2 / 关注点，右侧保留 L2 汇总、关注点定义、服务 Tab 和主评分表单，无常驻右侧 inspector。
5. 每个适用评估点使用居中的 1—5 按钮填写四维当前等级，并持续完整显示当前已选等级标准；主区不显示全部 L1—L5 对照；当前总体由后端计算并只读显示。
6. 四维按各自标准独立判定当前稳定实现的最高完整等级；对象专用 rubric 优先，通用矩阵只作明确标记的回退，rubric 缺失时不得由前端生成。
7. L2 / 关注点在 `DIRECT / CHILD_ROLLUP` 中只有一个有效来源；评分执行页不回写关注点评级；结果页显示后端聚合。“统一设置下级”仅在全部下级未评分时选择一个等级初始化全部下级四维，任一维度已有评分后锁定。
8. 每个 `SERVICE / FOCUS` 显示是否适用；无安全技术服务时直接评估关注点，不生成空服务或伪作用域。
9. 评分区使用三列弹性布局，评分依据最小 `380px`，当前 rubric 紧邻维度下沉一行并完整显示；目标等级和目标理由必填，每点提供可选证据说明。
10. 客户主结果最细到 L2；关注点、服务、四维原始分和证据进入内部下钻与附录。

## 7A. 安全能力关注点图谱碰撞治理

### 7A.1 设计目标

图谱必须同时满足“关系完整、标签可读、布局稳定、可解释”。不能通过删除业务关系、把所有标签缩到 9—10px 或无限缩放画布来制造无碰撞假象。

### 7A.2 碰撞分类

- 节点与节点重叠；
- 标签与标签重叠；
- 连线穿过无关节点或标签；
- 跨分支连线交叉；
- 高负载分支挤压低负载分支；
- 自动适配后整体过小，虽不重叠但不可读。

### 7A.3 布局策略

1. 以当前关注点为固定中心，技术 / 管理 / 标准为稳定扇区；扇区角宽由分支负载和标签实际宽度决定，不再平均分配。
2. 先做结构化种子布局，再做节点碰撞、标签碰撞、边穿节点和边交叉四类优化；中文标签的碰撞半径按真实文本包围盒测量，不只按字符数估算。
3. 同一作用域或同一关系角色使用局部簇；共享对象只保留一个业务节点，跨簇关系使用独立端口和弧形路由。
4. 高密度叶节点默认聚合为“服务 12 / 模块 18 / 控制项 36”等可展开簇；展开簇不删除关系，完整关系同步保留在下方矩阵。
5. 当布局无法在当前宽度同时满足可读阈值时，自动进入“聚合总览”，而不是继续缩小字号；用户可进入“仅看技术 / 管理 / 标准”或“只看当前分支”。
6. 用户拖拽 / 固定属于当前会话的视图状态，不写回业务关系；提供“恢复自动布局”。

### 7A.4 交互降噪

- 默认边线低对比；悬停 / 键盘聚焦节点时，只强调一跳关系，其余降至背景。
- 点击边或节点在行内 / 按需详情中显示关系说明，不常驻空 inspector。
- 搜索定位先切到相关视图和展开对应簇，再执行居中和短暂焦点环。
- 图谱、关系矩阵和详情使用同一个当前对象 ID，避免视觉选择与数据对象错位。

### 7A.5 自动验收阈值

- `nodeOverlaps = 0`；
- `labelOverlaps = 0`；
- `edgeNodeIntrusions = 0`；
- 结构树视图 `edgeCrossings = 0`；含真实跨分支业务关系时必须低于版本化阈值并可通过视图过滤降为 0；
- 1440px 默认适配后业务标签字号不低于 `12px`；
- 布局相同输入必须稳定可重放；
- L0、L1、L2、关注点四类对象分别保留黄金样例和高负载反例。

## 7B. 信息化环境 Draw.io 不可变设计边界

1. 原始 Draw.io 的颜色、字体、节点尺寸、位置、边框、连线、分区和视觉语义全部不可修改。
2. 禁止通过 CSS filter、统一填色、字体覆盖或节点重排把原图“适配”成 Apple Shell。
3. Apple Shell 只作用于原图外部的页面壳、工具条、搜索、缩放、状态和按需详情。
4. 默认打开使用“适应画布”，搜索 / 路由定位使用独立 overlay 焦点环，不写入或覆盖 SVG 原样式。
5. 节点详情按需打开；关闭后完整归还画布宽度。详情中的作用域、服务、模块 / 措施和系统继续使用应用生成界面的业务标签规则。
6. 提供适应、100%、放大、缩小、全屏、返回上次焦点；控件不遮挡原图标题、图例和关键节点。
7. 原图过密时通过定位、局部放大和 minimap 解决，不重新设计原图。

## 14. 统计类 Vibrancy 与成熟度双栏评分补充

### FE-R93：概念图脱离真实工程结构

- 风险：把局部视觉稿当作完整页面实现，会丢失评分目录、L2 汇总、关注点摘要、服务 Tab 或固定保存栏。
- 方案：完整页面结构只跟随当前真实工程和用户确认的图 1；图 2 仅提供统计区样式，图 3 不作为实现结构依据。
- 门禁：评分执行页必须同时存在 `maturity-v4-score-directory`、`maturity-v3-l2-summary`、`maturity-v4-focus-context`、共享服务 Tab、双栏评分区和底部保存动作。

### FE-R94：毛玻璃泛化导致信息密度和对比度下降

- 风险：把 blur 用于普通内容、表单或目录，会增加层级噪声，弱化字段边界，并在不支持 `backdrop-filter` 的运行面失去可读性。
- 方案：建立共享 `sapd-stat-vibrancy`，只应用于统计类 Vibrancy；普通表单、目录、表格、证据区、导航和 Draw.io 禁用。提供实体底色回退、强制颜色模式回退和单层阴影。
- 门禁：共享类必须由独立样式文件提供；成熟度项目进度、L2 汇总、当前评估点汇总、T/G/M 分析、覆盖统计和报告摘要复用该类，不允许页面各自复制 blur 参数。

### 成熟度评分执行补充验收

1. 双栏评分区以真实工程为底板：左侧四维评分 / Rubric / 评分依据，右侧当前汇总 / 目标 / 证据；不得删除原业务结构。
2. 五个定位点始终可见，首尾点位于端点圆心；range thumb、定位点和 Tip 使用同一内缩区间。
3. 切换等级时显示对象专用等级解释 Tip，L1 / L5 不越界，减少动态效果时禁用动画。
4. 统计类 Vibrancy 只改变呈现，不修改评分、聚合、目标、证据或完成率口径。
5. 本轮无评分规则变化；成熟度三份文档继续同步，Web 先验收，DMG App 后置到发布矩阵。

## 15. 成熟度统计口径与目录层级补充

### FE-R95：差距、目标达成与完成率混为一个指标

- 风险：把 `gapIndex` 当作进度条，或用固定 CSS 宽度模拟差距，会让同一数据同时表达“距目标多少”和“工作完成多少”，用户无法判断当前结论。
- 方案：进度条唯一绑定后端 `targetAchievementRate`；`距目标尚差 x.xx 级 / 已达到目标 / 待完成评分 / 未设置目标` 只作状态解释；评分完成度独立绑定 `completionRate` 和 `completedItemCount / applicableItemCount`。
- 门禁：前端不得重算评分或目标；统计区必须同时显示目标达成率和“完成 / 适用”，并明确两者口径不同。

### FE-R96：目录层级选择被首个关注点评分覆盖

- 风险：点击 L0、L1、L2 后自动进入第一个关注点，会把目录浏览误装成评分选择，破坏对象粒度，也可能让右侧标题、结果与左侧选中 ID 不一致。
- 方案：L0 / L1 / L2 分别读取 `categoryResults / subCategoryResults / capabilityResults` 的同粒度后端聚合；关注点才进入评分表单。恢复状态保存 `viewLevel / viewId`，禁止 `rows[0]` 回退驱动主展示。
- 门禁：自动审计覆盖 L0、L1、L2、关注点四类选择，断言左侧选中对象与右侧统计 / 评分对象一致。

### FE-R97：重复等级说明与滑杆端点错位浪费评分空间

- 风险：Tip 与静态定义重复，占用垂直空间；range 内缩两次会让 L1 thumb 偏右并露出蓝色半圆。
- 方案：删除可见静态定义，保留 Tip 和无障碍隐藏说明；range 覆盖完整胶囊，五个点仍按 `17px` 圆心内缩，thumb 在端点与圆心一致。
- 门禁：四维评分行只保留维度、滑杆和评分依据；L1 / L5 截图不得出现端点错位，减少动态效果时说明仍可访问。

### 联动结论

- 本轮使用既有 API 结果字段，不新增前端评分、聚合或目标推断。
- 统计类 Vibrancy 加强到共享 `28px` blur 与受控景深阴影，仅用于判断型统计表面；普通内容、目录、表单、Draw.io 仍禁用。
- 影响面为 Web / App 共享前端；正式数据、源文件、保护基线、用户库和打包产物均不修改。

## 16. 成熟度层级统计图表与评分反馈补充

### FE-R98：层级雷达把总体目标误装成逐维目标

- 风险：L0 / L1 / L2 只有一个后端 `targetIndex`；若前端把它画成四个“维度目标”，用户会误认为组织、流程、工具、数据分别设置过目标。
- 方案：雷达蓝线只读取当前层 `dimensionResults`；虚线固定命名“总体目标参考”，把同一 `targetIndex` 等距投射到四轴，并明确“仅作参照，不代表逐维目标”。缺失维度不按 `0` 补点。
- 门禁：切换 L0 / L1 / L2 后，画布 `viewLevel / viewId`、右侧标题和后端结果对象必须同粒度；前端不得计算新目标、权重或聚合。

### FE-R99：统计页面只有 KPI 带和平面清单，难以比较

- 风险：大号数字、四条迷你轨道和两列文字清单占据首屏，却不能快速回答强弱维度、均衡程度、下级等级分布或具体差距。
- 方案：统计表面改为左图右数；右侧同时显示精确四维值、目标达成率、完成 / 适用、评分完成度、强弱维度和极差；下级对象使用带当前值轨道的分隔行，目标与完成率仍可精确核对。
- 门禁：极差只做展示解释，不参与综合得分；下级无结果统一显示“未评分”，不得输出英文占位或把未评分按 `0` 计入等级分布。

### FE-R100：等级 Tip 跨行覆盖评分内容

- 风险：Tip 绝对定位在滑杆上方，并由 `:hover / :focus-within` 长期显示，会覆盖表头、相邻维度或评分依据；长 Rubric 在大视口更容易形成半透明重影。
- 方案：滑杆与 Tip 使用同一行内反馈槽；Tip 只在分值改变时进入、停留并淡出，普通悬停和持续焦点不触发长期显示。完整文本继续放在无障碍说明中，视觉 Tip 单行截断。
- 门禁：专项审计禁止恢复 `has-value:hover` 和 `focus-within` 可见规则；每个维度行必须持有自己的 Tip，任一状态下不得改变其他行高度或覆盖边界。

## 19. 成熟度连续评分、完成语义、复核与分层统计补充

### FE-R111：复核页复用完整执行表单造成布局破坏与双写入口

- 风险：把双栏评分执行、目标编辑、概览和底部动作嵌入表格行，会触发旧三列 inspector 规则，出现竖排文字、越界控件和大面积空白；同时形成第二套可编辑评分入口。
- 方案：复核队列展开项使用独立只读摘要，展示四维有效等级与对象 Rubric；修改返回评估执行，复核页只承担核对和确认。

- 方案：全能力雷达主统计表面和分层统计共同复用 `sapd-stat-vibrancy`；分层统计补完整边框、圆角与 padding，L1 列表取消 `max-height` 和内部纵向滚动。
- 门禁：统计表面必须保持共享 class；普通表格、评分矩阵、目标输入和目录不得被全局毛玻璃化。

## 20. 成熟度连续评分落点、双统计与文字几何补充

### FE-R113：`nearest` 只保证可见，不保证落到下一项首维度

- 风险：页面存在项目 sticky header 和内部滚动容器时，`scrollIntoView({ block: "nearest" })` 可能把下一项停在表单中部，用户仍需向上寻找“组织与角色”。

- 门禁：浏览器复验必须同时断言下一项 ID 已变化、首维度位于 sticky header 下方、活动元素属于 organization 评分组。

### FE-R114：合并统计掩盖“处理完成”与“适用范围”两个分母

- 风险：只显示 `completed / applicable` 时，一个已明确不适用的评估点仍会让用户误以为关注点未处理完成；只显示状态文字又无法回答当前适用比例。
- 方案：关注点摘要并列显示完成 `completed / applicable` 和适用性 `applicable / total`。不适用项不计入完成分子或分母，也不进入 applicable、评分或聚合分母。
- 门禁：六项中五项适用且已评分、一项不适用的黄金样例必须显示“完成 `5 / 5`”“适用性 `5 / 6`”。

### FE-R115：适用性控件脱离关注点标题导致对象所有权不清

- 风险：控件置于独立状态栏时，用户难以确认它控制整个关注点还是当前服务；小复选框和弱文字进一步降低辨认度。
- 方案：控件移动到关注点标题末尾，保持同一标题基线；复选框至少 `20px`，标签至少 `13px`，当前适用状态继续用文字表达。
- 门禁：控件必须位于标题容器内，服务 Tab 自己的适用性仍保留独立对象边界，不得互相替代。

### FE-R116：成熟度计数与 Rubric 行长缺少稳定几何

- 风险：`14 / 14` 在狭窄统计格内换行后与“评估完成”叠压；对象 Rubric 横跨整列时行长过长、扫描困难。
- 方案：L2 完成主值使用单行 tabular 数字并单独调节字号；Rubric 反馈桌面限宽 `760px`，窄容器恢复 `100%`。
- 门禁：完成主值不得换行或遮挡标题；Rubric 不截断、不悬浮、不跨行覆盖。

### 联动结论

- 本轮无评分规则变化；关注点 `resolved / total` 是执行处理状态，层级后端 `completedItemCount / applicableItemCount`、评分完成率和聚合规则保持不变。
- 影响面为 Web / App shared runtime，根因层为 shared frontend；不修改 dataClient、ViewModel、ETL、正式数据、保护基线、用户库、Draw.io 或 DMG，DMG App 回归后置到下一次发布矩阵。

## 22. 成熟度结果信息架构、共享滚动与检查语义补充

### FE-R122：装饰性复核状态会制造无意义确认成本

- 风险：`待复核 / 已确认` 没有独立需要人工判断的业务内容，却要求逐项确认，用户无法理解确认对象并增加重复操作。
- 方案：将步骤命名为“评分检查”，只区分阻塞、已完成和不适用；每个阻塞项直接“返回评分”，评分完整后只保留一个有真实锁定结果后果的“完成评估”。
- 门禁：主界面不得出现待复核、已确认或逐项确认按钮；所有阻塞行必须携带原 `scoreItemId` 返回首个缺失字段；项目级完成动作只在无阻塞时可用。

### FE-R123：适用性与评估进度共用分母会误读完成状态

- 风险：把 `completed / total` 或 `applicable / applicable` 标成评估进度，无法同时回答范围适用多少和适用项完成多少。
- 方案：固定显示适用性 `applicable / total` 与评估进度 `completed / applicable`；`total` 只等于后端同粒度 `applicable + notApplicable`。
- 门禁：14 个评估点、6 个不适用时，适用性必须为 `8 / 14`；完成 7 个时评估进度必须为 `7 / 8`，完成 8 个时为 `8 / 8`。

### FE-R124：结果摘要、结论和图表分散会产生重复首屏

- 风险：试算警告、总体结论、统计口径和两张雷达分散成多块，既占用首屏又让用户无法快速关联当前、目标、差距与覆盖范围。
- 方案：删除重复警告，把评估结果、当前 / 目标 / 差距、适用性、进度和达成率合并为一条统计带；四维雷达与全能力雷达合并到一个响应式 Vibrancy 区域。
- 门禁：结果统计带必须先于雷达，桌面双雷达横排、窄屏堆叠且全局横向溢出为 0；成熟度与证据分布必须位于结果评价下方。

### FE-R125：维度 Top 10 可能被误实现为前端新优先级模型

- 风险：后端只有总体 `gapItems[].priority`，若前端按四维分数自行创造高 / 中 / 低阈值，会生成不可追溯的新业务结论。
- 方案：四维 Top 10 只按后端 `capabilityResults[].dimensionResults[dimension]` 升序用于发现低位项；行末高 / 中 / 低继续复用后端总体优先级。L2 表同样只显示后端优先级。
- 门禁：前端不得出现维度优先级阈值、差距重算或目标推断；缺少后端差距候选的能力不进入 Top 10，L2 优先级显示 `—`。

### FE-R126：隔离评分滚动会把概览排除在用户预期滚动范围外

- 风险：只让四维评分列滚动会让整体页面出现双滚动认知，且“评估概览固定”被误实现为锁死宽度或与项目页面割裂。
- 方案：桌面回到项目级共享纵向滚动，评分维度不再单独滚动；评分表头与右侧概览在共享容器内 sticky，概览始终完整。窄屏恢复自然文档流。
- 门禁：返回阻塞评分后共享项目滚动值必须变化，右侧概览仍完整位于视口；评分列 `overflow-y` 为 `visible`，页面全局横向溢出为 0。

### 联动结论

- 本轮无评分规则变化；只修正 shared frontend 的结果信息架构、检查语义、统计分母、优先级展示边界和滚动所有权。
- 不修改 dataClient、ViewModel、后端评分 / 聚合、ETL、正式数据、保护基线、用户库、Draw.io 或 DMG。影响面为 Web / App shared runtime，DMG App 回归后置到下一次发布矩阵。

## 23. 成熟度正式统计门禁、纵向雷达与局部搜索补充

### FE-R127：派生差距与达成率占据结果首排会掩盖可行动口径

- 风险：把成熟度差距和目标达成率与当前、目标、适用性、进度并列，会重复表达同一关系却不能支持新的业务动作。
- 方案：结果首排删除两项派生值，固定呈现当前成熟度、目标成熟度、适用性、评估进度和后端同粒度分层评价。
- 门禁：首排不得出现“成熟度差距 / 目标达成率”；分层评价只读取 `categoryResults`，不得由前端重算。

### FE-R128：只禁用完成按钮不能阻止半成品结果外泄

- 风险：评分未完成时后端仍能形成试算数组，若结果页继续渲染，用户会把不完整聚合误当正式结论。
- 方案：后端输出 `statisticsReady / resultAvailability`，未完成、无效 N/A 或目标冲突时统一阻断客户结果和内部明细。
- 门禁：`statisticsReady !== true` 时页面不得输出成熟度值、雷达、热力表或优先级，只显示回到评分检查的入口。
- 历史兼容：字段上线前已经锁定的 `completed / reported / archived` 正式快照，仅在持久化后端摘要明确 `completionRate=100`、`notScoredCount=0` 且快照未失效时继续展示；不得把该兼容用于 scoring 项目，也不得在前端重算完成状态。

### FE-R129：目标低于当前评分会形成逻辑倒挂

- 风险：目标等级低于后端四维计算出的当前等级，既不构成改进目标，也会污染完成状态、报告和导入结果。
- 方案：后端以既有阈值生成 `minimumTargetLevel`，冲突项标记 `targetBelowCurrent / invalid_target`；导入返回 `target_below_current`，前端只解释并阻断跨评分点导航。
- 门禁：冲突项 `isComplete=false`、项目 `statisticsReady=false`；前端不得复制等级计算。

## 21. 成熟度复核闭环、结果首屏与评分锁定补充

- 风险：全能力雷达埋在局部摘要之后，用户先看到局部结论；若前端按差距大小自行分高 / 中 / 低，会制造未经后端确认的业务结论。
- 方案：全能力分组雷达前置为结果首个核心区，T / G / M 分界使用粗线；T / G / M 与 L1 两层统计只计数后端 `gapItems[].priority` 的高 / 中 / 低值。
- 门禁：雷达必须先于总体结论；普通轴与分组轴线宽可辨；前端不得新增优先级阈值、评分或业务关系推断。

### FE-R120：页面滚动与评分滚动混用会破坏对象上下文

- 风险：评分维度很多时，标题、关注点、服务 Tab 和右侧毛玻璃概览一起滚出视口，用户失去当前对象上下文且无法持续比较评分轮廓。
- 方案：桌面评分壳层固定可用高度，只有四维评分列纵向滚动；维度表头 sticky，右侧概览完整占满且内部不滚动。
- 门禁：滚动评分列前后，项目 / L2 / 关注点 / 服务对象和概览外框位置不变；页面无全局横向溢出。

### FE-R121：评估进度分母和 L2 指标顺序不清

- 风险：只显示 `completed / applicable` 无法回答适用范围占全部评估点多少，也容易把完成度、当前成熟度和目标成熟度混在一起。
- 方案：L2 汇总固定顺序为评估进度、评估维度均值、当前成熟度、目标成熟度；进度同时显示 `applicable / total` 与 `completed / applicable`，当前和目标使用不同强调色。
- 门禁：`total` 只由同粒度后端 `applicableItemCount + notApplicableItemCount` 得出；四维均值、当前和目标均读取同一 calculation run，不读取 DOM 或关注点投影重算。

### 联动结论

- 本轮无评分规则变化；只修正复核状态闭环、阻塞定位、结果信息优先级、后端差距候选展示、滚动所有权和进度语义。

## 25. 第二十三轮结果分组、评分上下文与完成门禁补充

- 方案：两区固定等宽等高；表格内收并使用 `40px / 11px` 低噪声表头、细边框、工程圆角和系统字体。
- 门禁：同视口两区宽度差为 `0`；表格头 computed height 为 `40px`、字体为 `11px`，页面与两张表横向溢出均为 `0`。

### FE-R173：模板 Tab 切换重建整页导致项目记录刷新

- 风险：模板视图变化与项目记录没有业务依赖，却触发整页重建，使展开状态、分页或项目记录发生闪烁和错位。
- 方案：模板 Tab 只替换模板管理区，项目进展 DOM、筛选、分页和展开状态保持不变。
- 门禁：切换自定义模板 Tab 前后，项目主记录文本与业务 ID 完全一致，模板区独立显示空状态或对应数据。

### FE-R174：对外模板泄露开发字段和客户信息

- 风险：ID、快照、哈希、对象枚举和客户名称会把开发交换包伪装成业务模板，业务人员无法安全维护。
- 方案：对外 XLSX 只能包含“模板基础信息”“评估模板”，只投影模板名称、类型、版本、说明、L0—L2、关注点、服务、评分粒度和业务评分字段。
- 门禁：工作簿工作表集合严格等于两张业务表；可见单元格中不存在 ID / hash / snapshot / customer 字段或项目客户值。

### FE-R175：高级别能力关系未通过合并单元格表达

- 风险：逐行重复或全局 forward-fill 会把 L0 / L1 / L2 / 关注点与服务关系变成不可读、不可追溯的扁平数据。
- 方案：按连续业务路径合并 L0、L1、L2、关注点序号和关注点名称；导入只展开工作簿明确的 merge range，不做全局补值。
- 门禁：标准业务模板存在层级合并范围，185 个评估点从模板导出到自定义导入后保持同一评估点粒度。

### FE-R176：模板结构导入与项目评分上传混用

- 风险：同一入口既接收结构又接收分数会允许标准模板裁剪冒充自定义模板，或把客户评分写入模板资产。
- 方案：模板导入只接收无评分的自定义“模板配置”文件；项目评分只在项目概览和评分页接收“项目评分”文件。
- 门禁：标准模板导入返回 `standard_template_import_forbidden`；评分列非空的模板导入返回 `template_contains_scores`；项目评分文件不得进入模板库。

### FE-R177：评分文件结构被修改仍可写入当前项目

- 风险：删除适用项、新增评估点或重排关系会导致分数写到错误对象，破坏标准模板与当前项目的对象粒度。
- 方案：评分上传按 L0 / L1 / L2 / 关注点 / 评分粒度 / 服务业务路径与当前模板全量匹配，缺项、增项、重复或结构变化整批拒绝。
- 门禁：结构变化返回 `invalid_structure`，标准模板不因评分文件中的“不适用”而改变结构，不适用只更新项目分数状态。

### FE-R178：评分文件校验问题没有进入完成门禁

- 风险：非法等级、目标倒挂或不适用项残留评分只显示短时提示，用户仍可能完成项目并生成不可信结果。
- 方案：上传问题持久化为项目 `scoreImportIssues`，在评分检查显示文件行号和业务消息并加入 `blockingCount`；正确重传或修改对应评估点后清除。
- 门禁：有文件问题时完成评估禁用；评分检查显示重新上传入口，目标倒挂使用后端计算等级并返回 `target_below_current`。

### 联动结论

- 本轮改变 XLSX 模板/评分交换契约和项目本地阻塞状态，不改变四维评分公式、等级阈值、Rubric、聚合权重、适用性分母、正式结果口径或后端差距优先级。
- 影响面为 Web / App shared runtime + maturity API exchange；来源 Excel、保护基线、正式 JSON / SQLite、真实用户库、ETL 与 DMG 不变。

## 37. 第三十五轮 XLSX 业务语义补充

### FE-R179：无评分数据被误解为删除评分字段

- 方案：评分标题和评分列是固定结构，模板导入仅要求对应数据单元格为空；页面说明、工作簿填写说明和错误提示使用同一口径。

### FE-R180：模板类型无法从标准模板切换为自定义模板

- 方案：模板基础信息的模板类型提供标准/自定义下拉，删除文件用途字段；切换自定义后强制填写新的模板名称和模板说明。

### FE-R181：不适用行残留分数产生伪阻塞

- 方案：项目评分导入以适用性优先；不适用行的四维评分和目标等级直接忽略并清空，不进入评分检查阻塞项。

### FE-R182：评分文件上传缺少可追溯反馈

- 方案：成功提示区分标准/自定义模板；成功和部分成功上传写入历史修改记录，包含文件名、成功数和问题数。

## 38. 第三十六轮改进路线图与报告同步补充

### FE-R184：差距排行没有转化为可维护、可汇报的行动计划

- 风险：改进优先 Top 10 只回答“优先改什么”，没有负责人、资源、依赖和执行状态，领导层报告无法形成可跟踪的改进闭环。
- 方案：评估结果新增“改进路线图”，固定使用当前后端 `gapItems` 前 10 项作为能力身份和优先级来源；页面只允许维护改进行动、负责人、资源投入、依赖事项和中文状态，不设置完成期限，并按能力 ID 保存到当前项目本地状态。生成报告时后端重新绑定当前正式差距项，将路线图同时固化到 Markdown 与自包含 HTML，并纳入快照哈希。
- 门禁：路线图最多 10 行且身份、排名、当前 / 目标、差距与优先级均来自当前正式结果；前端不得新增评分或优先级阈值；编辑后报告显示“内容待更新”；新报告的 Markdown、HTML 和返回对象都包含同一条路线图信息；页面无横向溢出，宽表仅允许模块内横向滚动。

- 本轮不修改四维评分、等级阈值、Rubric、聚合权重、适用性分母、目标下限、差距排序或正式结果粒度。
- 影响面为 Web / App shared runtime + maturity report snapshot contract；正式 JSON / SQLite、源 Excel、保护基线、真实用户库、ETL 与 DMG 不变。

## 39. 第三十七轮对象专用评分依据补充

### FE-R185：通用四维矩阵被误当作每个评估点的实际 Rubric

- 风险：不同能力、关注点和服务被展示为同一套 L1—L5 依据，评分理由失去对象语义，且与来源工作簿不一致。
- 方案：通用矩阵降为 `GENERIC_REFERENCE`；正式评分通过关注点绑定的 `rubric_set` 使用对象专用依据，完整提取见 `docs/08-maturity/assessment-rubric-source-appendix-2026-07-17.md`。
- 门禁：固定模板不得默认使用通用回退；API、页面、评分文件和报告引用同一个 `rubricSetId/sourceRef`。

### FE-R186：共享 Rubric 与空白等级没有独立业务状态

- 风险：合并单元格被展开后误认为每个服务独立编写；空白等级又可能被统一补成通用文字，无法区分业务不可评分与遗漏。
- 方案：按合并范围形成 32 个 rubric set，并为每个四维五级槽保存可用、业务不可用、遗漏、未结构化或批准回退状态；空白合并保留共享关系。
- 门禁：页面和 Excel 只允许可评分等级；业务不可用不阻止发布，遗漏 / 未结构化阻止正式模板发布和评估完成。

### FE-R187：XLSX 只有统一参考，无法表达对象专用依据和禁选等级

- 风险：导出的评分表允许用户选择当前对象没有依据的等级，回传后也无法判断是非法评分还是来源遗漏。
- 方案：增加长表 `Rubric_Reference` 和独立 `Generic_Level_Reference`，按维度写入允许等级验证；缺失文件只允许作为 `release_status=BLOCKED` 审阅版。
- 门禁：导入返回可区分的 `RUBRIC_LEVEL_UNAVAILABLE / RUBRIC_LEVEL_MISSING / RUBRIC_UNSTRUCTURED`，不得静默纠正或通用回退。

### FE-R188：来源缺口尚未完成业务裁定

- 风险：当前 185 个评估点中，63 个落在不完整源依据组，另有 10 个评估点所属的 7 个关注点在源表中不存在；直接实现会把候选关系固化为事实。
- 方案：以附录第 8 章作为实施前业务清单，先确认整级空白、8 个单维缺项、`M-SA.AM-01/02` KPI 边界、`T-AS.DG-02` 上下限和 7 个新增关注点绑定。
- 门禁：业务裁定完成前不改运行代码、正式 JSON / SQLite、源 Excel、用户库或发布模板；本轮只同步设计。

## 40. 第三十八轮当前字典映射门禁补充

### FE-R189：直接按源 Excel 服务行整理 Rubric 会覆盖当前字典

- 风险：源服务集合在 22 个关注点与当前工程字典不一致；若以源服务行为主表，会删除当前服务、引入历史编码或把评分依据绑定到错误评估点。
- 方案：固定 `capability-tree / capability-workbench / build_maturity_base_template` 为对象主表；rubric 只通过当前关注点编码、父 L2 和名称语义绑定，所有当前服务通过所属关注点继承。
- 门禁：91 个关注点、160 条服务关系、185 个评估点形成全量映射表；源服务只作差异证据，不能覆盖当前字典。

### FE-R190：问题分类早于对象身份确认

- 风险：8 个同编码关注点存在名称语义差异，7 个当前关注点没有源评分依据；此时输出缺级 / 遗漏分类会把身份问题误写为 rubric 内容问题。
- 方案：引入独立映射门禁。当前结果为 76 个关注点已对齐、8 个待身份复核、7 个无来源；评估点为 `147 / 28 / 10`，门禁 `BLOCKED`。
- 门禁：只有 91 / 160 / 185 全部唯一绑定后，才重新按当前字典投影并输出问题分类。未通过前不改运行代码、正式数据、源 Excel或 XLSX 模板。

## 41. 第三十九轮项目信息编辑与测试数据环境分层补充

### FE-R191：项目创建后基本信息不可维护

- 风险：项目名称、客户组织、负责人、计划时间等只在创建时填写，后续纠错只能重建项目，且报告与项目历史无法反映元数据变化。
- 方案：项目概览复用现有项目表单语法提供编辑浮层；保存同步客户上下文、追加 `PROJECT_INFO_UPDATED` 历史、重算结果并使旧报告失效，但不改变模板、评分、状态或锁定状态。
- 门禁：必填与日期校验、取消零写入、无变化零历史、刷新保留、已完成项目仍锁定、报告待更新均通过。

### FE-R192：开发测试项目数量被错误等同于交付包数量

- 风险：为了让交付包只带 2 条案例而直接删除开发种子，会破坏本地多状态回归；由前端隐藏又会让数据契约与页面计数不一致。
- 方案：后端 workspace 明确区分 `development=5` 与 `delivery=2`。本地 stable 开发服务使用 development；Mac App、DMG 与 ZIP bundle 的 `bundle` runtime label 使用 delivery。
- 门禁：同一能力字典下开发 profile 返回 `demo-project-001` 至 `005`，交付 profile 只返回 `001/002`；前端“全部”数量与 API 一致，正式数据和真实用户库不变。

## 42. 第四十轮逐维目标与下级目标设置补充

### FE-R193：单一目标等级掩盖四个维度的目标差异

- 风险：当前状态按四维评分，目标却只有一个等级和说明，无法表达组织、流程、工具、数据的不同建设目标，雷达只能使用误导性的等轴目标。
- 方案：在现有四个维度行中原位并排展示“当前状态 / 目标状态”，两侧复用同一 L1—L5 矩阵、对象 Rubric 和可选说明；后端新增 `targetElements / targetDimensionNotes / targetDimensionResults`，派生综合目标继续服务既有差距链路。
- 门禁：每个适用点评分区恰有 4 个维度行、每行 2 个 radiogroup 和 2 个说明输入；目标侧修改不影响当前侧；完成条件是当前四维与目标四维完整，说明继续可选。

### FE-R194：旧目标记录在新评分区丢失

- 风险：直接切换字段会让浏览器本地项目、受控案例和旧评分表中的目标等级及说明在新页面显示为空。
- 方案：仅当新字段不存在时，把旧 `targetLevel / targetReason` 同值展开到四维；已有新字段绝不覆盖。旧 14 列 XLSX 继续可导入，新导出使用当前/目标双层表头。
- 门禁：迁移幂等，不更换 localStorage key，不清空项目；旧目标与说明首次打开即在四个目标控件中可见；新版 XLSX 四维目标往返无损。

### FE-R195：统一下级设置只能处理当前评分

- 风险：用户必须逐个打开下级评估点设置目标，或清空当前评分时误删目标与证据。
- 方案：现有“下级评估设置”增加独立“下级目标状态设置”行，提供“清空下级所有目标 / 统一设置下级目标状态”；当前与目标各自判断是否已有数据、各自锁定和确认清空，只作用于当前关注点 SERVICE 下级。两行使用相同网格轨道对齐文字、滑块与按钮，目标控件使用既有低饱和金棕语义色。
- 门禁：清空当前后目标保留；清空目标后当前评分、适用性与证据保留；统一目标只更新四个目标维度，不改当前评分。

### FE-R196：逐维目标改造后丢失目标下限

- 风险：只校验综合指数时，一个目标维度可以低于同维度当前状态，并被其他维度的提升抵消，形成业务上的局部倒退。
- 方案：前端禁选低于同维度当前状态的目标等级，后端按 `targetDimensionConflicts` 做权威校验；任一逐维冲突阻塞切换、统计和完成。统一设置下级目标状态允许等于当前关注点所有适用下级四维当前状态的最高等级，但不得低于；最高为 L5 时允许统一设置 L5。反向统一当前状态允许等于已有目标最低等级，但不得高于，确保操作顺序不改变规则。
- 门禁：即使加权目标不低于加权当前，只要任一目标维度低于同维度当前状态就必须失败；新版 XLSX 按维度校验，旧版单一目标按四维当前最高等级校验。

### 联动结论

- 影响 `shared runtime + maturity calculation/report/XLSX contract`；算法版本升级为 `sapd-maturity-v2.2.0`，报告模型升级为 V3，评分交换升级为 V2.2 并兼容旧 V2.1 工作簿。
- 不修改来源 Excel、保护字典、对象 Rubric 内容、四维权重、真实用户数据库、ETL 或 DMG。

## 43. 第四十一轮自定义评估模板可视化编辑补充

### FE-R197：自定义模板创建后错误进入评分执行

- 风险：创建完成后路由重挂载会使用默认评分页签，用户尚未配置模板就看到评分表单，项目状态与下一步不一致。
- 方案：创建自定义模板时先持久记忆项目页签为 `template`，项目状态保持 `template_configuring`；项目列表和模板管理提供“继续配置 / 继续优化”回到同一页面。固定模板路径不变。
- 门禁：通过真实三步创建流程后，落地页面含脑图工作台且不含评分表单；刷新和再次打开仍能继续配置。

### FE-R198：流程式三栏仍不是脑图工作台

- 风险：把目录、流程列和属性栏固定并排，即使支持拖拽，本质仍是管理后台；无法像 XMind 一样在一个空间中理解完整分支并自由浏览。
- 方案：改为单一可平移、缩放的树枝脑图；完整模型不裁剪，但首次默认只展开到 L1，显示模板根、全部 L0 和全部 L1。所有存在下级的节点右侧常驻收起 / 展开按钮，L1、L2、关注点逐层披露下一级；目录和属性只作为可收起悬浮工具。
- 门禁：基础模板首次画布含 1 个模板根、3 个 L0、10 个 L1、0 个 L2、0 个关注点和 13 条关系线，14 个可见非叶节点均有按钮；展开一个 L1 后只出现其 L2，继续展开后按真实数据出现关注点和服务。空白处拖动画布、5%—130% 缩放、适配全图、树枝连线和目录节点定位均通过。

### FE-R199：完整结构不能挤压主体画布

- 风险：3 / 10 / 32 / 91 的完整目录或固定属性栏会持续占用画布空间，分支越多可读区域越小。
- 方案：画布保持稳定大区域，完整目录和属性面板覆盖显示、默认收起；首次只为模板根 → L0 → L1 分配空间，展开时按真实子树渐进分配 L2、关注点和服务空间，并补偿画布偏移使触发分支继续留在可视区。目录选择深层节点时自动展开其祖先路径并定位。
- 门禁：`1440×900` 与 `1280×720` 均无页面级横向溢出；脑图不发生响应式回流，目录和属性浮层宽度受控且可关闭。

### FE-R200：节点复制不能只复制可见卡片

- 风险：仅复制当前节点会丢失下级能力、关注点、服务关系或评分项；服务分支收起时尤其容易产生表面成功、内部断链的模板。
- 方案：模板根复制完整模板资产；结构节点复制完整子树，并为分类、能力、关注点、映射、服务和评分项建立新 ID 映射，重写父子引用，评分记录保持空白。
- 门禁：复制一个含 6 条安全技术服务的关注点后，关注点增加 1、评分项从 185 增至 191，副本右键展开可见 6 条服务；移除副本后恢复 185。

### FE-R201：新增节点必须先允许自由建模再吸附

- 风险：只能在固定表单里选择父级，会把脑图退化为表格编辑；不校验吸附关系又会形成非法层级。
- 方案：空白处右键创建自由节点，允许编辑名称和节点类型；只有合法父级显示吸附态，松开后由统一 owner 物化为模板对象并同步交叉引用。
- 门禁：自由节点可在 FOCUS / L2 等类型间切换；FOCUS 拖到 L2 后自由节点消失、关注点出现、评分项增加 1，删除验收节点后计数恢复。

### FE-R202：全部树级节点需要渐进披露

- 风险：只折叠服务仍会让 32 个 L2 和 91 个关注点把主干推离视口；把“＋”放在节点边缘还会与展开动作冲突。
- 方案：模板根、L0、L1、L2、关注点统一使用常驻的收起 / 展开按钮，默认展开到 L1；收起不修改业务数据，复制和拖动仍包含完整子树。节点边缘不再显示新增“＋”。
- 门禁：默认 L2 / 关注点 / 服务均为 0；L1 → L2 → 关注点 → 服务逐层展开数量准确，重新收起恢复上一级主干视图。

### FE-R203：新增下级不能脱离画布上下文

- 风险：右键后跳到固定属性表单会让用户失去当前分支和关系位置，脑图再次退化为管理后台表格。
- 方案：新增下级统一从右键菜单触发，在合法子级位置生成带临时虚线边的行内节点，`Enter` 保存、`Escape` 取消；节点边缘圆形按钮专用于收起 / 展开。
- 门禁：临时节点、关系说明和临时边同时出现；取消不改变评分项，保存关注点后评分项增加 1。

### FE-R204：同级新增与任意连线都必须受类型约束

- 风险：只提供下级会增加重复定位成本；允许任意 Node-Edge 连线又会形成 L2 直接挂服务等非法结构，并破坏评分粒度。
- 方案：L0 / L1 / L2 / 关注点 / 服务右键提供“新增同级”，由当前记录的真实父级建立关系；模板根提供 L0 和根级 L1 两个明确入口。快捷新增、同级新增和拖拽吸附统一使用模板根 → L0 / 根级 L1 → L2 → 关注点 → 服务的有类型约束。
- 门禁：右键菜单能区分新增下级和新增同级；新增同级的临时关系指向当前业务父级；非法边没有可创建或可吸附反馈。

### FE-R205：结构编辑需要可逆操作

- 风险：复制完整子树、移动父级或把关注点转换为服务评估粒度会同时修改多组引用，误操作后只靠手工删除无法可靠恢复。
- 方案：维护最多 15 步会话级结构快照，工具栏提供撤销 / 重做，并绑定 `⌘/Ctrl+Z`、`⇧⌘/Ctrl+Z`；快照覆盖模板、评分记录、校验态和项目模板状态。刷新后清空历史栈，避免跨会话使用过期对象。
- 门禁：新增关注点 185 → 186，撤销 → 185，重做 → 186，再撤销并刷新仍为 185；工具栏可用态随历史栈变化。

### FE-R206：自定义评估点不能继承无关对象的评分依据

- 风险：新增自定义评估点若复制模板内第一个完整 Rubric，可能把漏洞、日志、身份或其他对象的专用标准错误带入新节点；界面虽然可评分，业务语义已经失真。
- 方案：自定义模板根属性面板展示 L1—L5 通用描述；新建且无对象专用依据的评估点使用版本化四维通用 Rubric。基础模板带出的评估点按评估点 ID 绑定基础知识库，不在自定义模板中固化依据文本；基础依据更新后解析最新版本，固定模板缺失仍失败关闭。
- 门禁：代码不存在 `inheritedRubricEntries` 或等价的“任取首个完整评估点”逻辑；新建评估点固定生成四维 × 五级共 20 条 `CUSTOM_GENERIC_FALLBACK`；通用定义使用渐进披露，不挤占脑图画布。

### FE-R207：行内新增覆盖后续节点

- 风险：新增或复制后出现的行内编辑器只覆盖在当前坐标上，布局未为其预留高度，会遮挡下一个兄弟节点并造成误点。
- 方案：布局 owner 根据当前 `parentType / parentId / nodeType` 在对应分支结束处预留固定编辑高度，后续分支整体下移；取消或提交后恢复正常布局。
- 门禁：在 L0、L1、L2、关注点和服务各层触发新增，编辑器、确定按钮、临时关系线和下一节点均不重叠；取消零写入，保存后布局重新收敛。

### FE-R208：来源三态只靠小字无法识别

- 风险：“标准 / 标准修改 / 新增”只使用相近边框和过小标签，用户无法快速判断哪些内容仍继承标准、哪些已经偏离标准。
- 方案：标准使用中性实线和灰色侧标；标准修改使用金棕实线、浅底和实心侧标；新增使用蓝色虚线、浅底和蓝色侧标。属性面板同步展示完整来源名称和定义。
- 门禁：三种节点在未选中、未悬浮时仍可凭边框样式、底色和侧标区分；选择态不得抹除来源语义。

### FE-R209：属性面板混入结构操作

- 风险：同一面板同时出现节点属性、父级、增删、复制和新增下级，用户难以判断保存范围，也会形成画布与表单双重结构 owner。
- 方案：属性面板只维护当前节点自身属性；名称、编号、定义和服务作用域按节点类型显示。当前 `isCritical` 没有实际业务结果，因此不展示“设为关键能力”。父级、增删、移动和复制只由画布节点及右键菜单负责。
- 门禁：服务节点显示名称、编号、定义、作用域和只读角色；L0 / L1 / L2 / 关注点显示名称、编号和定义；属性面板不存在关键能力、新增下级、移动、复制、移除和服务角色下拉。

### FE-R210：服务角色允许手工选择会破坏评估粒度

- 风险：把 T 服务改为平台参考会丢失独立评估点；把 G / M 服务改为独立评估点会把管理平台错误纳入服务聚合。拖拽换父级后若不重算，模板结构和评分项会不一致。
- 方案：服务角色改为系统硬规则：T 下服务固定 `ASSESSMENT_POINT`，G / M 下服务固定 `PLATFORM_EVIDENCE_REFERENCE`；无服务时关注点作为 `FOCUS`。加载、创建、拖拽、导入和后端校验共用该规则，页面只读展示判定结果。
- 门禁：角色选择控件为 0；跨 T 与 G / M 拖动服务、关注点、L2 或 L1 后，映射角色、关注点 `itemType`、评分项和空白评分记录同步；非法导入和直接 API 改写均被拒绝。

### 联动结论

- 影响 `shared runtime` 的成熟度前端创建链路、模板管理入口、自定义模板编辑器及模板验证 / XLSX 导入契约。
- 新增自定义模板通用 Rubric 及其导入 / 导出引用，不覆盖基础模板复制来的对象专用 Rubric，也不改变固定模板的 Rubric 完整性门禁。
- 不改变评分公式、聚合权重、适用性分母、ETL、固定模板、正式 SQLite、真实用户数据库或 App / DMG 交付包。

### FE-R211：新增属性栏被空白高度撑满

- 风险：新增节点字段很少时属性栏仍填满画布，操作按钮与输入区被大面积空白割裂；加入定义字段后还可能把确认按钮推到视口外。
- 方案：悬浮属性栏改为内容驱动高度并设置画布内最大高度，超出部分由属性栏内部滚动；定义输入保持紧凑可调整高度，确认操作跟随内容并在滚动时可见。
- 门禁：关注点新增属性栏没有无效全高留白，名称、编号、可选定义、取消和确认新增在同一紧凑面板内可达。

### FE-R212：节点定义没有进入模板编辑合同

- 风险：标准节点只能改名称和位置，用户无法审阅或优化定义；新增节点也缺少表达业务范围和边界的字段。
- 方案：基础模板从知识对象投影 L0 / L1 / L2 / 关注点定义；所有结构节点属性栏提供定义编辑。标准来源定义的模板内修改进入“标准修改”，新增节点定义为可选，任何修改都不覆盖保护字典。
- 门禁：标准来源节点显示后端定义；修改后来源状态变化且模板校验快照变化；新增节点不填定义仍可保存。

### FE-R213：画布临时节点暴露面板方位

- 风险：“在右侧完成”把当前桌面布局写进业务节点，在窄屏、面板关闭或布局变化后产生错误指引。
- 方案：临时节点只显示父子业务路径和待确认状态；输入与确认位置由属性栏自身的标题、字段和按钮表达。
- 门禁：画布 DOM 不再包含“在右侧完成”，改变属性栏位置不影响节点文案。

### FE-R214：首页模板与项目模板形成两套入口

- 风险：首页只能导入、项目内才能新建，导致相同模板资产使用两套编辑心智；未经复核的项目草稿若直接进入模板管理，又会把未校验结构误当成项目来源资产。
- 方案：首页“新增模板”和项目“评估模板”复用同一图谱编辑器。项目模板只有校验保存后进入模板管理并带来源项目；模板管理新增草稿可直接续编，且不进入项目列表或评分流程。
- 门禁：首页新增模板进入模板工作台；项目草稿不出现在项目来源资产中，校验保存后出现“项目：名称”；模板管理新增工作区不增加可见评估项目数量。

### FE-R215：属性浮层存在右侧空白且缺少完成动作

- 风险：透明外层、双重滚动槽和旧响应式网格会把字段区压窄并留下空白；现有节点编辑没有
  显式结束动作，新增能力后用户无法判断属性是否已经确认。
- 方案：属性浮层统一负责边框、背景和单一内部滚动；内容宽度固定为浮层可用宽度。现有
  节点字段编辑后提供“确认并完成”，确认后画布重绘并关闭属性栏。
- 门禁：桌面面板没有独立空白列；名称、编号、定义和确认按钮同属一个表面，首次点击确认
  可完成，不因输入失焦重绘导致按钮点击失效。

### FE-R216：目录与脑图重复占用工作区

- 风险：完整目录和脑图重复展示同一层级，还提供两套拖动入口；画布越大，浮层越妨碍建模。
- 方案：移除模板目录浮层，顶部对象搜索承担快速定位；在模板页命中结果时不跳评分，自动
  展开祖先、居中选中并打开属性。
- 门禁：工具栏不出现“目录”；L0 / L1 / L2 / 关注点 / 服务搜索结果均能留在模板页定位；
  全部收起、全部展开和适配全图仍可用。

### FE-R217：模板来源原件与副本权限混淆

- 风险：项目来源模板在模板管理显示“继续优化”会被理解为可直接修改资产原件；原模板
  的发布字段继承到副本还会造成来源和状态混淆。
- 方案：项目来源原件只“进入项目优化”，并提供“创建副本并调整”。副本使用新模板 ID /
  快照、记录来源并清除原发布字段；导入模板的副本也直接进入模板工作区。
- 门禁：项目原件内容和 `validated` 状态不变；副本属于 `templateWorkspace`，回首页后
  以模板管理新增资产展示，不伪装成来源项目。

### FE-R218：新建项目模板类型与具体资产同层堆叠

- 风险：固定模板、自定义策略和每个具体模板作为同级大卡片，会把“类型选择”和“来源选择”
  混在一起；选择历史项目模板后还可能误改原件。
- 方案：第二步只显示固定 / 自定义两个一级选择。选择自定义后，在二级选择器中列出模板
  管理全部资产及状态 / 来源，并为新项目创建专属副本。新建项目按钮归入项目进展标题区；
  成熟度详情返回成熟度首页。
- 门禁：一级 radio 只有两个；任何来源创建后模板 ID 和快照均变化，来源模板不变；页头
  不重复显示新建按钮；详情返回路由为 `/workbench/maturity`。

### FE-R219：属性失焦重绘中断保存点击

- 风险：字段 `change` 事件先于按钮 `click` 执行；如果失焦时写入并重绘属性栏，原保存
  按钮会被替换，导致第一次点击无效。项目页和属性栏同时滚动还会让局部 / 总保存入口
  离开可视区。
- 方案：模板属性改为显式草稿提交。字段输入只更新未保存提示，“保存修改”一次读取当前
  面板、校验并写入；保存成功后关闭详情栏并在当前页反馈，失败时保持打开。模板页本身
  固定占满工作区且不滚动，标题动作区和属性保存区始终可见。
- 门禁：修改输入后只点击一次即保存并关闭详情栏；空名称、重复名称 / 编号或空服务作用域
  不重绘、不丢输入；项目页 `scrollHeight === clientHeight`，局部保存与“校验并保存”
  同时可达。

### FE-R220：项目与模板删除没有资产所有权约束

- 风险：只删除 `store.projects` 会让 API 示例项目刷新复活；项目来源模板由项目列表动态
  投影，项目删除会使模板资产一并消失。标准、活动项目模板和独立模板若共用同一删除动作，
  还会破坏知识基线或来源项目。
- 方案：项目采用两阶段应用内确认与本地 tombstone；删除项目前把自定义模板原子保留为
  `RETAINED_PROJECT` 资产。标准模板显式置顶且禁删，活动项目模板只提示不允许删除，
  原项目已删除的保留模板与独立 / 导入模板允许单独确认删除。
- 门禁：任一步取消均零写入；删除后刷新项目不复活、模板显示“原项目已删除”；活动项目
  模板删除零写入；持久化失败时项目和模板均保持原状。验证不得对真实用户项目执行最终
  删除。

## 44. 第四十二轮成熟度首页可见性与模板滚动补充

### FE-R221：测试项目存在但首页看起来丢失

- 风险：首页默认“进行中”会隐藏已完成项目；第一列只显示客户名会隐藏项目名，导致
  `123 项目` 等测试项目被误判为数据丢失。
- 方案：首页默认选择“全部”，第一列改为“项目 / 客户”，项目名为主文本、客户名为次文本。
  数据仍只来自 API 工作区和受控本地项目叠加，不重置、不回填、不覆盖用户状态。
- 门禁：API 返回项目数不变；首页“全部”选中且数量等于叠加后项目数；每行同时显示项目名
  与客户名。

### FE-R222：项目与模板操作列被按钮撑出容器

- 风险：双栏首页中，按整页宽度设计的长按钮在半宽表格里会越过操作列；标准模板的禁用
  按钮还占用无效空间。
- 方案：项目操作固定为紧凑的主动作 + 删除；模板按主动作 / 删除与副本 / 导出两排对齐。
  标准模板只显示导出，不显示“不可删除”按钮；两个表格都为操作列预留稳定比例。
- 门禁：`1440×900` 单栏和 `2048×1080` 双栏下所有操作组边界都包含于所在单元格，
  标准模板按钮集合仅为“导出”。

### FE-R223：模板页外层滚动带走总保存区

- 风险：工作台按 `100vh` 计算高度，同时项目页仍是 `overflow:auto`，形成外层项目滚动
  和画布内部交互两个 owner；滚动后“校验并保存”及画布工具栏被带出视区。
- 方案：进入评估模板 Tab 时给项目页明确模板工作区状态，使用 `height:100%` 与
  `auto / minmax(0, 1fr)` 网格；项目页和项目正文禁止滚动，脑图视口只处理平移缩放。
- 门禁：两个桌面尺寸下项目页不可滚动，工作台底部不越出可视区，“校验并保存”和属性
  底栏均可见。

## 45. 第四十三轮评估依据来源跟随原则

### FE-R224：自定义模板固化旧 Rubric 会与知识库更新脱节

- 风险：自定义模板若保存完整评分依据副本，基础知识库或通用评估依据更新后，旧模板仍展示
  过期标准；若统一回退通用依据，又会丢失基础评估点的对象专用语义。
- 方案：自定义模板采用 `LATEST_BY_ASSESSMENT_POINT_ORIGIN`。保留基础评估点身份的记录绑定
  `BASE_KNOWLEDGE_LATEST`，每次加载使用当前基础模板中同 ID 的 20 条 Rubric；模板新增、节点
  复制和 XLSX 自建评估点绑定 `CUSTOM_GENERIC_LATEST`，每次加载使用当前通用 Rubric 版本。
  本地模板只持久化来源策略、来源引用和版本回执，不把旧依据文本作为模板真值。
- 门禁：基础 Rubric 更新后打开既有自定义模板可见新对象专用依据；通用 Rubric 更新后打开
  既有自建评估点可见新通用依据；复制基础子树产生的新评估点不得继续继承对象专用 Rubric；
  任一来源缺少四维 × 五级完整依据时继续失败关闭。该解析规则不追溯改写已保存评分值或正式
  报告，评分与报告仍保留当次来源版本供审计。
