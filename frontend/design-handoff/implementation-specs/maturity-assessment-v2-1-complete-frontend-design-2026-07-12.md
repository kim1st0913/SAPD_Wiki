### 评分目录状态契约

- `已完成`：当前节点全部适用评估点均完成四维评分并设置目标等级；评估说明为可选，不进入完成条件。目录节点使用绿色圆点标签，文字通过 `aria-label` / `title` 保留。
- `进行中`：至少一个适用评估点已开始但尚未全部完成，或节点内同时存在适用与不适用项；目录节点使用黄色圆点标签，文字通过 `aria-label` / `title` 保留。
- `未开始`：当前节点的适用评估点尚无评分、目标、依据或证据输入；目录节点使用冷灰圆点标签，文字通过 `aria-label` / `title` 保留。
- `不适用`：节点下没有适用评估点；目录节点使用中性灰标签，文字通过 `aria-label` / `title` 保留；不计 0 分，不进入任何上层分数与完成率分母。

## 4. 项目列表完整设计

### 4.1 页面任务

项目列表不是统计首页，而是成熟度项目的操作队列。用户必须能在一屏内判断：哪个项目需要我做什么、做到哪一步、下一步从哪里继续。

### 4.2 页面结构

1. **紧凑页头**：标题“成熟度评估”、一句业务说明、主按钮“新建评估项目”。次级全局操作放入“更多”，包括模板管理、导出项目包和历史导入任务。
2. **状态视图**：`进行中 / 待复核 / 已完成 / 全部`。这是项目状态筛选，不做大型统计卡。
3. **单行工具条**：项目 / 客户搜索、模板类型、负责人、行业、更新时间、列设置、清空筛选。
4. **全宽项目表**：默认占据主区全部宽度，不常驻右侧项目摘要。
5. **按需项目预览**：点击项目行后在该行下方展开简要动作区；也可直接进入项目。无选择时不预留空白 inspector。

### 4.3 默认列与优先级

| 优先级 | 列 | 表达方式 |
|---|---|---|
| P0 | 项目 / 客户 | 项目名称为主行；客户组织、行业和规模为副行 |
| P0 | 状态 / 下一步 | 状态文字 + 下一步动作，不只显示颜色 |
| P0 | 模板 | 模板名称；`固定` / `自定义` 为轻量标签 |
| P0 | 当前 / 目标 | `L2 2.38 → L3 3.20`；未正式计算显示“未计算” |
| P0 | 评分完成度 | 细进度条 + `126 / 185`，完成定义包含四维、目标和理由 |
| P0 | 待复核 | 数量；0 时降为弱文本 |
| P0 | 最近更新 | 相对时间 + 完整时间 tooltip |
| P0 | 操作 | 单一动态主动作 + 更多菜单 |
| P1 | 目标达成率 | 默认可见于宽屏；窄屏进入展开区 |
| P1 | 项目负责人 | 宽屏可见；可作为筛选 |
| P2 | 证据覆盖率 | 默认不单独占列；放入展开区，明确“辅助信息” |

### 4.4 动态操作

| 状态 | 行内主动作 | 更多操作 |
|---|---|---|
| 草稿 | 继续设置 | 编辑项目信息、删除草稿 |
| 模板配置中 | 继续配置 | 导出 / 导入模板结构、查看校验 |
| 评分中 | 继续评分 | 导出 / 导入评分、复制历史草稿 |
| 待复核 | 进入复核 | 查看评分、导出评分表 |
| 已完成 | 查看结果 | 生成报告、导出项目包 |
| 已生成报告 | 查看报告 | 查看结果、导出项目包、归档 |
| 已归档 | 查看快照 | 恢复到列表视图，不允许改历史评分 |

### 4.5 行内展开内容

- 项目负责人、评估人员、计划时间；
- 模板 / 知识快照 / 算法版本；
- 当前、目标、差距、目标达成率；
- 评分完成度、不适用项数量、证据覆盖率（辅助信息）；
- 最近一次导入结果和报告快照；
- 与当前状态匹配的 1 个主动作和不超过 3 个次动作。

### 4.6 页面状态

- 首次空态：说明“从企业组织项目开始”，提供“新建评估项目”，不展示空表和 0 值指标。
- 搜索空态：保留筛选上下文，提供“清空筛选”。
- 加载态：表头保留，行使用骨架；不在页面中央只放 spinner。
- 错误态：说明项目列表或单项摘要哪个失败，支持局部重试。
- 已归档视图：默认只读，状态和报告快照清楚可见。

## 5. 新建项目完整设计

### 5.1 承载方式：居中浮层页

恢复成熟度模块最早使用的浮层交互基准：点击“新建评估项目”后，在项目列表上方弹出一个居中的大尺寸浮层页。它不是右侧抽屉，也不是替换整个工作台的独立创建页。

- 复用工程早期的 `.maturity-v1-modal-backdrop + .maturity-v1-modal` 结构语义：遮罩覆盖当前应用视口，浮层水平、垂直居中。
- 桌面端浮层宽度为 `min(780px, calc(100vw - 48px))`，最大高度为 `calc(100dvh - 48px)`；上下左右必须留出可见背景，不贴靠任何一侧。
- 项目列表、筛选和应用壳继续保留在浮层后方，使用低噪声半透明遮罩弱化；背景暂停交互，但不得卸载、重排或重置状态。
- 浮层具有完整四边边框、`8px` 圆角和克制阴影，视觉上是一张独立工作页，不是普通小型确认框。
- 浮层内部固定为四段：标题区、步骤条、当前步骤内容区、底部操作区。只有内容区滚动，标题、步骤和操作始终可见。
- 标题区显示“新建评估项目”、`第 1 / 3 步` 和关闭按钮；步骤条为 `客户与项目 → 选择模板 → 确认创建`。
- 底部操作区每一步只保留一个主动作。第一步为“下一步：选择模板”，第二步为“下一步：确认信息”，第三步为“创建并进入项目”；“返回”和“取消”为次动作。
- 浮层打开、前后步切换和关闭不改变项目列表的筛选、排序、分页与滚动位置。
- 同一时刻只允许存在一个创建浮层，不叠加第二层弹窗，也不再出现右侧抽屉或新的全页向导。

### 5.2 第一步：客户与项目

浮层宽度允许使用紧凑双列字段网格，一次只完成项目事实。长文本字段横跨两列，计划开始 / 结束时间成对展示；小屏自动退化为单列。

- 项目名称（必填）；
- 客户组织 / 客户信息（必填）；
- 客户所属行业（必填）；
- 企业规模（必填）；
- 客户特点（可选，长文本）；
- 客户偏好与约束（可选，长文本）；
- 项目负责人（必填）；
- 计划开始 / 结束时间、评估人员、备注（可选）。

点击“下一步”时只校验本步字段。错误显示在对应字段下方，焦点移动到第一个错误；已填写内容不丢失。

禁止出现：项目作用域、评估对象类型、部门 / 系统 / 业务域 / 专题对象、项目默认目标等级。

### 5.3 第二步：选择评估模板

模板选择使用纵向选项列表，不做大卡片墙，也不在本步展开完整模板编辑器。

- 固定知识库模板：清楚显示“只读结构”“按知识快照真实关系生成评估点”；可查看版本、快照、L0/L1/L2/关注点 / 评估点数量，不展示编辑按钮。
- 自定义模板：可以选择已发布模板，或“从固定模板复制为新自定义模板”；明确创建后将进入模板配置。
- 每个模板选项只展示影响决策的字段：类型、版本、来源、适用说明、评估点数量、最近发布。
- 未选择模板时禁用“下一步”；模板摘要加载失败时保留当前选择和第一步输入，支持在浮层内局部重试。

### 5.4 第三步：确认并创建

使用分组定义列表汇总已填写信息，不重复展示可编辑长表单。每组提供“修改”入口，直接返回对应步骤并保留全部内容。

- 汇总客户、项目、负责人和模板；
- 明确评估对象固定为企业组织；
- 明确固定模板作用域来自字典映射；
- 自定义模板提示需先完成校验和发布；
- 主按钮为“创建并进入项目”，不再同时出现“保存”“保存并计算”等多个蓝色动作。

创建成功后关闭浮层，并进入新项目对应的状态页面。创建失败时浮层保持打开，所有输入与当前步骤保持不变；字段错误就地提示，系统错误显示在底部操作区上方，并提供重试。

### 5.5 关闭、草稿与键盘规则

- 关闭按钮、背景遮罩、`Esc` 和第一步“取消”在任意步骤都直接关闭浮层，并把焦点返回“新建评估项目”；它们不创建项目，也不写入新草稿。
- 关闭时丢弃本次尚未保存的创建表单内容；若本次是继续编辑项目列表中已有草稿，则只放弃本次未保存变化，不删除已经存在的草稿记录。
- 不在关闭路径中展开内联确认区或第二层模态框。需要保存草稿时必须由用户触发独立、明确的“保存草稿”命令，不能把“取消”解释为保存。
- 浮层使用焦点约束，Tab 不进入被遮罩的项目列表；步骤条使用 `aria-current="step"`，错误提示与字段建立可访问关联。
- 动效只表达状态：遮罩与浮层以 `160—200ms` ease-out 淡入，浮层最多伴随 `6px` 的纵向归位；不得使用横向滑入、弹跳、缩放或装饰性序列。

### 5.6 响应式规则

- `≥1024px`：浮层宽度固定为 `780px`，四周至少保留 `24px`，项目列表作为完整背景上下文可辨识。
- `720—1023px`：浮层宽度为 `calc(100vw - 40px)`，最大高度为 `calc(100dvh - 40px)`，仍保持居中和四边留白。
- `<720px`：浮层宽度为 `calc(100vw - 24px)`，最大高度为 `calc(100dvh - 24px)`；双列字段退化为单列，但仍保持浮层边界，不切换为右侧 sheet 或独立创建路由。

### 5.7 验收口径

1. 点击“新建评估项目”后，项目列表 DOM、路由、筛选、分页和滚动位置均不被替换或重置。
2. `1440px` 桌面端浮层宽度为 `780px`，左右留白基本相等，四边均可见背景；不得贴右、贴左或占满工作台。
3. 每一步只展示当前步骤内容，必须经过“下一步”逐步校验，不允许把全部字段一次性铺开。
4. 前进、返回、局部失败和重试均保留已填写内容；关闭、遮罩、`Esc` 和“取消”结束未创建流程并丢弃未保存表单。
5. 创建成功后浮层关闭并进入新项目；失败时不退出、不清空。
6. 项目作用域、评估对象类型、项目默认目标等级和非业务来源字段均不得出现。
7. 标题、步骤、内容和底部动作无裁切；浮层内容滚动不带动项目列表；键盘焦点不会逃逸到背景。
8. 实现不得使用“遮罩左列 + 右侧面板”的布局、`border-left` 抽屉边界或 `translateX` 横向进入动效；页面不存在占满主工作区的 `.maturity-v2-create-page` 创建状态。

## 7. 模板页面完整设计

### 7.1 固定模板项目

使用只读树表：能力 L0（如有）→ L1 → L2 → 关注点 → 评估点预览。顶部展示只读说明、版本和快照；支持搜索、展开层级、导出评分表、复制为自定义模板。不得显示结构编辑、删除或权重修改控件。

评估点预览必须清楚区分：

- 技术关注点有真实映射：`SERVICE`，显示真实作用域和安全技术服务；
- 技术关注点无服务映射：`FOCUS`，不显示空作用域；
- 治理 / 管理关注点：`FOCUS`，平台参考服务只作为说明，不单独计数为评估点。

### 7.2 自定义模板配置

该页允许三栏，因为任务本身是结构编辑，不沿用评分页的无目录规则：

1. 左栏：可选 L0 / L1 / L2 树，支持重排和移动；
2. 中栏：关注点、作用域、服务和映射配置；
3. 右栏：来源、原归属、当前归属、变更类型、服务角色、评估点预览和校验。

关键交互：

- 删除 L0 前要求重新分配 L1；
- 移动 L2 / 关注点时明确提示“服务映射将随关注点移动”；
- `ASSESSMENT_POINT` 与 `PLATFORM_EVIDENCE_REFERENCE` 使用文字 + 图标区分；
- 发布前显示阻塞错误、需确认警告和信息提示三类校验；
- 已发布版本只读，修改必须“创建新版本”。

## 8. 四维评分页完整设计

### 8.1 结构裁定

评分页不再把全部评估项从上到下铺成一张超长层级矩阵，也不使用目录 + 主区 + inspector 三栏结构。采用“左侧评分目录 + 右侧评分工作台”的两栏工作区：

```text
左侧：L0 → L1 → L2 → FOCUS 评分目录
右侧：当前 L2 汇总 → 关注点摘要 → 服务 Tab → 当前评估点四维评分
```

- 目录复用安全能力映射的层级轨道、缩进和展开控件；无 L0 的自定义模板直接从 L1 开始。
- L0 / L1 / L2 / FOCUS 节点显示圆点状态标签与完成数 / 适用数；状态文字保留在可访问名称、目录图例和右侧工作台，不进入服务 Tab 的聚合分。
- 默认恢复上次工作的目录路径与当前评估点；无历史位置时按模板源顺序定位第一个有效路径。搜索和“跳转到能力”直接切换到命中 L2，并展开对应关注点。
- 页面一次只编辑当前服务 Tab 或 FOCUS，避免 32 个 L2 及全部服务在同一滚动面连续出现。
- 不常驻右侧 inspector。评分标准、目标、证据和复核信息均在当前评估点行下方展开。
- 选择有服务映射的关注点后，右侧服务 Tab 按模板顺序展示 `SERVICE`；无服务映射时直接展示该关注点自身的 `FOCUS` 表单。
- 桌面目录宽度约 `304px`，主评分区占据剩余宽度；`< 960px` 时目录转换为主区上方的限高树，不压缩评分依据和 rubric。

#### 8.1.1 第三轮授权变化与保留边界

第三轮用户明确授权以安全能力映射目录替代三行能力切换与当前 L2 关注点列表。下列区域继续保持顺序、层级和功能：

1. 全局侧栏、顶部全局搜索和右上角全局动作；
2. 面包屑、`成熟度评估` 页标题、页面说明、总体适用点 / 完成度 / 自动保存和“更多”；
3. 项目概览、评估模板、评分执行、评分复核、评估结果、报告快照项目内导航；
4. L0 / L1 / L2 / 关注点业务层级、源顺序和显式选中 ID；
5. 当前 L2 汇总面板中的能力名称、当前、目标、差距、完成度和四维平均字段及顺序；
6. 当前聚焦评估点摘要中的编码、名称、定义、下级数量、完成度和批量动作位置；评分执行页不显示下级汇总出的当前平均或目标反馈；
7. 左侧评分目录 + 右侧主评分表单的左右分栏、服务 Tab、当前指数 / 人工目标 / 目标理由 / 评估证据说明和“保存并转到下一项”。

本轮授权变化仅包括：评分目录及四态标签；服务 Tab；右上角保存并转到下一项；当前等级定义平滑聚焦；结果页能力雷达与统计重排；不适用分母统一。上一轮已确认的加长评分依据、`SERVICE / FOCUS` 同构、四维独立评分和 API Rubric 契约继续保留。未在此清单内的功能删除或对象粒度变化一律视为回归。

### 8.2 顶部工具条

- 当前项目 / 模板只读上下文；
- 评分进度：完成定义为四维自评 + 目标等级；评估说明和证据材料均为可选；
- “跳转到能力”命令，结果按 L0 / L1 / L2 / 关注点分组；
- 搜索评估点；
- 筛选：未评分、待复核、已确认、不适用、无证据（辅助）；
- 导出评分表、导入评分数据；
- 自动保存状态。

工具条下方保留方案 1 的三行能力切换几何结构和 `能力域（L0/L1/L2）` 行标签，只在原区域内收敛 Apple Shell 控件表面，不改变业务顺序、组宽和信息层级：

- **L0**：保留方案 1 的横向分组与标签，使用 `36px` 高低噪声 segmented control；冷灰轨道、白色选中实面、`1px` 细描边、轻阴影和 Apple blue 文字，不使用整块高饱和蓝底。
- **L1**：保留方案 1 与 L0 同行的内容宽度分组，不改成新的整行导航；选中项使用白色实面、细蓝描边和 `14px / 650` 文字，未选项保持中性表面。
- **L2**：保留方案 1 的独立第二行和原有能力标签宽度；选中项使用浅蓝灰实面 + 细蓝描边，未选项保持冷灰白。宽度不足时在本区域内自然换行，不出现原生横向滚动条。
- 三层均只显示能力名称，不显示分数、数量、状态或完成度；能力切换区与下方 L2 汇总继续使用方案 1 的间距和 `1px` 分隔关系。

### 8.3 L2 汇总面板

选择 L2 后必须先展示不可折叠的 L2 汇总面板，不再只把 L2 作为一条可收起标题行。汇总面板回答“这个能力现在处于什么水平、为什么、还差多少”：

- 第一行保持方案 1 字段顺序：`能力 L2 编码 + 名称`、当前成熟度 / 等级、目标 / 等级、差距、完成度、四维平均；评分来源仅作为“当前 L2”标题旁的紧凑二段控件，不新增一行、不移动既有指标；
- 第二行：组织与角色、制度与流程、平台与工具、数据与信息四个维度的后端聚合平均分，默认显示 1 位小数；
- 第三行：关注点汇总表，逐行显示关注点名称、适用评估点数、四维平均分、当前平均分、目标平均分和状态；
- 若 L2 应用了短板约束或上限规则，同时显示“原始平均分 → 规则后结果”和规则说明，不隐藏修正过程；
- 证据覆盖率只放在辅助信息区，不与当前分、目标或完成度并列成主指标。

汇总面板使用一块连续表面和分隔线，不拆成 KPI 卡墙。`DIRECT` 模式展示节点四维的整数选择及后端计算结果；`CHILD_ROLLUP` 模式展示下级实际统计分。所有指数、平均分、等级、差距和完成度均由 maturity API 返回，前端不得重新计算。

### 8.4 关注点分块与执行页反馈边界

当前 L2 内按关注点分块。一个关注点只显示一次，随后连续展示该关注点下全部真实安全技术服务评估点；不得把同一关注点重复成多个“关注点 + 单服务”条目。

关注点头部只回答“当前评估什么、定义是什么、下级有多少、完成多少”：显示编码、名称、关注点定义、下级评估点数量、完成度、保存状态和批量入口。若当前关注点无服务，则显示“关注点直接评估”。

评分执行页不回写关注点评级：安全技术服务逐项评分后，关注点头部不得显示由下级汇总出的当前平均、目标等级、四维平均或“汇总分已变化”等反馈，避免把聚合结果误读为可编辑的父级分数。关注点与 L2 的正式聚合继续由后端计算，并在“评估结果”页与 L2 只读结果区展示；前端评分执行页不自行计算，也不把聚合结果作为关注点输入。

#### 8.4.1 L2 / 关注点评分来源与统一设置

每个 L2 和关注点具有互斥字段 `score_source_mode`：

| 模式 | 页面输入 | 页面反馈 | 计算边界 |
|---|---|---|---|
| `DIRECT` 直接评分 | 当前节点四个维度分别使用 1—5 按钮；可填写对应评分依据、目标和理由 | 显示后端按节点四维计算的当前指数 / 等级 | 当前节点直接评分是唯一有效来源；下级记录可保留但不进入本次计算 |
| `CHILD_ROLLUP` 下级汇总 | 父级四维 1—5 不可提交；只提供“统一设置下级”和“查看计算明细” | 显示来自 N 个适用下级的实际四维加权平均分、当前 / 目标、范围与完成度 | 下级当前生效结果是唯一有效来源；父级直接评分保留为非生效历史，不进入本次计算 |

- 新建节点默认 `DIRECT`，模板可以锁定默认模式；已有下级评分或汇总结果的 demo / 历史项目迁移后保持 `CHILD_ROLLUP`，不得因默认值覆盖既有结果。
- 模式切换必须通过显式确认浮层完成，说明“哪些数据将退出当前计算、哪些数据仅作为历史保留、切换后的有效来源”。切换不删除任何评分记录，并记录切换人、时间和原因。
- 同一 calculation run 对同一节点只允许一个有效来源；API 若同时返回 `direct_effective=true` 与 `rollup_effective=true`，页面进入阻塞错误态，不自行选一个结果继续显示。
- “统一设置下级”是关注点单等级初始化，不是父级评分：仅当该关注点全部下级安全技术服务的四个维度均未评分时可用；用户只选择一个 `L1—L5` 等级，系统将该等级同时带入所有下级的组织、流程、工具、数据四个维度，并标记 `FOCUS_BATCH`。
- 下级已有任一维度评分后锁定统一初始化入口，不允许再批量覆盖。后续只能逐个安全技术服务调整，单项调整标记 `ITEM`。批量入口不设置适用性、人工目标或目标理由。
- `CHILD_ROLLUP` 的实际统计结果只进入后端结果聚合，不在评分执行页关注点头部反馈，也不与“统一设置下级”的 1—5 控件共用表面。

### 8.5 评估点折叠行

列顺序：

1. 安全技术服务 / 关注点评估项：关注点已在分组头显示；服务行只显示当前真实服务编码 / 名称，无服务映射时显示“关注点评估项”；
2. 类型 / 作用域：`SERVICE` 显示真实作用域，`FOCUS` 显示“关注点评估”；
3. 是否适用：原生方框勾选，默认勾选为“适用”；取消勾选即“不适用”；
4. 四维摘要：组织 / 流程 / 工具 / 数据显示已选整数分，未评分显示短横线；实际评分按钮在展开区；
5. 系统当前：只读指数与成熟度等级；
6. 人工目标：原生下拉菜单，选项为成熟度 L1—L5；
7. 状态：未评分、已评分、待复核、已确认、退回、不适用；
8. 服务名称 / 关注点评估项名称作为当前对象标识；多个下级服务使用“上一服务 / 下一服务”按钮连续切换，当前下级评估点不使用下拉菜单；表单控件不得触发行展开或重置选择。

折叠行可在状态下方显示一行证据说明预览；无内容时显示中性“未填写证据说明（可选）”，不能用警告色暗示阻塞。

当“是否适用”取消勾选时，该服务评估点或关注点评估点退出当前与目标聚合；四维评分、人工目标及相关评分依据立即置灰且不可编辑，只保留“是否适用”和“不适用原因”可操作。重新勾选“适用”后恢复原草稿值和编辑能力。

“是否适用”必须出现在每一个 `SERVICE` 与 `FOCUS` 评估点上，不能只放在关注点统一设置区，也不能因为上层节点使用 `CHILD_ROLLUP` 而隐藏。默认值为“适用”；批量设置只负责初始化，下级单项始终可覆盖。

### 8.6 行内展开评分区

1. **对象说明**：关注点说明、评估点类型、真实作用域 / 服务；治理 / 管理 `FOCUS` 在平台与工具维度旁展示参考服务。
2. **四维评分**：组织与角色、制度与流程、平台与工具、数据与信息各一行；每行使用 `1 / 2 / 3 / 4 / 5` 方形评分按钮，并显示当前维度的等级标准与评分依据输入。采用用户确认的方案 2 评分区：主行只保留“维度、评分按钮、加长评分依据”，当前选中等级标准下沉为紧邻该维度的整行说明。
3. **系统当前结果**：四维加权后的指数、等级和百分制只读展示；不提供人工总体分输入。
4. **目标等级**：使用原生下拉菜单选择成熟度 L1—L5，仍为适用项完成条件。
5. **评估说明（可选）**：目标理由与评估证据说明合并为一个多行文本框，可记录目标考虑、访谈、制度、配置、运行记录、抽样结果或判断依据；文件 / 链接和证据等级作为次级关联。
6. **补充信息**：评分说明、备注；选择“不适用”时只保留不适用原因并要求必填。
7. **动作**：取消、保存、保存并转到下一项。正式计算放在项目 / 复核阶段，不让单行按钮造成“保存即权威计算”的误解。

桌面评分区建议使用 `grid-template-columns: minmax(120px, 160px) minmax(260px, 320px) minmax(380px, 1fr)`。评分依据占满第三列，最小宽度 `380px`、默认最小高度 `40px`，输入增长到两行后可继续自适应增高；不得把评分依据压缩成截图方案 1 中的窄尾列。当前标准行从第二列跨到第三列，只显示 `L4 量化控制。具体维度标准文本`；不再保留持续占宽的独立 rubric 列或“对照全部 L1—L5”入口。

#### 8.6.1 无安全技术服务的 FOCUS 完整样例

以真实关注点 `G-SP.SM-01 具有明确的网络安全战略计划与目标` 为样例：

- 所属路径显示 `安全治理能力 G → G-SP 网络安全战略计划 → G-SP.SM 安全战略管理能力`；当前评估点类型固定为 `FOCUS`，标题副文案为“关注点评估点 · 无独立安全技术服务”；
- 左侧评分目录按真实层级显示 `G-SP.SM-01`、`G-SP.SM-02`、`G-SP.SM-03`，选中 `G-SP.SM-01`；右侧不生成空服务、不显示“暂无服务”占位 Tab、不伪造作用域，直接使用同一评分表单评估关注点自身；
- 该 `FOCUS` 默认 `DIRECT`，直接填写四维 1—5、各维度加长评分依据、人工目标与理由、评估证据说明、备注和是否适用；
- 若治理 / 管理对象存在平台参考服务，只在平台与工具维度的辅助说明中显示 `PLATFORM_EVIDENCE_REFERENCE`，不生成独立评分项，也不改变评分来源；
- 当该 `FOCUS` 被设为不适用时，退出其上层 `CHILD_ROLLUP` 的分子与分母，并要求填写不适用原因。

### 8.7 维度评分按钮与 L1—L5 标准

每个维度使用同一结构：`维度名称 → 1—5 评分按钮 → 当前标准提示 → 评分依据`。

- 单个评分按钮使用原生 `button / radio` 语义，桌面建议 `40 × 36px`；五个按钮在评分列水平居中，按钮文字显示 `1—5`，相邻说明显示完整成熟度等级名称。
- hover 或键盘 focus 只更新标准预览，不立即改变分数；click、Space 或 Enter 才提交选择。指针离开后恢复显示当前已选等级标准。
- 标准预览是按钮下方的常驻区域，不把关键标准只藏在 tooltip。显示格式为 `L4 量化控制。具体维度标准文本`，文本必须完整展示，不使用单行截断。
- 评分主区不显示“对照全部 L1—L5”。选中等级使用 Apple blue 实底、描边和约 `1.14` 倍平滑放大；定义区使用 `220ms` 左右的轻微显现动画，同时保留数字、`aria-pressed` 和焦点环，不能只靠颜色表达。
- 标准必须来自当前模板版本的维度 rubric，“对象专用标准优先、通用标准回退”的数据优先级不变。模板未提供维度专用标准时可按后端契约回退通用成熟度定义，但评分主界面只显示当前等级名称和定义，不显示“通用等级定义”来源标签；前端不得硬编码或自行生成标准。
- 四个维度可以选不同分数。评估点总体分仍由后端按四维权重计算，页面不提供人工总体分按钮。

#### 8.7.1 四维评分判定契约

四维评分必须分别判断，不允许因为某一维度达到某级而自动联动其他维度。评估人员应选择“当前已经稳定实现的最高完整等级”，不能把建设计划、采购意向或目标状态计入当前分；若某级核心要求只部分满足，应选择已完整满足的较低等级，并在评分依据中记录差距。

评分标准采用以下优先级：

1. 当前模板版本中与评估对象、维度和等级绑定的专用 rubric；
2. 对自定义模板中新建且没有对象专用依据的评估点，使用后端返回的版本化通用四维 rubric；
3. 任一适用评估点缺少上述可追溯标准时进入 `rubric_missing`，不得由前端硬编码、拼接或复制其他对象的评分文字。

L1—L5 规范业务定义引用业务设计第 62.2 节；V3 对象专用内容引用评分基线主表；运行时通用四维内容引用后端版本 `sapd-maturity-custom-generic-rubric-v3-2026-07-30`。本文件不再保存通用评分矩阵副本。

#### 8.7.2 维度边界与禁止联动

- **组织与角色**只判断客户在当前评估点上的职责、岗位、所有者、协同和履职机制，不以项目评估人员是否充足代替客户现状。
- **制度与流程**判断制度是否存在、正式发布、实际执行、覆盖、留痕、可重复和持续优化；只有文档但未执行，不能据此评为 L3 及以上。
- **平台与工具**判断当前评估点在对应作用域中的实际部署、覆盖、集成、自动化和自适应能力；字典存在服务映射、已采购产品或仅完成部署，不自动等于工具成熟。
- **数据与信息**判断业务数据的记录、质量、覆盖、分析、指标、决策支持和预测能力；它不是“上传了多少证据”，证据数量和证据覆盖率不得自动改变该维度分数。
- 治理 / 管理 `FOCUS` 的 `PLATFORM_EVIDENCE_REFERENCE` 只辅助判断平台与工具维度，不生成评分，也不自动抬高该维度。
- 人工目标仍是评估点总体目标，不是四维目标；V2.1 不提供四个目标维度输入。
- 后端按四维最终等级和模板权重计算当前指数；默认四维等权 `0.25`，前端不得自行平均、取最高、取最低或直接写总体分。

#### 8.7.3 Rubric 数据与页面状态

API / ViewModel 应为当前评估点返回 4 个维度 × 5 个等级共 20 条可追溯 rubric，至少包含 `dimension_code`、`level`、`level_name`、`criteria`、`source_type` 和 `source_version`。来源差异由数据契约和审计保留；评分主界面只显示当前已选等级的完整定义，不展示全部五级对照。任一适用评估点缺少某维度全部五级标准时，评分区进入 `rubric_missing` 阻塞态，不允许前端临时生成文字。

适用评估点完成四维自评并设置目标等级后可标记“已评分”并提交复核；评估说明与证据材料均为可选。不适用时整个评估点退出计算，不能只把单个维度设为不适用。每个维度继续提供评分依据输入，便于复核人员理解为什么选择该等级。

### 8.8 评估证据描述框

- 字段标签固定为“评估说明（可选）”，每个评估点一份；前端以既有 `targetReason` 作为编辑入口，并兼容读取历史 `evidenceSummary`，不新增第二个说明字段。
- 默认显示 3 行，输入后可自适应增长到 8 行；建议上限 1000 个中文字符，显示剩余字数但不打断输入。
- placeholder：`说明用于支持本次评分的访谈、制度、配置、日志、报告或运行事实。`
- 文本变化进入现有自动保存状态；保存失败保留内容并提供重试，不因重渲染丢失焦点。
- 可选关联“整体 / 组织 / 流程 / 工具 / 数据”维度；文件、链接、证据等级和共享证据属于次级功能。
- 空证据说明不阻止评分、复核、计算或报告，不使用黄色、红色和“待补”文案。

### 8.9 自评、复核与批量操作

- 评分阶段只显示自评；
- 复核阶段在每个维度显示“自评值 → 复核值”，复核未调整时不重复绘制两套控件；
- 发生调整必须填写复核原因；
- 最终值为后端 `review_level ?? self_level`，前端只读展示。
- 批量设置只写草稿，并在提交复核前逐项确认；
- “统一设置”是关注点下级服务的就地批量赋值入口；带入值必须记录 `FOCUS_BATCH` 来源，单项调整记录 `ITEM` 来源；
- 单个服务调整后，关注点及全部能力层汇总必须基于实际子项即时重算，不得继续展示旧的统一值；
- 批量设置“不适用”必须填写批次原因，可逐项覆盖；
- 批量目标允许生成待确认草稿；每个适用项最终必须有目标等级，评估说明可留空；
- 从历史项目复制后，所有值标记“复制草稿”，不能直接成为已确认评分。

### 8.10 保存、状态与位置稳定性

- 评分控件变化触发重渲染和后端试算时，必须保存并恢复当前 L0 / L1 / L2 Tab、关注点展开状态、页面滚动 owner 和当前控件焦点；不得跳回页首或改变路由；

- 下级成熟度分布按 L1—L5 统计已有后端结果的下级对象；未评分对象只计入总数和“未评分”显示，不进入等级分布，也不按 `0` 计算。

### 21.2 下级对象比较布局

- 下级 L1、L2 或关注点继续使用同一 calculation run 的结果；列表按两列分隔行展示层级、编码 / 名称、当前值轨道、目标和完成率。

- Tip 定义正文单行截断，完整 Rubric 继续由 `aria-describedby` 提供给键盘与读屏。窄屏无法容纳行内 Tip 时隐藏视觉 Tip，但不删除无障碍说明。

## 27. 第十九轮复核闭环、结果首屏与评分锁定裁定

### 27.1 复核状态必须对应真实业务操作

- `待复核` 固定表示：当前适用评估点已完成四维评分和目标等级，但尚未执行显式确认；它不是错误、也不等于未评分。`已确认` 固定表示：用户已在复核页执行单项确认或全量确认，系统已保存确认状态。

- 不适用项继续显示为“不适用”，不进入待复核、已确认、评分或聚合分母；无证据继续是信息状态，不阻塞确认。

### 27.2 全能力分组雷达优先与后端优先级

### 29.1 结果首排只保留可行动口径

- “评估结果与统计口径”首排固定为当前成熟度、目标成熟度、适用性 `applicable / total`、评估进度 `completed / applicable` 和分层评价。删除首排“成熟度差距”和“目标达成率”，不得再把派生比值包装成同权主结论。

- 后端 `summary.statisticsReady` 是结果可见性的唯一门禁。只要存在未完成评分、无效不适用原因或目标冲突，客户结果与内部明细都不得输出成熟度统计、雷达、热力表或优先级；页面只提供返回“评分检查 / 首个待调整项”的操作。

### 29.2 目标等级必须不低于后端当前等级

- 评分文件导入使用同一校验，冲突行返回 `target_below_current`；前端禁止自行计算当前等级或最低目标。
- 评分执行页发现冲突后必须在目标区显示原因，并阻止切换到其他评分点；后端重新校验通过后才解除。项目“完成评估”同样只在 `statisticsReady=true` 时可用。

### 29.3 评分检查只列待处理对象

- 四个统计固定为已完成、未完成、不适用、无证据（信息）。已完成只计数，不进入下方表格；表格只列未完成 / 目标冲突项和不适用原因核对项。
- 不适用核对不增加虚假的逐项确认操作；每一行只提供“返回评分”。无证据仍是辅助信息，不阻塞完成。

### 32.1 结果页的数据归属与阅读顺序

- 桌面评分页的 L2 汇总、关注点标题、适用性与服务评估点导航共同构成固定评分上下文。它们在共享项目滚动中保持 sticky，评分维度表头与右侧评估概览使用实测上下文高度计算偏移；L2 汇总必须使用内容自然高度并在中宽桌面压缩为“能力标题 + 三列统计”，不得沿用旧 `104px` 高度或用固定猜测值导致重叠、裁切。
- 用户在目录中点击关注点后，目录继续停留在点击前的 `scrollTop / scrollLeft`，并用显式 `focusId / scoreItemId` 更新评分对象。禁止因重新渲染目录而跳回顶部，也禁止使用首个子节点恢复选择。

- 完成门禁只由适用评估点未完成和目标等级低于后端当前等级两类问题拥有。`statisticsReady=true` 的必要条件为 `completed applicable == applicable` 且 `targetBelowCurrentCount == 0`。

- 项目级反馈必须绑定当前 route。点击项目标题左侧返回按钮后，反馈立即清除，首页不得继承上一项目的完成、计算或错误提示。
- 完成门禁继续只检查适用评估点完整度与后端目标下限冲突。不适用、无证据、不适用说明、评估说明和证据材料均为信息项；评分文件导入同样不得把空的不适用说明变成失败行。

### 33.2 首页与模板资产信息架构

- 成熟度首页固定分为“项目进展”和“模板管理”两个连续工作区域。项目进展拥有状态视图、筛选、项目队列与下一步；模板管理拥有全部模板、自定义模板、导入任务、导入、导出和继续调整，不再藏在页头“更多”菜单。

- 从模板中心使用模板新建项目时，项目获得专属模板副本；后续调整只作用于项目模板。历史导入任务保留来源类型、状态、成功数和失败数。

## 54. 第四十三轮节点属性与服务角色硬规则裁定（2026-07-31）

### 54.1 画布编辑与来源识别

- 行内新增和复制编辑器出现时，布局 owner 必须为当前分支预留完整编辑高度，并把后续兄弟分支整体下移；临时编辑器、确定按钮、关系线和原节点不得覆盖下一节点。
- 节点来源固定分为“标准”“标准修改”“新增”三种可见状态。标准使用中性实线与灰色侧标，标准修改使用金棕实线、浅底和实心侧标，新增使用蓝色虚线、浅底和蓝色侧标；三者在未选中状态下无需依赖说明文字即可区分。
- 来源含义不变：“标准修改”包括重命名、移动位置以及下级增删改；复制或新建的节点及其复制下级均为“新增”。

### 54.2 节点属性面板

- 属性面板不再承载新增下级、新增同级、移动、复制或移除等结构操作；这些操作只在画布节点和右键菜单提供。
- 各级节点属性固定包含名称、编号和定义。当前 `isCritical` 不参与校验、评分、优先级或报告，L2 不再展示“设为关键能力”。安全技术服务额外维护服务作用域并显示只读系统角色说明，其他节点不得出现服务作用域或服务角色。
- 服务角色不是模板用户可选字段，页面不得渲染角色下拉框；移动服务、关注点、L2 或其上级分类后，系统按新归属自动纠偏角色及评分项。

### 54.3 服务角色与评估粒度硬规则

- T 类安全技术能力下只要存在安全技术服务，每条服务映射固定为 `ASSESSMENT_POINT`，每条服务作为独立 `SERVICE` 评估点；若该关注点没有服务，则关注点自身作为 `FOCUS` 评估点。
- G / M 类治理和管理能力下的服务映射固定为 `PLATFORM_EVIDENCE_REFERENCE`，只作为关注点评估点“平台与工具”维度的参考，不生成独立服务评估点；关注点自身作为 `FOCUS` 评估点。
- 能力类型按当前层级自上而下识别 L0 → L1 → L2 的 T / G / M 标识；自定义路径无法识别时按 T 处理，避免服务关系无评估点。
- 同一规则必须覆盖基础模板生成、自定义模板加载迁移、行内新增、自由节点吸附、拖拽换父级、XLSX 导入和后端模板校验。导入文件中的评分粒度与能力类型冲突时拒绝导入，后端不得接受手工改写的服务角色。

### 54.4 当前知识映射与门禁

- 平台工具参考不是知识库中的独立对象类型，而是成熟度模板对 `security_technical_service → supports_focus → capability_focus` 关系赋予的评估语义。
- 当前基础模板有 160 条服务关系：154 条 T 类关系生成独立服务评估点，6 条 M 类关系作为平台工具参考；当前 G 类能力没有服务关系。不得据此把“M 开头”作为唯一判断，权威判断仍是服务所归属能力路径的 T / G / M 类型。
- 门禁：角色控件为 0；T 服务改为平台参考、G / M 服务改为独立评估点均被后端以 `service_role_capability_kind_conflict` 拒绝；移动分支后角色和 `SERVICE / FOCUS` 评估粒度立即一致；标准 / 标准修改 / 新增三态和行内编辑器无覆盖通过页面验收。

## 55. 第四十四轮节点定义与共享模板资产闭环（2026-07-31）

### 55.1 节点定义编辑

- L0、L1、L2、关注点和安全技术服务的属性栏必须包含“定义”。标准来源节点从成熟度基础模板投影知识库定义；在自定义模板内修改后标记为“标准修改”，只影响当前模板快照，不覆盖知识库对象或标准模板。
- 行内新增和空白画布新增均提供“节点定义（可选）”，未填写不得阻塞新增。定义与名称、编号一样进入模板校验快照身份；新增节点删除后不保留无效变更。
- 标准知识对象本身没有定义时，页面保持空白并允许在当前模板补充，不得由前端根据名称、编号或关系临时编造定义。

### 55.2 属性栏与画布文案

- 悬浮属性栏使用内容驱动高度，上限为画布可用高度和紧凑桌面高度中的较小值；内容超出后只在属性栏内部滚动。禁止用填满画布的空白区域撑高新增面板。
- 新增面板固定按名称、编号、定义、服务作用域（仅服务）和系统角色（仅服务）的顺序展示，并始终保留取消、确认新增操作。
- 临时节点卡只显示业务父子路径与“待确认”，不得出现“在右侧完成”等依赖当前面板方位的实现提示。

### 55.3 首页新增与项目模板保存

- 成熟度评估首页模板管理同时提供“新增模板”和“导入自定义模板”。“新增模板”默认深拷贝当前基础模板，进入与项目评估模板完全相同的图谱建模工作台，但不创建可见评估项目，也不进入评分流程。
- 模板管理新增的草稿保留在模板管理中，可继续优化；通过“校验并保存”后显示为已校验模板资产。
- 项目内自定义评估模板在草稿、配置和校验失败阶段不得进入首页模板资产列表。校验保存通过后立即进入模板管理，显示“项目：项目名称”来源；原件只能回到项目继续优化，在模板管理独立维护必须先创建副本。

### 55.4 数据边界与门禁

- 标准模板和知识库继续只读；共享模板资产当前仍保存在受控浏览器本地工作区，不写正式 SQLite、源 Excel 或真实用户数据库。
- 门禁：基础模板所有 L0 / L1 / L2 / 关注点定义均可在标准来源节点属性栏看到；新增节点定义为空仍可确认；属性栏无无效全高留白；首页新增模板进入同一脑图编辑器；项目模板保存前不存在于模板管理、保存后显示来源项目。

- API 工作区投影的项目删除后写入本地 tombstone，刷新不得重新出现。持久化失败时不得

### 57.3 模板删除权限与操作层级

- 项目删除后保留的模板、模板管理自建模板和导入模板可单独确认删除；删除模板不影响
  已经创建的项目专属副本。
- 模板操作区先按资产类型确定动作集合，再使用稳定网格；不得按文案长度临时决定按钮宽度、

- 项目与模板表格都必须为操作列预留稳定宽度，主按钮与删除按钮在同一行且不越出单元格。
  标准模板行只显示导出；项目来源、自建和导入模板按权限显示优化、创建副本、导出和删除。

### 57.5 边界

## 58. 第四十七轮评估依据来源跟随契约（2026-07-31）

### 58.1 来源判定

- 自定义模板使用 `LATEST_BY_ASSESSMENT_POINT_ORIGIN`，评估依据由评估点来源决定，不能由
  模板创建时间或模板内旧文本决定。
- 基础知识库带出的评估点以稳定评估点 ID 关联 `BASE_KNOWLEDGE_LATEST`；基础模板对应评估点
  的依据更新后，既有自定义模板下一次加载使用更新后的对象专用依据。
- 自定义模板新增、复制产生的新评估点，以及 XLSX 导入形成的自建评估点，关联
  `CUSTOM_GENERIC_LATEST`；通用评估依据更新后，既有自建评估点下一次加载使用更新后的
  四维 × 五级通用依据。

### 58.2 存储与解析

- 自定义模板持久化来源策略、来源引用和最近解析版本；可从权威来源恢复的 20 条 Rubric
  不作为模板内长期真值保存。加载、模板复制、项目模板修复和导入完成后统一重新解析。
- 复制节点及全部下级会创建新的评估点身份，因此使用最新通用依据，不能继续携带被复制
  对象的专用依据。
- 基础或通用来源缺少完整四维 × 五级依据时保持 `rubric_missing` 阻塞，不用另一来源静默补齐。

### 58.3 审计边界

- 本规则更新模板的评估依据解析，不自动改写已经填写的评分值、说明、证据或正式报告。
  评分交换和报告继续保留实际使用的 `sourceType / sourceVersion`，避免把后续知识更新伪装成
  历史评估时点的依据。
- 本轮不修改知识库基线、通用 Rubric 正文、评分公式、四维权重、聚合规则或真实用户数据。

## 59. 第四十八轮模板管理按钮数量与操作网格（2026-08-03）

### 59.1 按资产类型固定动作数量

- 标准模板固定 1 个动作：`导出`。
- 活动项目模板固定 4 个动作：`进入项目优化 / 创建副本 / 导出 / 删除`。删除仍作为权限说明
  入口，点击后提示先删除项目，不能改变项目或模板；状态显示“项目锁定”。
- 模板管理自建模板固定 3 个动作：`编辑 / 导出 / 删除`。
- 导入模板、模板副本和原项目已删除后保留的模板固定 3 个动作：`创建副本 / 导出 / 删除`。
- 同一资产类型不得因模板名称、状态、来源文案或表格宽度临时增减动作。

### 59.2 视觉层级与网格

- 每组最多一个 Apple blue 主动作，仅用于`进入项目优化`或`编辑`；创建副本和导出使用
  中性次按钮，删除使用低饱和红色描边，不与主操作竞争。
- 1 个动作使用单槽；3 个动作使用同排三等分；4 个动作使用等宽 `2 × 2` 网格。按钮高度、
  圆角、字重和内边距统一，操作组从单元格左侧开始，不根据文字长度拉伸单个按钮。
- 操作列继续保留稳定宽度；按钮不得跨单元格、压缩成竖排、遮挡分隔线或溢出表格。

### 59.3 验收与边界

- 运行态按 `data-template-action-count` 核对每行数量，所有按钮在 `1440 × 900` 与
  `2048 × 1080` 下位于操作单元格边界内；4 按钮行两列等宽，3 按钮行三列等宽。
- 本轮只修改 shared runtime 的模板管理操作呈现和动作集合合同，不改变模板所有权、删除
  确认流程、导出内容、数据投影、正式 SQLite、源 Excel 或真实用户数据。

## 60. 第四十九轮首页信息去重与模板命名合同（2026-08-04）

### 60.1 项目列表与状态数量

- 评估项目管理首列统一命名为“客户”，只投影 `project.organization`；项目名称不再作为同一
  单元格的第二层信息。搜索入口同步命名为“客户”，查询客户、负责人和现有业务筛选字段。
- 标题区删除与状态标签重复的“进行中 / 已完成”数字。状态标签继续显示进行中、已完成和全部
  数量，并作为列表筛选的唯一统计入口。
- 项目标题、说明、新建入口与客户 / 模板 / 负责人 / 行业筛选合并为一个头部，不再拆成上下两块；
  项目头部与右侧模板管理头部使用同一高度。项目状态标签保留在合并头部下方，不进入筛选区。

### 60.2 模板名称规范

- 标准模板唯一正式显示名为 `SAPD标准模板`。
- 项目专属模板使用 `{项目名称}项目模板`；项目名称本身以“项目”结尾时只追加“模板”，避免
  出现“项目项目模板”。项目模板根名称跟随项目名称，不在模板属性栏独立改名。
- 模板管理自建、复制和 XLSX 导入模板统一使用 `{自定义名称}模板`。复制名称把“模板 副本”
  归一为“副本模板”，序号放在“模板”之前。
- 旧存量名称不批量回写；列表、项目页头、模板工作台、新建向导和报告通过同一显示函数归一化。
  新建、复制、导入、属性保存和项目模板校验从本规则生效后直接持久化规范名称。

### 60.3 验收与边界

- 首页项目表不得出现“项目 / 客户”表头或同一行项目名 + 客户名双层结构；标题区不得再次输出
  进行中 / 已完成汇总块。
- 双栏首页中项目头部与模板头部顶边、底边等高；项目筛选不得形成额外独立区域，也不得挤压
  右侧模板模块或改变双栏模块首页定位。
- 标准、项目、自建三类模板分别显示为 `SAPD标准模板 / XXX项目模板 / XXXX模板`，来源标签、
  锁定状态、所有权、模板 ID、快照和项目数据保持不变。
- 本轮影响 shared runtime 的展示和后续命名生成，不覆盖知识库模板内容、正式 SQLite、源 Excel、
  已有评分、报告或真实用户数据。
