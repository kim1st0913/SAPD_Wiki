# SAPD Wiki Security Capability Mapping Workbench Visual Implementation Spec V1

版本：V1
日期：2026-05-17
适用范围：`安全能力映射` 页面内部工作台视觉与交互承载实现

本文档用于下一轮 Codex 前端实现。本文档只定义视觉实现规格，本轮不修改运行代码、不修改数据链路、不修改 ETL、数据库、数据模型、导出 JSON 或 workbench JSON。

## 1. 本轮拒绝验收原因

F3-P1R 未通过验收，主要原因如下：

- 当前页面仍像旧详情页或卡片堆叠，没有形成真正的安全能力映射关系工作台。
- 中央区域没有清晰的关系图，用户无法一眼看出当前关注点如何连接到作用域、服务、模块、措施、安全工作、职能、流程或标准。
- 技术视角、管理视角、标准 / 框架映射没有形成可切换的工作页签。
- 右侧没有独立的关联模块清单，模块 / 措施仍被压在关系路径里，无法作为可核对的洞察列表使用。
- 1920px 宽屏下虽然出现三列，但不是“宽屏关系工作台”，更像三组纵向信息面板并列。
- 1440px 下关系结构可读性不足，技术路径和管理路径没有形成清晰的画布层级。
- 当前实现过度依赖节点卡片和边框分组，缺少关系图所需的线、方向、层级、主次和聚焦态。

结论：下一轮不能继续在现有卡片墙基础上做小修 CSS，必须按本文档重构能力页内部工作台结构。

## 2. 安全能力映射工作台目标形态

目标形态是一个用于核对安全能力映射关系的专业分析工作台，而不是普通详情页。

核心结构：

- 左侧：能力目录区，用于选择能力分类、能力域、单一能力和关注点。
- 中央：关系工作区，用于展示当前关注点摘要、视角切换和关系图画布。
- 右侧：关联洞察区，用于显示关联模块清单、来源证据、统计摘要和待确认项。

核心交互：

- 选择左侧关注点后，中央关系图以当前关注点为起点。
- 中央必须有三个视角页签：
  - 技术视角
  - 管理视角
  - 标准 / 框架映射
- 页签切换只改变中央关系图的表达，不改变全局导航、不重新加载数据、不改变 `dataClient` 数据来源边界。
- 右侧洞察区跟随当前视角和当前关注点更新，但不承担业务关系推断。

核心视觉判断：

- 用户在 1920px 下应看到“能力目录 + 当前关注点关系图 + 右侧关联清单”的宽屏工作台。
- 用户在 1440px 下仍应看到完整关系图主结构，右侧可以收窄或折叠，但不能把中央关系图退化成普通详情列表。
- 关系图不是全局复杂网络图，只是当前关注点的局部关系图。

## 3. 页面总体布局规格

### 3.1 外层布局

保留现有 Application Shell，不重做顶部栏、全局侧边栏和 Manifest 导航。

`安全能力映射` 页面内部建议使用：

```text
CapabilityWorkbenchPage
├── CapabilityCatalogPane      左侧能力目录
├── CapabilityRelationStage    中央关系工作区
└── CapabilityInsightPanel     右侧关联洞察区
```

### 3.2 推荐宽度

1920px：

- 左侧能力目录：300px 至 340px。
- 中央关系工作区：剩余宽度的主要部分，建议不低于 900px。
- 右侧关联洞察区：300px 至 360px。
- 三栏完整展示，不出现大片空白。

1440px：

- 左侧能力目录：220px 至 260px，可显示省略文本。
- 中央关系工作区：不低于 720px。
- 右侧关联洞察区：可压缩为 240px 至 280px，或折叠为右侧抽屉入口。
- 中央关系图不可被右侧区域挤压成普通列表。

低于 1280px：

- 左侧能力目录可折叠。
- 右侧洞察区默认折叠。
- 中央保留“当前关注点摘要 + 视角切换 + 关系图画布”。

### 3.3 高度规则

- 顶部控制区不超过 96px 至 120px。
- 中央关系图画布应占据页面主体高度。
- 来源证据、明细矩阵、说明文本默认折叠，不挤压关系图。
- 关系图内部允许局部滚动，但页面不应出现多个互相竞争的大滚动区。

## 4. 左侧能力目录区规格

左侧能力目录区用于选择当前关注点，不是关系详情区。

必须包含：

- 页面内标题：`安全能力映射`。
- 收起 / 展开目录按钮。
- 搜索入口，可沿用当前能力页搜索。
- 能力层级树：
  - 能力分类
  - 能力域
  - 单一能力
  - 关注点

视觉规则：

- 目录节点应以树形缩进表达层级，不使用大卡片。
- 当前关注点选中态要清楚，建议使用浅底、1px 边界、字重和小型标签组合。
- 目录节点文本允许单行省略，悬停时可用 `title` 展示完整名称。
- 目录区不展示来源字段、不展示原始数据字段。
- 目录区不承载技术视角、管理视角或标准映射明细。

不允许：

- 把左侧目录做成一组大详情卡。
- 在目录中展示 `sheet`、`row`、`raw_value` 等非业务字段。
- 在目录中硬编码业务关系。

## 5. 中央关系工作区规格

中央关系工作区是本页面核心。

结构建议：

```text
CapabilityRelationStage
├── CurrentFocusHeader
├── RelationViewTabs
└── RelationGraphCanvas
```

中央关系工作区必须做到：

- 当前关注点始终是关系图的起点。
- 视角页签始终可见。
- 关系图有明确节点、连线、方向和分组。
- 技术、管理、标准 / 框架三种视角只能显示一个主画布，不要三种视角同时堆在主列。
- 右侧清单从中央画布中剥离出来，不再塞在技术节点尾部。

## 6. 当前关注点摘要区规格

当前关注点摘要区应是关系图上方的轻量对象头，不是详情页。

必须展示：

- 关注点名称。
- 关注点编码。
- 关注点说明，最多 2 至 3 行，超出省略。
- 能力路径：能力分类、能力域、单一能力。
- 轻量统计：
  - 技术映射数量
  - 管理映射数量
  - 标准 / 框架映射状态
  - 待确认项数量

视觉规则：

- 高度控制在 72px 至 96px。
- 不使用大号 KPI 卡。
- 不重复页面标题 `安全能力映射`。
- 不把长说明撑成详情页。
- 不展示来源证据原始字段。

## 7. 视角切换规格

### 7.1 总体规则

中央关系工作区必须提供三种视角切换：

- `技术视角`
- `管理视角`
- `标准 / 框架映射`

建议使用横向 segmented tabs：

```text
[ 技术视角 ] [ 管理视角 ] [ 标准 / 框架映射 ]
```

每个页签应包含轻量数量提示，例如：

- 技术视角：`6 服务`
- 管理视角：`9 职能`
- 标准 / 框架映射：`待投影` 或 `0 控制项`

实现约束：

- 下一轮可以在组件内部维护本地 UI 状态，例如 `activeRelationView`。
- 不修改 `dataClient`。
- 不修改 ViewModel 业务逻辑。
- 不新增依赖。
- 不从原始 JSON 重新推断关系。
- 视角切换不改变全局路由。

### 7.2 技术视角

技术视角展示当前关注点的技术落地路径：

```text
当前关注点 -> 作用域 -> 安全技术服务 -> 模块 / 措施
```

数据来源：

- 优先使用 `viewModel.localRelationMap.technical.scopeServicePairs`。
- 服务到模块 / 措施使用 `viewModel.localRelationMap.technical.serviceModuleMeasureLinks`。
- 如果 `localRelationMap` 来自 `capability-workbench.json` 或 fallback ViewModel，仍只消费 ViewModel 已整理字段。

### 7.3 管理视角

管理视角展示当前关注点的组织执行路径：

```text
当前关注点 -> 安全工作 -> 安全职能 -> L2/L3/L4 流程
```

数据来源：

- `viewModel.localRelationMap.management.securityWorks`
- `viewModel.localRelationMap.management.workFunctions`
- `viewModel.localRelationMap.management.workFunctionsByLayer`
- `viewModel.localRelationMap.management.processTree`

### 7.4 标准 / 框架映射

标准 / 框架映射展示当前关注点与标准、框架、条款、控制项或参考要求的关系：

```text
当前关注点 -> 标准 / 框架 -> 条款 / 控制项 / 参考要求
```

当前数据边界：

- `capability-workbench.json` 中已有 `standard_framework` 和 `standard_control` 对象组，但当前为空。
- `management-knowledge.json` 中存在 `gbt_42446_references`，且部分工作职能带有 `gbt_42446_refs`，但这不是当前关注点到标准控制项的直接投影。
- 下一轮前端实现不得伪造“当前关注点直接映射到标准条款”的事实。

V1 实现要求：

- 标准 / 框架页签必须存在。
- 如果当前 ViewModel 没有直接标准映射投影，画布展示受控空状态：
  - 标题：`暂无当前关注点的标准 / 框架直接映射`
  - 说明：`当前数据包尚未提供 当前关注点 -> 标准 / 框架 -> 控制项 的直接投影。`
  - 辅助入口：提示可在 `安全标准 / 框架` 或 `岗位参考页面` 中查看已有 GB/T 42446 参考数据。
- 不从工作职能间接推断当前关注点的标准映射。
- 不把 GB/T 42446 全量参考项塞进当前关注点关系图。

后续数据契约建议：

- 新增或补强后端投影字段，例如 `localRelationMap.standards.frameworks`、`localRelationMap.standards.controls`、`localRelationMap.standards.links`。
- 投影稳定后，标准 / 框架页签再展示真实关系图。

## 8. 技术视角关系图规格

### 8.1 关系图结构

技术视角关系图必须是横向关系图，不是表单块或卡片列表。

建议结构：

```text
[当前关注点]
      |
      +--> [作用域 I-AP 软件应用] -> [服务 应用架构管控]
      |                              -> 右侧关联模块清单
      |
      +--> [作用域 I-DI 数据与信息] -> [服务 数据分库分表]
      |
      +--> [作用域 I-HD 硬件] -> [服务 计算与存储分离]
```

中央画布列建议：

- 第 1 列：当前关注点起点节点。
- 第 2 列：作用域分组节点。
- 第 3 列：安全技术服务节点。
- 第 4 列：指向右侧关联洞察区的轻量连接提示，不在画布内展开大清单。

### 8.2 节点内容

关注点节点：

- 编码
- 名称
- 状态

作用域节点：

- 作用域编码
- 作用域名称

安全技术服务节点：

- 服务名称
- 服务编码
- 映射状态，例如 `已映射`、`待确认`、`不适用`

模块 / 措施：

- 不在中央画布中展开成长列表。
- 中央画布中只显示数量摘要，例如 `模块 3`、`措施 2`。
- 详细清单进入右侧关联洞察区。

### 8.3 多作用域展示

- 多个作用域纵向排列。
- 每个作用域内部保持横向路径。
- 连接线从当前关注点向多个作用域分叉，再指向各自服务。
- 服务较多时，服务节点可垂直堆叠在同一作用域泳道内。

## 9. 管理视角关系图规格

### 9.1 关系图结构

管理视角关系图必须表达组织执行链路：

```text
[当前关注点]
      |
      +--> [安全工作] -> [安全职能] -> [L2 流程组] -> [L3 流程] -> [L4 活动]
```

画布列建议：

- 第 1 列：当前关注点起点节点。
- 第 2 列：安全工作节点。
- 第 3 列：安全职能分层节点。
- 第 4 列：流程树摘要节点。

### 9.2 安全工作

- 作为当前关注点进入管理链路的第一层。
- 多个安全工作可以纵向排列。
- 安全工作节点应轻量，不要成为大卡片。

### 9.3 安全职能

安全职能必须体现层级：

- 决策层
- 管理层
- 执行层
- 监督层
- 待确认职能

视觉规则：

- 安全职能按层级分组。
- 每组显示数量和短列表。
- 待确认职能要有清晰但克制的状态表达。
- 不把所有职能堆成普通标签云。

### 9.4 L2 / L3 / L4 流程

流程展示规则：

- L2 流程组作为流程树上层。
- L3 流程作为主要流程节点。
- L4 活动作为折叠展开内容。
- 默认展开第一个 L2 / L3，其余保持可折叠。
- 无 L4 活动时显示轻量 `待补充`，不要占用大块空白。

## 10. 标准 / 框架映射规格

### 10.1 目标关系

目标关系为：

```text
当前关注点 -> 标准 / 框架 -> 条款 / 控制项 / 参考要求
```

标准 / 框架节点示例：

- GB/T 42446
- 等保三级
- NIST CSF 2.0
- ISO/IEC 27001:2022
- CIS CSC v8

控制项节点示例：

- 条款
- 控制项
- 参考要求
- 任务参考

### 10.2 当前 V1 数据限制

当前前端安全能力页没有稳定的“当前关注点到标准控制项”直接投影。

因此 V1 必须：

- 显示标准 / 框架页签。
- 显示标准映射画布空状态。
- 明确这是数据投影缺口，不是 UI 缺口。
- 不把维护页的标准参考表当成当前关注点映射关系。
- 不把标准 / 框架全量目录混入当前关注点画布。

### 10.3 后续真实映射准备

当后端提供直接映射投影后，标准 / 框架页签应变为：

```text
[当前关注点]
      |
      +--> [GB/T 42446] -> [参考任务 / 条款]
      +--> [NIST CSF 2.0] -> [控制项]
      +--> [ISO 27001] -> [控制项]
```

右侧洞察区同步显示：

- 标准 / 框架清单。
- 控制项清单。
- 待确认映射。
- 来源证据。

## 11. 右侧关联洞察区规格

右侧关联洞察区必须存在，且默认服务于当前视角。

结构建议：

```text
RightInsightPanel
├── 关联模块清单
├── 统计摘要
├── 待确认项
└── 来源证据
```

### 11.1 关联模块清单

技术视角下必须显示：

- 关联模块清单
- 关联措施清单
- 每项显示名称、类型和关联服务数量或状态

显示规则：

- 关联模块清单来自 `serviceModuleMeasureLinks.modules`。
- 关联措施清单来自 `serviceModuleMeasureLinks.measures`。
- 模块和措施去重展示。
- 不在主画布里铺开所有模块 / 措施，主画布只显示数量。
- 清单可按服务分组，也可按类型分组。

管理视角下右侧清单可切换为：

- 关联安全职能
- 关联流程
- 待确认职能

标准 / 框架视角下右侧清单可切换为：

- 标准 / 框架清单
- 控制项清单
- 数据投影缺口提示

### 11.2 来源证据

- 来源证据默认折叠。
- 展开后可显示来源名称和业务化来源说明。
- 不在默认主展示区显示 `sheet`、`row`、`column`、`raw_value`、`source_file`、`import_id`、`source_id`、`debug`、`raw`、`metadata`、`generated_at`。
- 如果现有来源证据组件会暴露非业务字段，下一轮不得把它放入默认可见区域。

### 11.3 统计摘要

统计摘要必须轻量，不做 KPI 卡墙。

技术视角统计：

- 作用域数量
- 服务数量
- 模块数量
- 措施数量

管理视角统计：

- 安全工作数量
- 安全职能数量
- L2 数量
- L3 数量
- L4 状态

标准 / 框架视角统计：

- 标准 / 框架数量
- 控制项数量
- 待投影状态
- 待确认项数量

### 11.4 待确认项

待确认项包括：

- 待确认服务映射
- 无模块
- 无措施
- 待确认职能
- 缺 L4 活动
- 标准映射未投影

视觉规则：

- 使用小型状态行，不使用大红色警告块。
- 待确认项可折叠。
- 优先辅助核对，不喧宾夺主。

## 12. 关系图视觉规则

### 12.1 节点

节点应是紧凑业务节点，不是大卡片。

节点必须包含：

- 类型标签
- 主名称
- 可选编码
- 可选状态

节点尺寸建议：

- 起点节点：宽 180px 至 220px，高 72px 至 96px。
- 普通节点：宽 150px 至 220px，高 56px 至 84px。
- 摘要节点：宽 120px 至 180px，高 44px 至 64px。

### 12.2 连线

连线必须表达方向。

规则：

- 使用 1px 线条和箭头。
- 当前关注点到第一层节点可使用分叉线。
- 同一层级内部不画过多交叉线。
- 线条颜色克制，建议蓝灰或中性灰。
- 不能仅靠节点排列暗示关系。

### 12.3 分组

分组用于表达作用域、职能层级、流程层级。

规则：

- 分组边界轻，使用浅底和 1px 边界。
- 分组标题小而清晰。
- 不使用厚边框、不使用大面积彩色填充。
- 分组不能套分组再套卡片，避免嵌套卡片墙。

### 12.4 空状态

空状态必须轻量。

示例：

- `暂无模块`
- `暂无措施`
- `暂无关联职能`
- `暂无当前关注点的标准 / 框架直接映射`
- `当前数据包尚未提供该关系投影`

空状态不应占满大块画布。

### 12.5 选中态

选中态用于节点聚焦。

规则：

- 节点 hover 可高亮连接线。
- 点击节点可更新右侧洞察区焦点。
- 如果下一轮不实现节点点击状态，也应至少实现 hover / focus 可读状态。
- 选中态不能改变业务关系，只改变视觉聚焦。

### 12.6 折叠态

折叠态适用于：

- 右侧证据。
- 流程 L4 活动。
- 过长模块 / 措施清单。
- 待确认项。

折叠态不适用于：

- 三个视角页签本身。
- 当前关注点起点。
- 当前视角的主关系路径。
