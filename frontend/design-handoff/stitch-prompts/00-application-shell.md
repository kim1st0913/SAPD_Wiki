# SAPD Wiki 全局导航 / 应用壳 Stitch Prompt

## 产品背景

SAPD Wiki 是一个企业级安全知识门户和本地化安全能力映射系统，用于组织、检索和分析安全能力、信息化环境对象、安全技术模块、安全管理工作、标准框架和方法论文档。

系统面向安全架构设计、安全咨询、安全治理、安全能力规划和安全知识管理场景。

## 本轮设计目标

请 Stitch 只设计：

```text
SAPD Wiki 全局导航 / 应用壳
```

不要设计完整业务页面，不要设计具体能力映射详情页。

本轮重点是：

- 顶部栏
- 左侧主导航
- 二级菜单展开方式
- 全局搜索
- 主内容区容器
- 当前页面标题区
- 面包屑
- 页面标签 / 状态标识
- 数据密集型工作台的承载框架

成熟度相关入口边界：

- `安全指南 > 成熟度模型使用方法` 只承载说明类内容，例如模型介绍、等级解释、评估流程和模板填写说明。
- `工作台 > SAPD 成熟度评估` 承载评估任务、填报、证据、匹配审查、评分结果、差距建议和报告导出。
- 成熟度评估中的能力选择与能力引用必须来自 `知识库字典 > 安全能力清单` 的权威数据，不在评估模块内另建一套能力清单。

## 视觉风格要求

- 企业级
- 克制
- 清晰
- 数据密集
- 知识门户风格
- 适合安全架构和安全治理场景
- 类似专业管理后台、知识库、数据目录、架构治理平台
- 优先考虑信息密度和可读性，而不是视觉炫技

## 布局要求

- 顶部栏承载系统名称、全局搜索、全局操作入口
- 左侧为一级导航
- 一级导航支持二级菜单展开
- 主内容区应为后续工作台页面预留足够空间
- 页面标题区应能展示当前页面名称、说明、标签和操作按钮
- 面包屑用于表达当前位置
- 主体区域应能承载表格、详情面板、映射工作台、抽屉等复杂组件
- 适配 1440px 宽屏工作场景
- 避免过度占用横向空间

## 禁止项

- 不要设计营销官网首页
- 不要设计大面积 Hero 区
- 不要使用过度科技炫技风格
- 不要把首页设计成复杂网络关系图
- 不要使用大面积发光元素
- 不要牺牲信息密度
- 不要把导航设计得过宽
- 不要让二级菜单挤压主内容区
- 不要为尚未实现的功能设计复杂交互闭环

## 输出要求

- 一张全局导航 / 应用壳高保真设计
- 包含展开二级菜单的状态
- 包含一个主内容区占位示例
- 包含数据密集型页面承载效果
- 适合后续扩展为安全能力映射、信息化环境映射、安全知识目录、标准框架目录等页面
